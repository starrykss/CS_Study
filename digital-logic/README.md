## 논리 게이트와 불 대수 · Logic gates and Boolean algebra

모든 디지털 회로는 0과 1을 다루는 작은 게이트로 만들어져요. 파란 선은 1, 회색 선은 0이에요.  
*Every digital circuit is built from tiny gates on 0s and 1s. Blue wires carry 1, grey wires 0.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **AND · OR · NOT**<br><sub>AND · OR · NOT</sub> | AND는 입력이 모두 1일 때, OR는 하나라도 1일 때 1을 내고, NOT은 값을 뒤집어요.<br><sub>AND outputs 1 only if all inputs are 1, OR if any is, and NOT flips the value.</sub> | 코드의 &&, \|\|, ! 과 같아요. 조건문을 단순하게 만들 때 이 규칙을 그대로 써요.<br><sub>They are the same as &&, \|\| and ! in code, and the same rules simplify conditions.</sub> |
| **XOR · NAND · NOR**<br><sub>XOR · NAND · NOR</sub> | XOR는 두 입력이 다를 때 1, NAND·NOR는 AND·OR의 결과를 뒤집은 거예요. 진리표로 모든 경우를 정리해요.<br><sub>XOR is 1 when inputs differ; NAND and NOR invert AND and OR. A truth table lists every case.</sub> | XOR는 덧셈의 합, 패리티 검사, 간단한 암호화, 두 값 교환 트릭에 쓰여요.<br><sub>XOR is the sum bit of addition and appears in parity checks, simple ciphers and swap tricks.</sub> |
| **NAND의 완전성**<br><sub>NAND universality</sub> | NAND 게이트 하나만 있으면 NOT, AND, OR, 결국 모든 회로를 만들 수 있어요.<br><sub>With NAND alone you can build NOT, AND, OR and therefore any circuit.</sub> | 실제 칩은 만들기 쉬운 NAND·NOR 셀을 많이 써요. "NAND to Tetris" 강의가 바로 이걸로 컴퓨터를 만들어요.<br><sub>Real chips lean on easy-to-make NAND and NOR cells; the “NAND to Tetris” course builds a whole computer this way.</sub> |
| **드모르간 법칙**<br><sub>De Morgan’s laws</sub> | NOT(A AND B) = NOT A OR NOT B, NOT(A OR B) = NOT A AND NOT B. 부정이 안으로 들어가면 AND와 OR가 바뀌어요.<br><sub>NOT(A AND B) = NOT A OR NOT B, and NOT(A OR B) = NOT A AND NOT B: pushing a negation inside swaps AND and OR.</sub> | 복잡하게 중첩된 부정 조건문을 읽기 쉽게 바꾸거나, SQL WHERE 조건을 정리할 때 바로 써요.<br><sub>Use it to untangle nested negated conditions in code or SQL WHERE clauses.</sub> |
| **카르노 맵**<br><sub>Karnaugh map</sub> | 진리표를 격자로 펼쳐 인접한 1끼리 크게 묶어서 논리식을 가장 간단하게 줄이는 방법이에요.<br><sub>Lay the truth table out as a grid and group adjacent 1s as large as possible to get the simplest expression.</sub> | 게이트 수가 줄면 칩이 작고 빨라져요. 요즘은 합성 도구가 자동으로 하지만 조건 단순화 감각을 기르는 데 좋아요.<br><sub>Fewer gates mean smaller, faster chips. Tools automate it now, but it trains your feel for simplifying conditions.</sub> |
| **트랜지스터와 CMOS 게이트**<br><sub>Transistors and CMOS gates</sub> | 게이트는 트랜지스터 스위치로 만들어요. CMOS는 1 쪽으로 끌어올리는 PMOS와 0 쪽으로 끌어내리는 NMOS를 짝지어요.<br><sub>Gates are built from transistor switches; CMOS pairs PMOS transistors that pull up to 1 with NMOS transistors that pull down to 0.</sub> | 인버터는 PMOS 하나와 NMOS 하나로, 입력이 0이면 PMOS가 켜져 출력이 1, 입력이 1이면 NMOS가 켜져 출력이 0이 돼요. NAND는 PMOS 두 개를 병렬로, NMOS 두 개를 직렬로 이어 둘 다 1일 때만 0을 내요. 항상 한쪽만 켜져 평소에 전류가 거의 흐르지 않아 저전력이고, NAND가 트랜지스터 4개로 가장 싸서 칩 설계의 기본 단위가 돼요.<br><sub>An inverter uses one PMOS and one NMOS: input 0 turns the PMOS on and the output becomes 1; input 1 turns the NMOS on and the output becomes 0. NAND puts two PMOS in parallel and two NMOS in series, giving 0 only when both inputs are 1. Only one side ever conducts, so idle current is tiny, and NAND needs just four transistors, making it the workhorse of chip design.</sub> |
| **진리표에서 논리식으로**<br><sub>From truth tables to formulas</sub> | 진리표에서 출력이 1인 줄마다 AND 항을 만들어 OR로 묶으면 어떤 함수든 회로로 만들 수 있어요 (곱의 합, SOP).<br><sub>Write one AND term for each row where the output is 1 and OR them together: any function can be built this way (sum of products).</sub> | 셋 중 둘 이상이 1이면 1인 다수결 함수는 최소항 m3, m5, m6, m7을 OR한 F = A′BC + AB′C + ABC′ + ABC예요. 이는 AND 층과 OR 층의 2단 회로가 되고, 반대로 0인 줄로 OR 항을 만들어 AND하면 합의 곱(POS)이에요. 표준형은 기계적으로 만들 수 있지만 길어서, 카르노 맵으로 F = AB + BC + AC처럼 줄여요.<br><sub>The majority function, 1 when at least two of three inputs are 1, is F = A′BC + AB′C + ABC′ + ABC, the OR of minterms m3, m5, m6 and m7. That is a two-level AND–OR circuit; building OR terms from the 0 rows and ANDing them gives the product of sums (POS) instead. Canonical forms are mechanical but long, so Karnaugh maps reduce them, here to F = AB + BC + AC.</sub> |
| **불 대수로 간소화**<br><sub>Simplifying with Boolean algebra</sub> | 항등·보수·흡수·분배 같은 법칙으로 논리식을 줄이면, 같은 동작을 훨씬 적은 게이트로 만들 수 있어요.<br><sub>Laws such as identity, complement, absorption and distribution shrink a formula so the same behavior needs far fewer gates.</sub> | A + 0 = A, A + A′ = 1, A + AB = A, A + A′B = A + B 같은 법칙을 차례로 적용하면 F = AB + AB′ + A′B가 A + B, 즉 OR 게이트 하나가 돼요. 게이트가 줄면 칩 면적·전력·지연이 함께 줄어요. 변수가 적으면 손이나 카르노 맵으로, 많으면 콰인–매클러스키 알고리즘이나 Yosys 같은 논리 합성 도구가 자동으로 줄여요.<br><sub>Applying A + 0 = A, A + A′ = 1, A + AB = A and A + A′B = A + B in turn reduces F = AB + AB′ + A′B to A + B, a single OR gate. Fewer gates mean less area, power and delay. Small cases are done by hand or with Karnaugh maps; larger ones by the Quine–McCluskey algorithm or synthesis tools such as Yosys.</sub> |
| **3상태 버퍼와 버스**<br><sub>Tri-state buffers and buses</sub> | 출력을 0, 1뿐 아니라 “연결 끊김(Z)” 상태로도 만들 수 있는 버퍼예요. 여러 장치가 선 하나(버스)를 차례로 나눠 써요.<br><sub>A buffer whose output can be 0, 1 or disconnected (Z), letting many devices take turns on one wire, a bus.</sub> | EN이 1이면 입력을 그대로 내보내고, 0이면 높은 임피던스(Z)가 되어 선에서 빠진 것처럼 행동해요. 디코더가 한 번에 한 장치의 EN만 켜 주면 CPU, RAM, I/O가 같은 데이터 버스를 공유할 수 있어요. 두 장치가 동시에 구동하면 1과 0이 맞붙어 과전류가 흐르는 버스 충돌이 생겨요. I²C 같은 버스는 오픈 드레인 방식으로 이 문제를 피해요.<br><sub>With EN = 1 it passes its input; with EN = 0 it goes high-impedance (Z) and behaves as if unplugged. When a decoder enables exactly one device at a time, the CPU, memory and I/O can share one data bus. Two drivers at once fight, 1 against 0, causing bus contention and overcurrent. Buses such as I²C avoid this with open-drain outputs.</sub> |
| **패리티와 오류 검출**<br><sub>Parity and error detection</sub> | 1의 개수가 짝수가 되도록 비트 하나를 덧붙여, 전송 중 비트 하나가 뒤집히면 알아채요. XOR 게이트 트리로 계산해요.<br><sub>Append one bit so the number of 1s is even; if a single bit flips in transit, the receiver notices. An XOR tree computes it.</sub> | 보내는 쪽은 데이터 비트를 모두 XOR한 값을 패리티 비트로 붙이고, 받는 쪽은 전체를 다시 XOR해 1이 나오면 홀수 개 오류로 판단해요. 두 비트가 동시에 뒤집히면 못 알아채요. 해밍 코드는 패리티 비트를 여러 개 두어 오류 위치를 찾아 고치고, ECC 메모리는 1비트 정정·2비트 검출(SECDED)을 해요. UART 통신과 RAID 5도 XOR 패리티를 써요.<br><sub>The sender appends the XOR of all data bits, and the receiver XORs everything again: a 1 means an odd number of errors. Two simultaneous flips go unnoticed. Hamming codes use several parity bits to locate and correct errors, and ECC memory corrects one bit and detects two (SECDED). UART links and RAID 5 rely on XOR parity too.</sub> |

## 조합 회로 · Combinational circuits

현재 입력만으로 출력이 정해지는 회로예요.  
*Circuits whose output depends only on the current inputs.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **반가산기**<br><sub>Half adder</sub> | 1비트 두 개를 더해 합(XOR)과 올림(AND)을 내요.<br><sub>Adds two single bits, producing a sum (XOR) and a carry (AND).</sub> | 컴퓨터의 모든 산술은 이 작은 회로에서 시작해요.<br><sub>All computer arithmetic grows from this little circuit.</sub> |
| **전가산기**<br><sub>Full adder</sub> | 두 비트와 아랫자리에서 올라온 올림까지 세 비트를 더해 합과 올림을 내요. 반가산기 두 개와 OR로 만들어요.<br><sub>Adds two bits plus the carry from the previous column, built from two half adders and an OR.</sub> | 전가산기를 이어 붙이면 몇 비트든 더하는 가산기가 되고, 2의 보수와 합치면 뺄셈도 해요. ALU의 핵심 부품이에요.<br><sub>Chain full adders for any width; with two’s complement they also subtract. It is the heart of the ALU.</sub> |
| **리플 캐리 가산기**<br><sub>Ripple-carry adder</sub> | 전가산기를 일렬로 이어 여러 비트를 더해요. 올림이 아랫자리부터 차례로 전달돼서 비트 수만큼 지연돼요.<br><sub>Full adders chained in a row add multi-bit numbers, but the carry ripples through one stage at a time.</sub> | 실제 CPU는 올림을 미리 계산하는 캐리 룩어헤드 가산기로 지연을 줄여요. 회로 깊이가 클럭 속도를 정해요.<br><sub>Real CPUs use carry-lookahead adders to cut the delay; circuit depth limits clock speed.</sub> |
| **멀티플렉서**<br><sub>Multiplexer</sub> | 선택 신호에 따라 여러 입력 중 하나를 출력으로 보내는 전자 스위치예요.<br><sub>An electronic switch that forwards one of several inputs, chosen by select lines.</sub> | CPU에서 ALU 입력을 레지스터 중 하나로 고르는 등 데이터 경로 곳곳에 있어요. 코드의 switch문과 같은 역할이에요.<br><sub>It appears throughout CPU datapaths, such as choosing which register feeds the ALU; it is a hardware switch statement.</sub> |
| **디코더**<br><sub>Decoder</sub> | n비트 입력을 받아 2ⁿ개의 출력 중 정확히 하나만 켜요.<br><sub>Takes an n-bit input and turns on exactly one of 2ⁿ outputs.</sub> | 메모리 주소로 어느 칩·행을 쓸지 고르고, 명령어의 종류를 해석하는 데 써요.<br><sub>It selects memory chips or rows from an address and decodes instruction types.</sub> |
| **우선순위 인코더**<br><sub>Priority encoder</sub> | 켜진 입력의 번호를 2진수로 바꿔요(디코더의 반대). 여러 개가 켜지면 가장 높은 것을 골라요.<br><sub>Turns which input is on into a binary number (the decoder’s inverse), picking the highest when several are on.</sub> | 4→2 우선순위 인코더는 I3이 켜지면 11, I2면 10처럼 가장 높은 활성 입력의 번호를 내고, 아무것도 켜지지 않으면 유효 비트 V를 0으로 내려요. 인터럽트 컨트롤러가 여러 요청 중 가장 급한 것을 고르거나, 키보드가 눌린 키를 번호로 바꾸는 데 써요.<br><sub>A 4-to-2 priority encoder outputs 11 when I3 is on, 10 for I2 and so on, always reporting the highest active input, and drops the valid bit V to 0 when nothing is on. Interrupt controllers use it to pick the most urgent request, and keyboards to turn a pressed key into a code.</sub> |
| **크기 비교기**<br><sub>Magnitude comparator</sub> | 두 2진수를 높은 자리부터 비교해 A > B, A = B, A < B를 알려 주는 회로예요.<br><sub>A circuit that compares two binary numbers from the top bit and reports A > B, A = B or A < B.</sub> | 자리마다 XNOR로 같은지 보고, 위 자리가 모두 같다가 처음 달라지는 자리에서 A가 1이고 B가 0이면 A > B로 결정해요. 식으로는 A>B = A₃B₃′ + (A₃⊙B₃)A₂B₂′ + …처럼 이어져요. 74HC85 같은 칩은 여러 개를 이어 8·16비트로 넓히고, CPU는 보통 A − B를 계산해 플래그로 비교해요.<br><sub>Each bit pair is checked for equality with XNOR; at the first position where higher bits were all equal and A has 1 while B has 0, the answer is A > B, written A>B = A₃B₃′ + (A₃⊙B₃)A₂B₂′ + …. Chips like the 74HC85 cascade to 8 or 16 bits, while CPUs usually compute A − B and compare via flags.</sub> |
| **캐리 룩어헤드 가산기**<br><sub>Carry-lookahead adder</sub> | 올림을 한 자리씩 기다리지 않고, 자리마다의 생성(G)·전파(P) 신호로 모든 올림을 한꺼번에 계산하는 빠른 가산기예요.<br><sub>A fast adder that computes every carry at once from per-bit generate (G) and propagate (P) signals instead of waiting bit by bit.</sub> | G = A·B는 그 자리에서 올림을 만들고, P = A⊕B는 들어온 올림을 넘겨준다는 뜻이에요. C₂ = G₁ + P₁G₀ + P₁P₀C₀처럼 모든 올림을 G와 P로 펼쳐 쓰면 AND 한 층과 OR 한 층으로 끝나 리플 캐리의 O(n) 지연이 사라져요. 자리가 많으면 4비트 블록을 계층으로 묶어 O(log n)으로 만들고, CPU의 64비트 덧셈기는 콕–스톤 같은 병렬 접두 구조를 써요.<br><sub>G = A·B means a bit creates a carry; P = A⊕B means it passes one along. Expanding each carry, such as C₂ = G₁ + P₁G₀ + P₁P₀C₀, needs only an AND level and an OR level, removing ripple carry’s O(n) delay. Wide adders group 4-bit blocks hierarchically for O(log n), and 64-bit CPU adders use parallel-prefix designs such as Kogge–Stone.</sub> |
| **산술 논리 장치 (ALU)**<br><sub>Arithmetic logic unit (ALU)</sub> | AND, OR, 덧셈, 뺄셈 같은 연산 회로를 모두 두고, 연산 코드로 결과 하나를 골라 내보내는 CPU의 계산기예요.<br><sub>The CPU’s calculator: circuits for AND, OR, addition and subtraction side by side, with an opcode selecting which result comes out.</sub> | 두 입력을 모든 연산 회로에 동시에 넣고, op 신호가 멀티플렉서로 결과를 골라요. 결과와 함께 Z(0인가), N(음수인가), C(올림), V(부호 있는 오버플로) 플래그를 내서 비교와 분기에 써요. 예를 들어 4비트에서 6 + 3 = 9는 부호 있는 수로 −7이 되어 V = 1이에요. ADD, AND, CMP, SUB 같은 명령어가 모두 이 회로를 공유해요.<br><sub>Both operands feed every operation at once, and the op signal drives a multiplexer that picks one result. Alongside it come the flags Z (zero), N (negative), C (carry) and V (signed overflow) used for comparisons and branches; in 4 bits, 6 + 3 = 9 reads as −7 signed, so V = 1. Instructions such as ADD, AND, CMP and SUB all share this circuit.</sub> |
| **가감산기**<br><sub>Adder–subtractor</sub> | XOR 게이트 몇 개를 더해 가산기 하나로 덧셈과 뺄셈을 모두 해요. 2의 보수 덕분이에요.<br><sub>A few XOR gates let one adder both add and subtract, thanks to two’s complement.</sub> | 모드 신호 M을 B의 각 비트와 XOR하고 올림 입력에도 넣어요. M = 0이면 A + B, M = 1이면 B가 뒤집히고 1이 더해져 A + B′ + 1 = A − B가 돼요. 예: 0110 + 1101 + 1 = 0100(6 − 2 = 4). 그래서 CPU에는 별도의 뺄셈기가 필요 없어요.<br><sub>The mode signal M is XORed with every bit of B and also fed in as the carry-in. With M = 0 the circuit computes A + B; with M = 1, B is inverted and 1 is added, giving A + B′ + 1 = A − B, e.g. 0110 + 1101 + 1 = 0100 (6 − 2 = 4). That is why CPUs need no separate subtractor.</sub> |
| **전파 지연과 해저드**<br><sub>Propagation delay and hazards</sub> | 게이트는 출력이 바뀌는 데 시간이 걸려요. 경로마다 지연이 달라 출력이 잠깐 튀는 글리치가 생길 수 있어요.<br><sub>Gates take time to switch, and unequal path delays can make an output glitch briefly.</sub> | F = AB + A′C에서 B = C = 1일 때 A가 1에서 0으로 바뀌면, A′가 NOT 지연만큼 늦게 1이 되어 잠깐 두 항이 모두 0이 되고 F가 튀어요(정적 해저드). 합의항 BC를 더하면 막을 수 있어요. 가장 긴 게이트 사슬인 임계 경로의 지연이 최대 클록 주파수를 정하고, 동기식 회로는 값이 안정된 뒤 클록 엣지에서만 읽어 글리치를 무시해요.<br><sub>In F = AB + A′C with B = C = 1, when A falls from 1 to 0, A′ rises only after the NOT delay, so both terms are briefly 0 and F dips (a static hazard); adding the consensus term BC prevents it. The delay of the longest gate chain, the critical path, caps the clock frequency, and synchronous circuits ignore glitches by sampling only on clock edges after values settle.</sub> |

## 순차 회로와 기억 · Sequential circuits and memory

되먹임과 클럭으로 이전 상태를 기억하는 회로예요.  
*Circuits that remember using feedback and a clock.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **SR 래치**<br><sub>SR latch</sub> | 두 NOR 게이트의 출력을 서로의 입력으로 되먹이면, 입력을 떼도 값을 유지하는 1비트 기억 장치가 돼요.<br><sub>Cross-feeding two NOR gates creates a one-bit memory that holds its value after the inputs are released.</sub> | 되먹임이 기억을 만들어요. CPU 캐시(SRAM)는 이런 래치 수십억 개로 이뤄져 있어요.<br><sub>Feedback creates memory; CPU caches (SRAM) are billions of such cells.</sub> |
| **D 플립플롭**<br><sub>D flip-flop</sub> | 클럭이 올라가는 순간에만 입력 D를 저장하고, 그 외엔 값을 유지해요.<br><sub>Captures input D only at the rising clock edge and holds it otherwise.</sub> | 모든 레지스터와 상태 기계가 클럭에 맞춰 동시에 바뀌게 해 주는 부품이에요. 클럭 속도(GHz)가 바로 이 박자예요.<br><sub>It makes registers and state machines change in lockstep; the clock speed in GHz is this beat.</sub> |
| **카운터**<br><sub>Counter</sub> | 플립플롭을 이어 클럭마다 값이 1씩 올라가게 만든 회로예요.<br><sub>Flip-flops chained so the value goes up by one every clock tick.</sub> | 타이머, 프로그램 카운터(PC), 주파수 분주기에 써요. 범위를 넘으면 0으로 돌아가는 것도 정수 오버플로와 같아요.<br><sub>Used for timers, the program counter and frequency dividers; wrapping to zero is the same as integer overflow.</sub> |
| **시프트 레지스터**<br><sub>Shift register</sub> | 클럭마다 저장된 비트들을 한 칸씩 옮겨요. 직렬 데이터를 병렬로(또는 반대로) 바꿀 수 있어요.<br><sub>Moves its stored bits one place on every clock, converting serial data to parallel or back.</sub> | USB·SPI 같은 직렬 통신에 써요. 소프트웨어의 비트 시프트(<<, >>)가 2배·절반 연산인 이유도 같아요.<br><sub>Used in serial links like USB and SPI; it is also why software bit shifts (<<, >>) multiply or divide by two.</sub> |
| **JK·T 플립플롭**<br><sub>JK and T flip-flops</sub> | JK 플립플롭은 클록마다 유지·리셋·셋·토글 중 하나를 해요. J와 K를 묶은 T 플립플롭은 클록마다 값을 뒤집어요.<br><sub>A JK flip-flop holds, resets, sets or toggles on each clock; a T flip-flop, J and K tied together, flips every clock.</sub> | JK = 00이면 유지, 01이면 0, 10이면 1, 11이면 토글이에요. SR 래치에서 금지였던 (1, 1) 입력을 쓸모 있는 토글로 바꾼 셈이에요. T = 1로 둔 T 플립플롭은 출력 주파수가 클록의 절반이 되어 분주기가 되고, 여러 개를 이어 붙이면 2진 리플 카운터가 돼요.<br><sub>JK = 00 holds, 01 resets to 0, 10 sets to 1 and 11 toggles, turning the SR latch’s forbidden (1, 1) input into something useful. A T flip-flop with T = 1 outputs half the clock frequency, a frequency divider, and chaining several gives a binary ripple counter.</sub> |
| **순차 회로 설계: 시퀀스 검출기**<br><sub>Sequential design: a sequence detector</sub> | “101”이 들어오면 1을 내는 회로를 상태 기계로 설계해요. 상태도 → 상태 할당 → 플립플롭 입력식 순서예요.<br><sub>Design a circuit that outputs 1 whenever “101” arrives, as a state machine: state diagram → state assignment → flip-flop input equations.</sub> | 상태는 S0(아직 없음), S1(1을 봄), S2(10을 봄), S3(101을 봄, 출력 1) 네 개이고, 겹치는 패턴도 인정하려면 S3에서 0이 오면 S2로 가요. 상태 4개는 플립플롭 2개로 저장하고, 상태표를 카르노 맵으로 줄여 다음 상태 논리를 만들어요. 통신의 프레임 시작 검출, 자판기, 엘리베이터 제어기가 이렇게 설계돼요.<br><sub>The states are S0 (nothing yet), S1 (saw 1), S2 (saw 10) and S3 (saw 101, output 1); to catch overlapping patterns, a 0 in S3 leads back to S2. Four states fit in two flip-flops, and Karnaugh maps of the state table give the next-state logic. Frame-start detectors, vending machines and elevator controllers are designed this way.</sub> |
| **셋업·홀드 시간과 메타안정성**<br><sub>Setup, hold and metastability</sub> | 플립플롭은 클록 엣지 앞뒤의 짧은 구간 동안 입력이 가만히 있어야 해요. 그 사이에 바뀌면 출력이 한동안 0도 1도 아닌 상태로 흔들려요.<br><sub>Inputs must stay still in a short window around the clock edge; changes inside it can leave the output hovering between 0 and 1.</sub> | 엣지 전 D가 안정해야 하는 시간이 셋업, 엣지 후가 홀드예요. 이를 어기면 출력이 메타안정 상태로 흔들리다 무작위 값으로 정착해요. 셋업 위반은 클록을 늦추면 풀리지만 홀드 위반은 경로에 지연을 더해야 해요. 다른 클록 영역에서 온 신호는 플립플롭 2단짜리 동기화기로 받아 위험을 거의 없애고, 정적 타이밍 분석(STA)이 칩의 모든 경로를 검사해요.<br><sub>Setup time is how long D must be stable before the edge, hold time after it. Violations can make the output metastable, wobbling before settling at a random value. Setup violations disappear with a slower clock, but hold violations need added path delay. Signals crossing from another clock domain go through a two-flip-flop synchronizer, and static timing analysis (STA) checks every path on a chip.</sub> |
| **SRAM과 메모리 배열**<br><sub>SRAM and memory arrays</sub> | 서로 물린 인버터 두 개가 비트 하나를 붙잡는 SRAM 셀을 격자로 늘어놓고, 행(워드 라인)과 열(비트 라인)로 읽고 써요.<br><sub>SRAM cells, two cross-coupled inverters holding a bit, are tiled into a grid and accessed by rows (word lines) and columns (bit lines).</sub> | 주소를 디코더가 풀어 한 워드 라인을 켜면 그 행의 셀들이 비트 라인에 연결되어, 쓰기 땐 값을 밀어 넣고 읽기 땐 감지 증폭기가 값을 읽어요. SRAM은 셀당 트랜지스터 6개로 빠르고 새로고침이 필요 없어 CPU 캐시와 레지스터 파일에 쓰이고, DRAM은 트랜지스터 1개와 커패시터로 촘촘하지만 계속 새로고침해야 해 주 메모리에 써요.<br><sub>A decoder turns the address into one active word line, connecting that row’s cells to the bit lines: writes drive values in, reads let sense amplifiers detect them. SRAM uses six transistors per cell, is fast and needs no refresh, so it serves CPU caches and register files; DRAM uses one transistor and a capacitor, denser but constantly refreshed, for main memory.</sub> |
| **LUT와 FPGA**<br><sub>LUTs and FPGAs</sub> | LUT는 진리표를 담은 작은 메모리예요. 내용만 바꾸면 어떤 함수든 되고, 수많은 LUT를 배선으로 연결한 칩이 FPGA예요.<br><sub>A LUT is a tiny memory holding a truth table, so rewriting it changes the function; an FPGA is thousands of LUTs joined by programmable wiring.</sub> | 2입력 LUT는 4칸 메모리와 멀티플렉서로, 입력이 칸을 골라 그 값을 내보내요. 0110을 넣으면 XOR, 0001을 넣으면 AND가 돼요. FPGA는 LUT·플립플롭 블록과 프로그래머블 배선으로 이뤄져, Verilog·VHDL로 쓴 회로를 합성 도구가 비트스트림으로 바꿔 올려요. 칩 시제품, 통신 장비, 초저지연 거래에 쓰이고 대량 생산은 전용 칩(ASIC)이 유리해요.<br><sub>A 2-input LUT is four memory bits and a multiplexer: the inputs select a slot and its value comes out, so 0110 makes XOR and 0001 makes AND. An FPGA combines LUT/flip-flop blocks with programmable routing; circuits written in Verilog or VHDL are synthesized into a bitstream that configures it. FPGAs serve chip prototypes, telecom gear and low-latency trading, while ASICs win at high volume.</sub> |
