## 유틸리티 우선의 기초 · Utility-first basics

작은 단일 목적 클래스를 조합해 스타일을 입히는 사고방식과, 간격·색·글자 스케일, 그리고 쓰인 클래스만 만드는 원리예요.  
*The mindset of composing small single-purpose classes, the spacing, color and type scales, and how only used classes get generated.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **유틸리티 우선**<br><sub>Utility-first</sub> | px-4, bg-sky-600처럼 CSS 선언 하나에 해당하는 작은 클래스를 HTML에 조합해 스타일을 입히는 방식이에요. 클래스 이름을 짓고 CSS 파일을 오갈 필요가 없어요.<br><sub>Utility-first styling composes small classes, each matching one CSS declaration such as px-4 or bg-sky-600, directly in the HTML, with no class names to invent and no CSS files to switch to.</sub> | 전통적인 CSS는 .btn-primary 같은 이름을 짓고 별도 파일에 규칙을 적어요. 유틸리티 우선 방식은 class="px-4 py-2 rounded-lg bg-sky-600 text-white"처럼 이미 준비된 클래스를 마크업에서 바로 조합해요. 스타일이 그 요소에만 걸려서 다른 화면을 깨뜨릴 걱정이 적고, 요소를 지우면 스타일도 함께 사라져 쓰지 않는 CSS가 쌓이지 않아요. 값이 디자인 토큰(간격 단계, 색 단계)에서 나와서 여러 사람이 만들어도 화면이 일관돼요. 인라인 style과 달리 hover:, md:, dark: 같은 상태·반응형 조건도 쓸 수 있어요. 대신 클래스 목록이 길어지므로 반복은 컴포넌트로 추출해 관리해요.<br><sub>Traditional CSS names things like .btn-primary and writes rules in a separate file. Utility-first combines ready-made classes in the markup, as in class="px-4 py-2 rounded-lg bg-sky-600 text-white". Styles apply only to that element, so changes rarely break other screens, and deleting an element deletes its styles, so unused CSS never piles up. Values come from design tokens (spacing and color scales), keeping screens consistent across many authors. Unlike inline styles, utilities support conditions such as hover:, md: and dark:. The trade-off is long class lists, which are managed by extracting components.</sub> |
| **간격과 크기 스케일**<br><sub>Spacing and size scales</sub> | p-4, mt-8, w-64의 숫자는 간격 단위의 개수예요. 한 단위는 --spacing(기본 0.25rem = 4px)이라 모든 간격이 같은 박자를 따라요.<br><sub>The numbers in p-4, mt-8 and w-64 count spacing units, and one unit is --spacing (0.25rem, or 4px, by default), so all spacing follows the same rhythm.</sub> | p-4는 padding: 1rem(16px), mt-8은 margin-top: 2rem(32px)이에요. v4에서는 모든 숫자가 calc(var(--spacing) \* n)으로 계산돼서 w-13이나 gap-2.5처럼 목록에 없던 숫자도 바로 써요. 같은 스케일이 패딩·마진·gap·너비·높이·inset에 공통으로 쓰여 요소 사이 리듬이 맞아요. w-1/2 같은 분수는 퍼센트, w-full·w-screen·max-w-prose 같은 이름 있는 값도 있고, size-10은 너비와 높이를 한꺼번에 정해요. 음수 마진은 -mt-4처럼 앞에 -를 붙여요. --spacing 값 하나를 바꾸면 프로젝트 전체 밀도를 조절할 수 있어요.<br><sub>p-4 means padding: 1rem (16px) and mt-8 margin-top: 2rem (32px). In v4 every number is computed as calc(var(--spacing) \* n), so values not in a fixed list, such as w-13 or gap-2.5, just work. The same scale serves padding, margin, gap, width, height and inset, keeping rhythm between elements. Fractions such as w-1/2 are percentages, named values such as w-full, w-screen and max-w-prose exist, and size-10 sets width and height at once. Negative margins prefix a dash, as in -mt-4. Changing --spacing alone adjusts the density of the whole project.</sub> |
| **색 팔레트와 투명도**<br><sub>Color palette and opacity</sub> | 색은 sky-500처럼 색 이름과 50~950 단계로 써요. 같은 이름을 bg-, text-, border-에 쓰고, /50으로 투명도를 줘요.<br><sub>Colors combine a name and a shade from 50 to 950, as in sky-500, use the same names for bg-, text- and border-, and take opacity with /50.</sub> | 기본 팔레트에는 slate, gray, red, sky 같은 색이 50부터 950까지 11단계로 있어요(v4.2에 mauve, olive, mist, taupe가 추가됐어요). bg-sky-500, text-sky-700, border-sky-200, ring-sky-500처럼 속성 접두사만 바꿔 같은 색을 써요. bg-black/50처럼 슬래시 뒤 숫자로 투명도를 주고, 내부적으로는 color-mix()로 계산돼요. v4 팔레트는 oklch로 정의되어 단계마다 밝기가 고르게 변하고 넓은 색 영역 화면에서 더 선명해요. 팔레트 밖 색은 bg-[#1da1f2]처럼 대괄호로, 브랜드 색은 @theme에 --color-brand-500으로 추가해 정식 토큰으로 만들어요. 글자는 600~900, 배경은 50~100처럼 단계 차이를 크게 두면 대비 기준도 쉽게 맞아요.<br><sub>The default palette has colors such as slate, gray, red and sky in 11 shades from 50 to 950, with mauve, olive, mist and taupe added in v4.2. Only the property prefix changes, as in bg-sky-500, text-sky-700, border-sky-200 and ring-sky-500. A slash adds opacity, as in bg-black/50, computed internally with color-mix(). The v4 palette is defined in oklch, so lightness steps evenly and colors look more vivid on wide-gamut screens. Colors outside the palette use brackets, as in bg-[#1da1f2], while brand colors become proper tokens in @theme, such as --color-brand-500. Keeping text at 600 to 900 and backgrounds at 50 to 100 makes contrast requirements easy to meet.</sub> |
| **글자 유틸리티**<br><sub>Typography utilities</sub> | text-4xl(크기), font-bold(굵기), tracking-tight(자간), text-base/7(크기/줄 간격), truncate·line-clamp(말줄임)로 글자를 다뤄요.<br><sub>Typography is handled with text-4xl (size), font-bold (weight), tracking-tight (letter spacing), text-base/7 (size with line height) and truncate or line-clamp (ellipsis).</sub> | 글자 크기는 text-xs부터 text-9xl까지 rem 단위라 사용자의 브라우저 글꼴 크기 설정을 존중해요. text-base/7처럼 슬래시로 줄 간격을 함께 주고, leading-\*로 따로 정할 수도 있어요. 굵기는 font-normal·medium·semibold·bold, 자간은 tracking-tight·wide로 조절해요. 한 줄 말줄임은 truncate, 여러 줄은 line-clamp-2처럼 써요. text-balance는 제목의 줄 길이를 고르게, text-pretty는 마지막 줄에 단어 하나만 남는 걸 막아요. 블로그 본문처럼 마크다운으로 만든 HTML 전체는 typography 플러그인의 prose 클래스로 한 번에 꾸미고, 한글 본문은 줄 간격을 넉넉하게 두는 게 좋아요.<br><sub>Sizes from text-xs to text-9xl use rem, respecting the browser’s font size setting. A slash adds line height, as in text-base/7, or leading-\* sets it separately. Weights run through font-normal, medium, semibold and bold, and tracking-tight or wide adjusts letter spacing. truncate cuts to one line with an ellipsis, and line-clamp-2 to several lines. text-balance evens heading lines, and text-pretty avoids a lone word on the last line. Whole markdown-generated HTML, such as blog posts, is styled at once with the prose class from the typography plugin, and Korean body text benefits from generous line height.</sub> |
| **임의 값**<br><sub>Arbitrary values</sub> | 스케일에 없는 값은 w-[37px]처럼 대괄호에 넣어 즉석에서 만들어요. CSS 변수는 bg-(--brand)처럼 괄호로 써요.<br><sub>Values off the scale go in brackets, as in w-[37px], and are generated on the spot, while CSS variables use parentheses, as in bg-(--brand).</sub> | 디자인 시안의 딱 그 숫자가 필요할 때 top-[117px], bg-[#bada55], grid-cols-[200px\_1fr]처럼 대괄호 안에 값을 적어요. 대괄호 안에서 공백은 밑줄(\_)로 적어요. 유틸리티가 없는 CSS 속성은 [mask-type:luminance]처럼 속성과 값을 통째로 써요. v4에서는 CSS 변수를 bg-(--brand)처럼 소괄호로 써서 var()를 생략해요. calc(), min(), clamp() 같은 함수도 그대로 넣을 수 있어요. 편리하지만 남발하면 디자인 스케일이 무너지니 일회성 값에만 쓰고, 두 번 이상 쓰는 값은 @theme 토큰으로 올려요.<br><sub>When a mockup needs an exact number, write the value inside brackets, as in top-[117px], bg-[#bada55] or grid-cols-[200px\_1fr]. Spaces inside brackets are written as underscores. Properties without a utility take the whole declaration, as in [mask-type:luminance]. In v4, CSS variables use parentheses, as in bg-(--brand), dropping the var(). Functions such as calc(), min() and clamp() work too. They are convenient, but overuse erodes the design scale, so keep them for one-offs and promote any value used twice to an @theme token.</sub> |
| **쓰인 클래스만 생성**<br><sub>Generating only used classes</sub> | Tailwind는 소스 파일을 훑어 실제로 쓰인 클래스 이름만 CSS로 만들어요. 그래서 클래스 이름은 문자열을 조립하지 말고 완전한 형태로 적어야 해요.<br><sub>Tailwind scans source files and generates CSS only for class names actually used, so class names must be written whole, never assembled from strings.</sub> | 가능한 유틸리티는 수십만 개지만 결과 CSS에는 프로젝트가 쓴 것만 들어가서 보통 수십 KB 이하예요. 스캐너는 코드를 실행하지 않고 텍스트에서 클래스처럼 보이는 토큰을 찾아요. 그래서 `text-${color}-500`처럼 조립한 이름은 찾지 못해 스타일이 빠져요. 조건에 따라 바뀌어도 color === "red" ? "text-red-500" : "text-blue-500"처럼 완전한 이름을 적어 두면 돼요. v4는 .gitignore에 있는 경로와 바이너리를 빼고 소스를 자동으로 찾고, 모노레포의 다른 패키지는 @source로 추가해요. DB에서 오는 색처럼 정말 동적인 값은 style 속성이나 CSS 변수로 넘겨요.<br><sub>Hundreds of thousands of utilities are possible, but the output holds only what the project uses, usually tens of kilobytes at most. The scanner does not run code; it looks for class-like tokens in text. So an assembled name such as `text-${color}-500` is never seen and the style goes missing. Even when classes vary, writing complete names, as in color === "red" ? "text-red-500" : "text-blue-500", works. v4 finds sources automatically while skipping .gitignore paths and binaries, and other monorepo packages are added with @source. Truly dynamic values, such as colors from a database, go through the style attribute or CSS variables.</sub> |

## 레이아웃과 반응형 · Layout and responsiveness

Flexbox와 Grid, 반응형 접두사와 컨테이너 쿼리, 크기와 위치 지정을 클래스로 표현하는 방법이에요.  
*Expressing Flexbox, Grid, responsive prefixes, container queries, sizing and positioning as classes.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **Flexbox 유틸리티**<br><sub>Flexbox utilities</sub> | flex, items-center, justify-between, gap-4, flex-1로 한 방향 배치를 만들어요. 내비게이션 바와 버튼 줄의 기본이에요.<br><sub>flex, items-center, justify-between, gap-4 and flex-1 build one-directional layouts, the foundation of navigation bars and button rows.</sub> | flex를 주면 자식이 가로로 나란히 놓이고, flex-col로 세로로 바꿔요. items-\*는 교차축(보통 세로) 정렬, justify-\*는 주축(보통 가로) 배분이에요. gap-4는 아이템 사이 간격을 주는데, 줄바꿈(flex-wrap)이나 숨긴 요소가 있어도 안전해서 space-x-\*보다 권장돼요. flex-1은 남은 공간을 차지하고, 긴 글이 넘칠 땐 min-w-0을 함께 줘야 줄어들어요. shrink-0은 로고나 아바타가 찌그러지지 않게 막아요. flex-col md:flex-row처럼 반응형 접두사로 방향을 바꾸는 패턴이 아주 흔해요.<br><sub>flex lines children up in a row, and flex-col switches to a column. items-\* aligns on the cross axis (usually vertical) and justify-\* distributes along the main axis (usually horizontal). gap-4 spaces items and stays correct with wrapping (flex-wrap) or hidden elements, so it is preferred over space-x-\*. flex-1 takes the remaining space, and long text needs min-w-0 alongside it to shrink. shrink-0 keeps logos and avatars from squashing. Switching direction with a responsive prefix, as in flex-col md:flex-row, is a very common pattern.</sub> |
| **Grid 유틸리티**<br><sub>Grid utilities</sub> | grid grid-cols-3 gap-6처럼 열 수와 간격을 정해 2차원 배치를 만들어요. col-span-2로 칸을 합치고 반응형 접두사로 열 수를 바꿔요.<br><sub>grid grid-cols-3 gap-6 sets column count and gaps for two-dimensional layout, col-span-2 merges tracks, and responsive prefixes change the column count.</sub> | grid-cols-1 sm:grid-cols-2 lg:grid-cols-4는 카드 목록의 단골 패턴으로, 화면이 넓어질수록 열이 늘어나요. col-span-2, row-span-2로 큰 카드를 만들고, col-start-\*로 시작 위치를 정해요. grid-cols-[240px\_1fr]처럼 임의 값으로 고정 사이드바와 유연한 본문을 만들 수 있어요. 열 개수를 고정하지 않고 자동으로 채우려면 grid-cols-[repeat(auto-fill,minmax(200px,1fr))]처럼 써요. place-items-center는 한 줄로 가로세로 가운데 정렬을 해요. subgrid도 지원해서 카드 안 제목과 버튼 줄을 이웃 카드와 맞출 수 있어요.<br><sub>grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 is the classic card list, adding columns as the screen widens. col-span-2 and row-span-2 make feature cards, and col-start-\* sets a start line. Arbitrary values such as grid-cols-[240px\_1fr] create a fixed sidebar beside a flexible main area. To fill columns automatically, write grid-cols-[repeat(auto-fill,minmax(200px,1fr))]. place-items-center centers both ways in one class. subgrid is supported too, aligning titles and buttons across neighboring cards.</sub> |
| **반응형 접두사**<br><sub>Responsive prefixes</sub> | sm:, md:, lg: 접두사는 “그 크기 이상에서”라는 뜻이에요. 접두사 없는 클래스가 모바일 기본값이고, 넓어질수록 덮어써요.<br><sub>The sm:, md: and lg: prefixes mean “from this size up”; unprefixed classes are the mobile default, overridden as the screen widens.</sub> | 기본 기준점은 sm 40rem(640px), md 48rem(768px), lg 64rem(1024px), xl 80rem, 2xl 96rem이에요. w-full md:w-1/2 lg:w-1/3이면 모바일은 꽉 차게, 태블릿 이상은 반, 데스크톱은 3분의 1이에요. 그래서 “sm:은 휴대폰용”이 아니라 “40rem 이상”이라는 점이 가장 흔한 착각이에요. hidden md:flex로 넓은 화면에서만 보이게 하고, max-md:처럼 max-를 붙이면 “미만”에, md:max-lg:로 범위에 적용해요. 기준점은 @theme의 --breakpoint-\*로 추가하거나 바꿔요. 모바일부터 설계하면 작은 화면에서 필요한 것만 남기게 돼서 더 단순해져요.<br><sub>The default breakpoints are sm 40rem (640px), md 48rem (768px), lg 64rem (1024px), xl 80rem and 2xl 96rem. w-full md:w-1/2 lg:w-1/3 is full width on mobile, half from tablets and a third on desktops. The most common confusion is reading sm: as “for phones” when it means “40rem and up”. hidden md:flex shows an element only on wide screens, a max- prefix such as max-md: targets “below”, and md:max-lg: targets a range. Breakpoints are added or changed with --breakpoint-\* in @theme. Designing mobile first keeps only what small screens need, which tends to simplify things.</sub> |

| **위치 지정**<br><sub>Positioning</sub> | relative 부모 안에서 absolute top-2 right-2로 배지를, inset-0으로 오버레이를 놓아요. sticky top-0은 스크롤해도 붙는 헤더예요.<br><sub>Inside a relative parent, absolute top-2 right-2 places a badge and inset-0 an overlay, while sticky top-0 makes a header that stays while scrolling.</sub> | absolute 요소는 position이 있는 가장 가까운 조상을 기준으로 놓이므로 부모에 relative를 줘요. top-2 right-2처럼 간격 스케일로 위치를 정하고, inset-0은 네 변을 모두 0으로 해 부모를 꽉 덮어요. sticky top-0은 스크롤하다 위에 닿으면 붙는 헤더를 만들고, fixed는 화면 기준이라 떠 있는 버튼에 써요. 겹치는 순서는 z-10, z-50 같은 z-index 유틸리티로 정해요. sticky가 동작하지 않으면 조상에 overflow:hidden이 있는지 먼저 확인해요. v4.2부터 inset-s-\*, inset-e-\* 같은 논리 방향 인셋도 있어요.<br><sub>An absolute element is placed against its nearest positioned ancestor, so the parent gets relative. ## v4 설정과 확장 · Configuring and extending v4

CSS 한 줄로 시작하는 설치, @theme 토큰, 캐스케이드 레이어, @utility와 @custom-variant, Preflight, 플러그인, 그리고 v3에서 바뀐 점이에요.

| **v4 설치와 구조**<br><sub>Setting up v4</sub> | tailwindcss와 빌드 플러그인을 설치하고 CSS에 @import "tailwindcss" 한 줄을 쓰면 끝이에요. 설정 파일과 콘텐츠 경로 목록이 필요 없어요.<br><sub>Install tailwindcss and a build plugin, write @import "tailwindcss" in your CSS, and you are done, with no config file or content path list.</sub> | Vite 프로젝트는 @tailwindcss/vite, Next.js처럼 PostCSS를 쓰는 곳은 @tailwindcss/postcss, 빌드 도구가 없으면 @tailwindcss/cli를 써요(v4.2부터 @tailwindcss/webpack도 있어요). | **도구와 클래스 정렬**<br><sub>Tooling and class sorting</sub> | VS Code의 Tailwind CSS IntelliSense는 자동 완성·색 미리보기·충돌 경고를, prettier-plugin-tailwindcss는 클래스 순서를 자동으로 정렬해 줘요.<br><sub>Tailwind CSS IntelliSense for VS Code provides autocomplete, color previews and conflict warnings, and prettier-plugin-tailwindcss sorts classes automatically.</sub> | 클래스 순서가 사람마다 다르면 같은 요소도 읽기 어렵고, 코드 리뷰에서 무엇이 바뀌었는지 잘 보이지 않아요. Prettier 플러그인은 저장할 때 레이아웃, 박스, 색, 글자, 변형처럼 Tailwind가 CSS를 출력하는 순서에 맞춰 클래스를 정렬해요.
