## 오토마타와 형식 언어 · Automata and formal languages

입력을 읽고 받아들일지 정하는 추상 기계예요. 정규식, 파서, 상태 관리의 이론적 바탕이에요.  
*Abstract machines that read input and decide whether to accept it; the theory behind regex, parsers and state management.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **DFA (결정적 유한 오토마타)**<br><sub>DFA · Deterministic finite automaton</sub> | 유한 개의 상태와 "이 상태에서 이 글자를 읽으면 저 상태로" 규칙만으로 입력을 판정하는 기계예요. 기억은 현재 상태 하나뿐이에요.<br><sub>A machine with finitely many states and “in this state, on this symbol, go there” rules; its only memory is the current state.</sub> | 주문·결제 상태, UI 상태(XState), 프로토콜 처리, 토크나이저를 상태 기계로 설계하면 불가능한 전이를 원천 차단해요.<br><sub>Modelling order flows, UI state (XState), protocols or tokenizers as state machines rules out impossible transitions.</sub> |
| **NFA와 부분집합 구성**<br><sub>NFA · Subset construction</sub> | 한 입력에 여러 갈래로 동시에 갈 수 있는 오토마타예요. 어느 한 갈래라도 받아들이면 받아들여요. 항상 같은 일을 하는 DFA로 바꿀 수 있어요.<br><sub>An automaton that can follow several branches at once and accepts if any branch does; every NFA has an equivalent DFA.</sub> | 정규식 엔진은 정규식을 NFA로 만들고, 필요하면 DFA로 바꿔 빠르게 실행해요(RE2, Rust regex).<br><sub>Regex engines compile patterns to NFAs and often to DFAs for speed (RE2, Rust regex).</sub> |
| **정규 표현식**<br><sub>Regular expressions</sub> | 정규식은 유한 오토마타로 바뀌어 실행돼요. 반복, 선택, 생략으로 문자열 패턴을 표현해요.<br><sub>A regex compiles into a finite automaton and describes string patterns with repetition, choice and optional parts.</sub> | 백트래킹 엔진에서 (a+)+ 같은 패턴은 지수 시간이 걸려 서비스를 멈출 수 있어요(ReDoS). 사용자 입력엔 타임아웃이나 안전한 엔진을 쓰세요.<br><sub>In backtracking engines, patterns like (a+)+ can take exponential time and stall services (ReDoS); use timeouts or safe engines for user input.</sub> |
| **푸시다운 오토마타**<br><sub>Pushdown automaton</sub> | 유한 오토마타에 스택을 하나 더한 기계예요. 괄호 짝 맞추기처럼 중첩 구조를 판정할 수 있어요.<br><sub>A finite automaton plus a stack, which lets it recognise nested structures like balanced brackets.</sub> | 프로그래밍 언어의 중첩된 블록·괄호를 파서가 처리하는 원리예요. 정규식으로 중첩 구조를 완벽히 다룰 수 없는 이유이기도 해요.<br><sub>It is how parsers handle nested blocks and brackets, and why regexes can’t fully handle nesting.</sub> |
| **촘스키 위계**<br><sub>Chomsky hierarchy</sub> | 언어(문자열 집합)를 정규 ⊂ 문맥 자유 ⊂ 문맥 의존 ⊂ 재귀 열거로 나누고, 각각을 처리하는 기계가 정해져 있어요.<br><sub>Languages nest as regular ⊂ context-free ⊂ context-sensitive ⊂ recursively enumerable, each with a matching machine.</sub> | 토큰은 정규식, 문법은 문맥 자유 파서로 나눠 처리하는 컴파일러 구조가 여기서 나와요.<br><sub>Compilers split work accordingly: regexes for tokens, context-free parsers for grammar.</sub> |
| **문맥 자유 문법과 파스 트리**<br><sub>Context-free grammar · Parse tree</sub> | "E → E + T"처럼 기호를 다른 기호들로 바꾸는 규칙으로 언어를 정의하고, 문장을 이 규칙으로 펼친 나무가 파스 트리예요.<br><sub>Rules such as “E → E + T” define a language; expanding a sentence by those rules gives its parse tree.</sub> | 연산자 우선순위와 결합 방향이 문법 구조로 정해져요. JSON·SQL·프로그래밍 언어 파서와 ANTLR 같은 도구가 이걸 써요.<br><sub>Operator precedence and associativity fall out of the grammar. JSON, SQL and language parsers and tools like ANTLR use this.</sub> |
| **알파벳·문자열·언어**<br><sub>Alphabets, strings and languages</sub> | 계산 이론은 기호의 유한 집합(알파벳), 그 기호로 만든 문자열, 문자열의 집합(언어)에서 시작해요.<br><sub>The theory starts from a finite set of symbols (an alphabet), strings over it, and sets of strings (languages).</sub> | Σ\*는 빈 문자열 ε를 포함해 Σ로 만들 수 있는 모든 문자열이고, 언어는 그 부분집합이에요. 언어끼리는 이어 붙이기(·), 합집합(∪), 클리니 스타(\*)로 새 언어를 만들어요. “입력이 언어 L에 속하는가?”라는 형태로 모든 결정 문제를 표현할 수 있어서, 어떤 기계가 어떤 언어를 인식하는지가 이론 전체의 뼈대가 돼요.<br><sub>Σ\* contains every string over Σ, including the empty string ε, and a language is any subset of it. Languages combine by concatenation (·), union (∪) and the Kleene star (\*). Every decision problem can be phrased as “is the input in language L?”, so which machines recognize which languages is the backbone of the whole theory.</sub> |
| **DFA 최소화**<br><sub>DFA minimization</sub> | 같은 언어를 받는 DFA 중 상태가 가장 적은 것을 찾아요. 구별할 수 없는 상태들을 하나로 합쳐요.<br><sub>Find the DFA with the fewest states for a language by merging states that can’t be told apart.</sub> | 먼저 수락·비수락 상태로 나누고, 같은 그룹 안에서 어떤 입력에 대해 서로 다른 그룹으로 가는 상태를 쪼개는 일을 더 쪼갤 게 없을 때까지 반복해요(분할 정제). 마지막에 같은 그룹의 상태를 하나로 합치면 최소 DFA예요. 마이힐–네로드 정리에 따라 최소 DFA는 이름만 빼고 유일하고, 홉크로프트 알고리즘은 O(n log n)에 만들어요.<br><sub>Split accepting from non-accepting states, then keep splitting any group whose members move to different groups on some symbol until nothing changes (partition refinement). Merging each final group gives the minimal DFA. By the Myhill–Nerode theorem it is unique up to renaming, and Hopcroft’s algorithm builds it in O(n log n).</sub> |
| **펌핑 보조정리**<br><sub>The pumping lemma</sub> | 어떤 언어가 정규 언어가 아님을 보이는 도구예요. 긴 문자열을 읽다 보면 상태가 반복되고, 그 고리를 늘려도 수락돼야 해요.<br><sub>A tool for proving a language is not regular: reading a long string must repeat a state, and pumping that loop must still be accepted.</sub> | 상태 p개인 DFA가 길이 p 이상의 문자열을 읽으면 비둘기집 원리로 어떤 상태가 반복돼요. 그래서 s = xyz (\|xy\| ≤ p, \|y\| ≥ 1)로 나눌 수 있고 모든 i에 대해 xyⁱz도 수락돼야 해요. aⁿbⁿ에서 y를 늘리면 a만 많아져 L을 벗어나므로 모순이에요. 정규 언어는 유한한 기억만 가져 개수를 셀 수 없다는 뜻이에요.<br><sub>When a p-state DFA reads a string of length at least p, some state repeats by the pigeonhole principle. So s = xyz with \|xy\| ≤ p and \|y\| ≥ 1, and xyⁱz must be accepted for every i. For aⁿbⁿ, pumping y adds only a’s and leaves the language: a contradiction. Regular languages have finite memory and cannot count.</sub> |
| **닫힘 성질과 곱 구성**<br><sub>Closure and the product construction</sub> | 정규 언어끼리 합치고, 겹치고, 뒤집어도 여전히 정규 언어예요. 두 DFA를 쌍으로 묶어 동시에 돌리면 돼요.<br><sub>Combining, intersecting or complementing regular languages yields regular languages; just run two DFAs in lockstep as pairs.</sub> | 곱 구성은 상태를 (M₁ 상태, M₂ 상태) 쌍으로 만들고 두 기계를 한 칸씩 함께 움직여요. 둘 다 수락하는 쌍만 수락하면 교집합, 하나라도 수락하면 합집합이에요. 여집합은 DFA의 수락 상태를 뒤집으면 되고, 이어 붙이기와 스타는 NFA로 보여요. 이 성질 덕분에 여러 패턴 조건을 하나의 오토마타로 합쳐 한 번에 검사해요.<br><sub>The product construction uses pairs (M₁ state, M₂ state) as states and moves both machines together. Accepting when both accept gives the intersection; when either accepts, the union. Complement flips a DFA’s accepting states, while concatenation and star follow from NFAs. These properties let many pattern rules merge into one automaton checked in a single pass.</sub> |
| **정규식 → NFA (톰슨 구성)**<br><sub>Regex to NFA (Thompson)</sub> | 정규식을 기호·선택·반복·이어 붙이기 조각으로 나눠, ε 전이로 이어 붙여 NFA를 만들어요.<br><sub>Break a regex into symbol, union, star and concatenation pieces, then glue them with ε-transitions into an NFA.</sub> | 기호 하나는 상태 두 개와 화살표 하나, 선택 a\|b는 ε로 갈라졌다 다시 합치는 조각, 반복 \*은 되돌아가는 ε와 건너뛰는 ε를 더한 조각이에요. 상태 수가 정규식 길이에 비례해서 빠르게 만들 수 있고, 이후 부분집합 구성으로 DFA로 바꾸거나 NFA를 그대로 시뮬레이션해요. grep, lex, RE2가 이 원리를 써요. 역참조(\1) 같은 기능은 정규 언어를 벗어나 백트래킹이 필요해요.<br><sub>A symbol is two states and an arrow; a\|b branches out with ε-edges and joins again; \* adds an ε back-edge and an ε skip. The state count grows linearly with the regex, so construction is fast; the NFA is then simulated directly or turned into a DFA by the subset construction. grep, lex and RE2 work this way. Features such as backreferences (\1) go beyond regular languages and need backtracking.</sub> |
| **무어 기계와 밀리 기계**<br><sub>Moore and Mealy machines</sub> | 입력을 받아 출력을 내는 유한 상태 기계예요. 무어는 상태에, 밀리는 전이에 출력이 붙어요.<br><sub>Finite-state machines that turn inputs into outputs: Moore machines attach outputs to states, Mealy machines to transitions.</sub> | 신호등처럼 지금 상태가 곧 출력인 것은 무어 기계, 자판기처럼 “500원 투입 / 음료 출력”처럼 전이마다 출력이 나오는 것은 밀리 기계예요. 둘은 표현력이 같고, 밀리 기계가 상태 수가 적고 반응이 한 박자 빨라요. 디지털 회로의 제어기, 통신 프로토콜, 게임 AI, XState 같은 UI 상태 관리에 그대로 쓰여요.<br><sub>A traffic light, whose state is its output, is a Moore machine; a vending machine that emits “drink” on the transition “insert 500” is a Mealy machine. They are equally expressive, but Mealy machines need fewer states and react one step sooner. They model circuit controllers, communication protocols, game AI and UI state machines such as XState.</sub> |
| **모호한 문법**<br><sub>Ambiguous grammars</sub> | 한 문자열에 파스 트리가 둘 이상 나오는 문법이에요. 1 + 2 \* 3이 9도 되고 7도 될 수 있어요.<br><sub>A grammar that gives a string more than one parse tree, so 1 + 2 \* 3 can mean 9 or 7.</sub> | E → E + E \| E \* E \| num은 덧셈과 곱셈 중 무엇을 먼저 묶을지 정하지 않아 모호해요. 우선순위마다 비단말을 나눠 E → E + T, T → T \* F처럼 쓰면 트리가 하나뿐이 돼요. if-else가 어느 if에 붙는지 정하는 dangling else 문제도 같은 종류예요. yacc·bison 같은 파서 생성기는 %left, %right 우선순위 선언으로 모호성을 풀어요.<br><sub>E → E + E \| E \* E \| num never says which operator binds first, so it is ambiguous. Introducing a nonterminal per precedence level (E → E + T, T → T \* F) leaves exactly one tree. The dangling-else problem, deciding which if an else belongs to, is the same kind. Parser generators such as yacc and bison resolve ambiguity with %left and %right precedence declarations.</sub> |
| **CYK 알고리즘**<br><sub>The CYK algorithm</sub> | 촘스키 정규형 문법으로 문자열을 만들 수 있는지, 짧은 부분 문자열부터 표를 채우며 판정하는 동적 계획법이에요.<br><sub>Dynamic programming that decides whether a Chomsky-normal-form grammar generates a string, filling a table from short substrings up.</sub> | 표의 각 칸에는 그 부분 문자열을 만들 수 있는 비단말을 적어요. 길이 1은 A → a 규칙으로, 길이가 길어지면 모든 자르는 위치에서 아래 칸 두 개를 A → BC 규칙으로 조합해요. 전체 문자열 칸에 시작 기호 S가 있으면 수락이에요. O(n³·\|G\|)으로 모든 문맥 자유 언어를 판정하고, 확률 버전(PCFG)은 자연어의 가장 그럴듯한 구문을 찾아요.<br><sub>Each cell holds the nonterminals that derive its substring. Length-1 cells come from rules A → a; longer cells combine two lower cells at every split point via rules A → BC. If the start symbol S appears in the full-string cell, the string is accepted. It decides any context-free language in O(n³·\|G\|), and its probabilistic version (PCFG) finds the most likely parse of a sentence.</sub> |

## 계산 가능성 · Computability

컴퓨터가 원리적으로 풀 수 있는 것과 없는 것의 경계예요.  
*The line between what computers can and can’t solve in principle.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **튜링 기계**<br><sub>Turing machine</sub> | 무한한 테이프, 읽고 쓰는 헤드, 상태 규칙만으로 된 가상의 기계예요. 계산 가능한 모든 것을 할 수 있다고 여겨져요.<br><sub>An imaginary machine with an infinite tape, a read/write head and state rules, believed able to compute anything computable.</sub> | 어떤 언어가 "튜링 완전"하다는 건 이 기계만큼 계산할 수 있다는 뜻이에요. 엑셀 수식, CSS+HTML, 마인크래프트 회로도 튜링 완전해요.<br><sub>“Turing complete” means as powerful as this machine; even spreadsheet formulas and Minecraft redstone qualify.</sub> |
| **정지 문제**<br><sub>Halting problem</sub> | 임의의 프로그램이 멈출지 무한히 돌지 항상 정확히 판정하는 프로그램은 존재할 수 없어요. 자기 자신을 넣으면 모순이 생기거든요.<br><sub>No program can always correctly decide whether an arbitrary program halts; feeding it to itself produces a contradiction.</sub> | 완벽한 무한 루프 탐지기나 모든 버그를 찾는 정적 분석기가 불가능한 이유예요. 실제 도구는 근사와 타임아웃으로 타협해요.<br><sub>It is why perfect infinite-loop detectors or bug finders can’t exist; real tools settle for approximations and timeouts.</sub> |
| **범용 튜링 기계**<br><sub>Universal Turing machine</sub> | 다른 튜링 기계의 설명 ⟨M⟩과 입력 w를 받아 M이 w에서 하는 일을 그대로 흉내 내는 기계예요. 프로그램도 데이터라는 뜻이에요.<br><sub>A machine that takes a description ⟨M⟩ of another Turing machine plus an input w and simulates M on w: programs are data.</sub> | 튜링 기계는 규칙표 하나로 정해지고, 규칙표는 0과 1의 문자열로 적을 수 있어요. 범용 기계 U는 테이프의 ⟨M⟩에서 지금 상태·기호에 맞는 규칙을 찾아 w 쪽에 적용하기를 반복해요. 이것이 프로그램을 메모리에 넣고 실행하는 폰 노이만 컴퓨터의 이론적 원형이에요. 처치–튜링 논제는 “알고리즘으로 계산할 수 있는 것 = 튜링 기계로 계산할 수 있는 것”이라고 말해요.<br><sub>A Turing machine is fully described by its rule table, which can be written as a string of 0s and 1s. The universal machine U repeatedly looks up the matching rule in ⟨M⟩ and applies it to w. This is the theoretical blueprint for stored-program (von Neumann) computers. The Church–Turing thesis states that whatever an algorithm can compute, a Turing machine can.</sub> |
| **대각선 논법**<br><sub>The diagonal argument</sub> | 목록을 다 만들었다고 가정하고, 대각선을 뒤집어 목록에 없는 원소를 만들어 내는 증명 기법이에요.<br><sub>Assume a complete list exists, then flip the diagonal to build an element that cannot be on it.</sub> | 무한 0/1 수열을 한 줄씩 다 나열했다고 가정하고, i번째 줄의 i번째 숫자를 모두 뒤집은 수열 d를 만들면 d는 어느 줄과도 한 자리 이상 달라요. 그래서 실수는 자연수보다 많고(칸토어), 프로그램(유한 문자열)은 셀 수 있지만 언어는 셀 수 없어 인식 불가능한 언어가 반드시 존재해요. 정지 문제의 결정 불가능성 증명도 같은 생각이에요.<br><sub>List every infinite 0/1 sequence, one per row, and build d by flipping digit i of row i: d differs from every row somewhere. Hence the reals outnumber the naturals (Cantor), and since programs are countable finite strings while languages are uncountable, some languages cannot be recognized by any program. The undecidability of the halting problem uses the same idea.</sub> |
| **환원**<br><sub>Reductions</sub> | 문제 A의 입력을 문제 B의 입력으로 바꾸는 계산 f가 있으면, B의 해법으로 A를 풀 수 있어요 (A ≤ B).<br><sub>If a computable f turns instances of A into instances of B, a solver for B solves A (A ≤ B).</sub> | “x ∈ A ⇔ f(x) ∈ B”인 f가 있으면 B가 풀리면 A도 풀리고, 거꾸로 A가 불가능하면 B도 불가능해요. 예를 들어 “M(w)를 실행한 뒤 hello를 출력”하는 프로그램을 만들면, hello 출력 여부를 판정하는 문제가 정지 문제만큼 어려워져 결정 불가능해요. f를 다항 시간으로 제한하면 같은 방식으로 NP-완전성을 증명해요.<br><sub>With x ∈ A ⇔ f(x) ∈ B, solving B solves A, and conversely if A is impossible so is B. For example, the program “run M on w, then print hello” prints hello exactly when M halts on w, so deciding whether a program prints hello is as hard as halting: undecidable. Restricting f to polynomial time gives the same technique for NP-completeness proofs.</sub> |
| **라이스 정리**<br><sub>Rice’s theorem</sub> | 프로그램이 “무엇을 하는가”에 관한 자명하지 않은 성질은 모두 결정 불가능하다는 정리예요.<br><sub>Every nontrivial property of what a program does is undecidable.</sub> | “빈 문자열을 받는가?”, “항상 멈추는가?”, “두 함수가 같은 일을 하는가?”, “바이러스인가?”처럼 프로그램의 동작(인식하는 언어)에 관한 성질은, 그 성질을 가진 프로그램과 안 가진 프로그램이 모두 있는 한 완벽히 판정할 수 없어요. 반면 “100줄이 넘나?” 같은 코드 모양(문법적 성질)은 판정할 수 있어요. 그래서 정적 분석기와 백신은 미탐과 오탐 사이에서 근사해요.<br><sub>Questions about behavior, the language a program recognizes, such as “accepts the empty string?”, “always halts?”, “do two functions compute the same thing?” or “is it a virus?”, can’t be decided perfectly whenever some programs have the property and others don’t. Syntactic questions like “is it over 100 lines?” remain decidable. Static analyzers and antivirus tools therefore approximate, trading missed cases against false alarms.</sub> |
| **결정 가능과 인식 가능**<br><sub>Decidable vs recognizable</sub> | 항상 멈추며 예·아니오를 내면 결정 가능, “예”일 때만 멈춤이 보장되면 인식 가능이에요. 언어들은 겹겹의 계층을 이뤄요.<br><sub>Decidable means a machine always halts with yes or no; recognizable only guarantees halting on yes. Languages form nested classes.</sub> | 정규(a\*b\*) ⊂ 문맥 자유(aⁿbⁿ) ⊂ 결정 가능(aⁿbⁿcⁿ) ⊂ 인식 가능(정지 문제 HALT) ⊂ 모든 언어 순으로 진부분집합이에요. 결정 가능 = 인식 가능이면서 여집합도 인식 가능한 언어예요. HALT는 인식 가능하지만 결정 불가능하고, HALT의 여집합은 인식조차 못 해요. 세상 대부분의 언어는 이 바깥에 있어요.<br><sub>Regular (a\*b\*) ⊂ context-free (aⁿbⁿ) ⊂ decidable (aⁿbⁿcⁿ) ⊂ recognizable (the halting language HALT) ⊂ all languages, each inclusion strict. A language is decidable exactly when it and its complement are both recognizable. HALT is recognizable but undecidable, and its complement is not even recognizable. Most languages lie beyond all of these.</sub> |
| **람다 계산**<br><sub>Lambda calculus</sub> | 변수, 함수 만들기(λx. M), 함수 적용(M N) 세 가지만으로 된 계산 모델이에요. 튜링 기계와 같은 힘을 가져요.<br><sub>A model of computation with only variables, function definitions (λx. M) and application (M N), as powerful as Turing machines.</sub> | 계산은 인자를 함수 몸통에 대입하는 베타 축약의 반복이에요: (λx. x × x) 3 → 3 × 3 → 9. 여러 인자는 함수를 돌려주는 함수로 받고(커링), 숫자(처치 수), 참·거짓, 재귀(Y 조합자)까지 모두 함수로 만들 수 있어요. 처치가 1936년에 제안했고, Lisp·Haskell 같은 함수형 언어와 화살표 함수·클로저의 뿌리예요.<br><sub>Computation is repeated beta reduction, substituting arguments into bodies: (λx. x × x) 3 → 3 × 3 → 9. Multiple arguments come one at a time (currying), and numbers (Church numerals), booleans and recursion (the Y combinator) are all encoded as functions. Church introduced it in 1936; it is the root of functional languages such as Lisp and Haskell, and of arrow functions and closures.</sub> |

## 계산 복잡도 · Computational complexity

문제를 풀 수 있는지보다 얼마나 빨리 풀 수 있는지를 다뤄요.  
*Not whether a problem can be solved, but how fast.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **빅오 표기법**<br><sub>Big-O notation</sub> | 입력 크기 n이 커질 때 시간이나 메모리가 얼마나 빨리 늘어나는지를 가장 큰 항으로 나타내요.<br><sub>Describes how fast time or memory grows with input size n, keeping only the dominant term.</sub> | n이 작으면 상수가 중요하지만, 데이터가 커지면 증가율이 모든 걸 결정해요. 10만 건에 O(n²)은 이미 위험해요.<br><sub>Constants matter for small n, but growth rate decides everything at scale; O(n²) on 100,000 items is already dangerous.</sub> |
| **P vs NP**<br><sub>P vs NP</sub> | P는 빨리 풀 수 있는 문제, NP는 답이 맞는지 빨리 확인할 수 있는 문제예요. 둘이 같은지는 아직 아무도 몰라요.<br><sub>P is problems solvable quickly; NP is problems whose answers can be checked quickly. Whether they are equal is unknown.</sub> | "NP-완전"이라는 말을 들으면 정확한 최적해 대신 근사·휴리스틱·제약 완화를 찾아야 한다는 신호예요.<br><sub>Hearing “NP-complete” is your cue to look for approximations, heuristics or relaxed constraints instead of exact optimums.</sub> |
| **외판원 문제와 근사**<br><sub>Travelling salesman · Heuristics</sub> | 모든 도시를 한 번씩 들르는 최단 경로를 찾는 NP-난해 문제예요. 경우의 수가 n!로 늘어서 큰 n은 정확히 풀 수 없어요.<br><sub>Finding the shortest route through every city is NP-hard; routes grow like n!, so large instances can’t be solved exactly.</sub> | 배달·물류·칩 배선은 그리디, 2-opt, 유전 알고리즘, OR-Tools 같은 솔버로 "충분히 좋은" 답을 찾아요.<br><sub>Delivery, logistics and chip wiring use greedy, 2-opt, genetic algorithms or solvers like OR-Tools for good-enough answers.</sub> |
| **NP-완전성**<br><sub>NP-completeness</sub> | NP 문제 중 가장 어려운 것들이에요. 하나라도 다항 시간에 풀리면 모든 NP 문제가 풀려요.<br><sub>The hardest problems in NP: if any one is solvable in polynomial time, every NP problem is.</sub> | NP는 답 후보를 다항 시간에 검증할 수 있는 문제, NP-hard는 모든 NP 문제가 다항 시간에 환원되는 문제, NP-완전은 둘 다인 문제예요. 쿡–레빈 정리(1971)로 SAT가 처음 NP-완전임이 증명됐고, 카프가 SAT에서 환원해 클리크, 정점 덮개, 해밀턴 회로, 3-색칠, 부분집합 합 등 21개를 보였어요. 실무에선 근사 알고리즘, 휴리스틱, SAT·ILP 솔버로 큰 사례를 풀어요.<br><sub>NP contains problems whose proposed answers can be verified in polynomial time; NP-hard problems are those every NP problem reduces to; NP-complete problems are both. The Cook–Levin theorem (1971) proved SAT NP-complete first, and Karp then reduced SAT to 21 problems including clique, vertex cover, Hamiltonian cycle, 3-coloring and subset sum. In practice, approximation, heuristics and SAT/ILP solvers handle large instances.</sub> |
| **SAT와 DPLL**<br><sub>SAT and DPLL</sub> | 논리식의 변수에 참·거짓을 정해 식 전체를 참으로 만들 수 있는지 묻는 문제예요. 첫 NP-완전 문제지만 실전에선 놀랍도록 잘 풀려요.<br><sub>Can true/false values be chosen so a logical formula becomes true? The first NP-complete problem, yet surprisingly tractable in practice.</sub> | DPLL은 변수 하나를 정하고, 문자가 하나 남은 절이 강제하는 값을 연쇄로 정한 뒤(단위 전파), 충돌하면 마지막 선택을 되돌리는 백트래킹이에요. 현대 CDCL 솔버는 충돌의 원인을 새 절로 배워 같은 실수를 반복하지 않아 변수 수백만 개짜리 문제도 풀어요. 칩 설계 검증, 패키지 의존성 해결(apt·conda), 일정 계획에 쓰여요.<br><sub>DPLL picks a variable, propagates values forced by clauses with one free literal (unit propagation), and backtracks on conflicts. Modern CDCL solvers learn a new clause from each conflict so they never repeat the mistake, solving instances with millions of variables. They power chip verification, package dependency resolution (apt, conda) and scheduling.</sub> |
| **다항 시간 환원의 예**<br><sub>A polynomial-time reduction</sub> | 독립 집합, 정점 덮개, 클리크는 간단한 변환으로 서로 바뀌어요. 하나를 풀면 셋 다 풀려요.<br><sub>Independent set, vertex cover and clique transform into each other with simple changes; solve one and you solve all three.</sub> | 크기 k인 독립 집합(서로 이웃이 아닌 정점들)의 나머지는 크기 n−k인 정점 덮개(모든 간선의 한쪽 끝을 포함)이고, 간선을 뒤집은 여집합 그래프에서는 크기 k인 클리크가 돼요. 이런 다항 시간 변환으로 NP-완전 문제들이 서로 연결돼 있어요. 정점 덮개는 극대 매칭을 이용해 최적의 2배 이내로 근사할 수 있어요.<br><sub>The complement of an independent set of size k (no two vertices adjacent) is a vertex cover of size n−k (touching every edge), and in the complement graph the same set is a clique of size k. Such polynomial-time transformations tie NP-complete problems together. Vertex cover also has a 2-approximation using a maximal matching.</sub> |
| **시간·공간 복잡도 클래스**<br><sub>Time and space complexity classes</sub> | 문제를 필요한 시간과 메모리로 분류하면 L ⊆ P ⊆ NP ⊆ PSPACE ⊆ EXPTIME의 계층이 생겨요.<br><sub>Classifying problems by the time and memory they need gives the hierarchy L ⊆ P ⊆ NP ⊆ PSPACE ⊆ EXPTIME.</sub> | L은 로그 크기 메모리, P는 다항 시간, NP는 다항 시간 검증, PSPACE는 다항 크기 메모리, EXPTIME은 지수 시간으로 풀리는 문제예요. 양화 논리식(QBF)과 일반화한 게임은 PSPACE-완전, 일반화한 체스는 EXPTIME-완전이에요. 공간은 다시 쓸 수 있어 시간보다 강력하고(사비치: NPSPACE = PSPACE), P ≠ EXPTIME은 증명됐지만 나머지 포함 관계는 대부분 미해결이에요.<br><sub>L uses logarithmic memory, P polynomial time, NP polynomial-time verification, PSPACE polynomial memory and EXPTIME exponential time. Quantified Boolean formulas (QBF) and generalized games are PSPACE-complete; generalized chess is EXPTIME-complete. Space can be reused, making it more powerful than time (Savitch: NPSPACE = PSPACE). P ≠ EXPTIME is proven, but most other separations remain open.</sub> |
| **확률적 알고리즘**<br><sub>Randomized algorithms</sub> | 무작위성을 써서 아주 작은 오류 확률을 받아들이는 대신 훨씬 빠르게 푸는 알고리즘이에요.<br><sub>Algorithms that use randomness and accept a tiny chance of error in exchange for far greater speed.</sub> | 밀러–라빈 소수 판정은 무작위 밑을 골라 시험하는데, 합성수라면 밑의 3/4 이상이 증거가 되어 한 번에 놓칠 확률이 1/4 이하예요. k번 반복하면 오류 확률이 (1/4)ᵏ로 줄어 RSA 키 생성에 쓰여요(몬테카를로). 답은 항상 정확하고 시간만 무작위인 것은 라스베이거스 알고리즘으로, 무작위 피벗 퀵정렬이 예예요. 이런 알고리즘으로 풀리는 문제의 클래스가 BPP예요.<br><sub>Miller–Rabin primality testing picks a random base; for a composite number at least 3/4 of bases are witnesses, so one round misses with probability at most 1/4, and k rounds drive the error to (1/4)ᵏ. It is used for RSA key generation (a Monte Carlo algorithm). Las Vegas algorithms are always correct with random running time, like random-pivot quicksort. Problems solvable this way form the class BPP.</sub> |
