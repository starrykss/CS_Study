## 암호가 지켜야 할 것 · What a cipher must guarantee

커크호프스 원칙, 시저·비즈네르 암호가 깨진 이유, 일회용 패드의 완전 비밀성, 그리고 “안전하다”를 정확히 정의하는 IND-CPA 게임까지, 현대 암호를 이해하는 출발점이에요.  
*Kerckhoffs’s principle, why the Caesar and Vigenère ciphers fell, the perfect secrecy of the one-time pad, and the IND-CPA game that pins down what “secure” means: the starting point for modern cryptography.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **커크호프스 원칙**<br><sub>Kerckhoffs’s principle</sub> | 알고리즘은 공개되어도 괜찮고 비밀은 키에만 있어야 한다는 원칙이에요. 현대 암호 설계의 첫 번째 규칙이에요.<br><sub>The algorithm may be public; the secret must live only in the key. It is the first rule of modern cipher design.</sub> | 1883년 오귀스트 커크호프스는 암호 시스템이 적의 손에 들어가도 안전해야 한다고 썼어요. 공격자가 알고리즘, 구현, 암호문을 모두 알아도 키만 모르면 평문을 알아낼 수 없어야 한다는 뜻이에요. 그래서 안전성은 키 공간의 크기와 알고리즘의 수학적 성질로 따지고, 128비트 키라면 전수 조사에 평균 2¹²⁷번 시도가 필요해요. 알고리즘을 숨기는 방식은 역공학이나 유출 한 번에 모든 사용자가 깨지고, 고치려면 시스템 전체를 바꿔야 해요. 반대로 AES, ChaCha20처럼 공개 경쟁과 수년의 분석을 거친 표준은 많은 연구자가 검증했기 때문에 신뢰받아요.<br><sub>In 1883 Auguste Kerckhoffs wrote that a cipher must remain secure even if it falls into enemy hands. An attacker who knows the algorithm, the implementation and the ciphertext should still learn nothing without the key. Security is therefore measured by key space and mathematical structure; a 128-bit key needs about 2¹²⁷ guesses on average. Hiding the algorithm fails for every user at once after a single leak or reverse-engineering effort, and fixing it means replacing the whole system. Public standards like AES and ChaCha20, chosen through open competitions and years of analysis, earn trust because many researchers have tried to break them.</sub> |
| **시저 암호와 빈도 분석**<br><sub>Caesar cipher and frequency analysis</sub> | 모든 글자를 같은 칸 수만큼 미는 가장 오래된 암호예요. 키가 26개뿐이고 글자 빈도가 그대로 남아서 쉽게 깨져요.<br><sub>The oldest cipher shifts every letter by the same amount. With only 26 keys and letter frequencies left intact, it breaks easily.</sub> | 시저 암호는 알파벳을 k칸 밀어 HELLO를 k = 3일 때 KHOOR로 바꿔요. 키가 26가지뿐이라 전부 시도해도 순식간이에요. 글자를 임의로 섞는 단일 치환 암호는 키가 26!개로 늘어나지만, 같은 글자가 늘 같은 글자로 바뀌기 때문에 영어의 E, T, A처럼 흔한 글자의 빈도가 암호문에 그대로 남아요. 9세기 알킨디가 정리한 빈도 분석은 가장 많이 나온 글자를 E에 맞추고, 짧은 단어와 글자 쌍으로 나머지를 채워 풀어요. 키 공간이 커도 통계적 구조가 남으면 깨진다는 첫 교훈이에요.<br><sub>The Caesar cipher shifts the alphabet by k, turning HELLO into KHOOR for k = 3. With only 26 keys, trying them all is instant. A general substitution cipher raises the key count to 26!, but the same letter still maps to the same letter, so the frequencies of common English letters such as E, T and A survive in the ciphertext. Frequency analysis, described by al-Kindi in the ninth century, matches the most common symbol to E and fills in the rest from short words and letter pairs. It is the first lesson that a large key space is useless if statistical structure leaks through.</sub> |
| **비즈네르 암호**<br><sub>Vigenère cipher</sub> | 반복되는 키로 글자마다 다른 칸 수를 밀어요. 키가 반복되는 주기가 드러나면 시저 암호 여러 개로 쪼개져 풀려요.<br><sub>A repeating key shifts each letter by a different amount. Once the period shows, it splits into several Caesar ciphers.</sub> | 비즈네르 암호는 키 KEY를 평문 길이만큼 반복하고, 글자마다 키 글자만큼 밀어요. ATTACKATDAWN은 KXRKGIKXBKAL이 돼서 같은 A도 위치에 따라 K, K, K처럼 나오거나 다른 글자가 돼요. 하지만 키가 주기적으로 반복되니 같은 평문 조각이 같은 키 위치에 오면 같은 암호문이 나와요. 카시스키 검사는 반복되는 조각 사이의 거리로, 일치 지수는 통계로 키 길이를 찾아요. 키 길이 n을 알면 n칸씩 건너뛴 글자들은 모두 같은 키로 민 시저 암호라서 열마다 빈도 분석으로 풀려요.<br><sub>Vigenère repeats the key KEY across the message and shifts each letter by the matching key letter, turning ATTACKATDAWN into KXRKGIKXBKAL. Identical plaintext letters no longer always look alike, but the key repeats, so the same fragment at the same key offset encrypts the same way. The Kasiski test measures distances between repeated fragments, and the index of coincidence estimates the key length statistically. Once the length n is known, every n-th letter was shifted by the same key letter, so each column is a Caesar cipher solved by frequency analysis.</sub> |
| **일회용 패드**<br><sub>One-time pad</sub> | 평문만큼 긴 진짜 무작위 키를 한 번만 XOR하면 이론적으로 깨지지 않아요. 키를 재사용하면 바로 무너져요.<br><sub>XOR with a truly random key as long as the message, used once, is provably unbreakable. Reusing the key breaks it at once.</sub> | 일회용 패드는 메시지와 같은 길이의 무작위 키를 비트마다 XOR해요. 받는 쪽은 같은 키로 한 번 더 XOR해서 평문을 얻어요. 섀넌은 키가 균등하게 무작위이고 평문만큼 길고 한 번만 쓰이면, 암호문이 평문에 대해 아무 정보도 주지 않는다는 완전 비밀성을 증명했어요. 어떤 평문이든 알맞은 키가 하나씩 있어서 공격자는 전혀 좁힐 수 없어요. 다만 키를 두 번 쓰면 c₁ ⊕ c₂ = m₁ ⊕ m₂가 되어 키가 사라지고, 언어의 통계로 두 평문을 풀 수 있어요. 키 배송이 어려워 외교·군사 핫라인 정도에만 쓰였고, 현대 스트림 암호는 짧은 키로 키스트림을 만들어 이를 흉내 내요.<br><sub>The one-time pad XORs the message with a random key of equal length, and the receiver XORs again with the same key. Shannon proved that if the key is uniformly random, as long as the message and never reused, the ciphertext reveals nothing about the plaintext: every plaintext has exactly one key that produces it. Reusing a key gives c₁ ⊕ c₂ = m₁ ⊕ m₂, cancelling the key and letting language statistics separate the two messages, which is how the Venona project read Soviet traffic. Distributing that much key is so impractical that pads were used only for hotlines and diplomacy; stream ciphers imitate them with a keystream expanded from a short key.</sub> |
| **안전성의 정의 (IND-CPA)**<br><sub>Defining security (IND-CPA)</sub> | 공격자가 두 평문 중 어느 것이 암호화됐는지 맞히지 못하면 안전하다고 정의해요. 그래서 암호화는 매번 무작위여야 해요.<br><sub>A scheme is secure if an attacker cannot tell which of two plaintexts was encrypted, which forces encryption to be randomized.</sub> | 현대 암호는 “안전하다”를 게임으로 정의해요. 공격자는 원하는 평문을 마음껏 암호화해 볼 수 있고(선택 평문 공격), 길이가 같은 두 평문 m₀, m₁을 제출해요. 도전자는 몰래 비트 b를 골라 Enc(m\_b)만 돌려주고, 공격자가 b를 맞힐 확률이 ½보다 무시할 만큼만 높으면 IND-CPA 안전이에요. 같은 평문이 늘 같은 암호문이 되는 결정적 암호는 공격자가 Enc(m₀)를 직접 만들어 비교하면 바로 지니까, 암호화는 nonce나 IV로 매번 달라져야 해요. 복호화 질의까지 허용하는 IND-CCA는 더 강한 기준이고, 무결성까지 지키는 AEAD가 이를 만족해요.<br><sub>Modern cryptography defines security as a game. The attacker may encrypt any plaintexts it likes (a chosen-plaintext attack) and then submits two equal-length messages m₀ and m₁. The challenger secretly picks a bit b and returns only Enc(m\_b); if the attacker guesses b with probability only negligibly better than ½, the scheme is IND-CPA secure. A deterministic scheme loses immediately, because the attacker can compute Enc(m₀) itself and compare, so encryption must be randomized with a nonce or IV. IND-CCA, which also allows decryption queries, is a stronger notion that authenticated encryption achieves.</sub> |

## 정수론 도구 상자 · The number theory toolbox

모듈러 연산과 역원, 확장 유클리드 호제법, 페르마·오일러 정리, 빠른 거듭제곱, 그리고 이산 로그 문제까지, 공개키 암호를 떠받치는 정수론을 손으로 계산하듯 따라가요.  
*Modular arithmetic and inverses, the extended Euclidean algorithm, the theorems of Fermat and Euler, square-and-multiply exponentiation and the discrete log problem: the number theory under public-key cryptography, worked through by hand.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **모듈러 연산**<br><sub>Modular arithmetic</sub> | n으로 나눈 나머지만 보는 계산이에요. 덧셈, 곱셈, 역원이 모두 0부터 n − 1 안에서 이루어져요.<br><sub>Arithmetic on remainders after dividing by n. Addition, multiplication and inverses all stay between 0 and n − 1.</sub> | a mod n은 a를 n으로 나눈 나머지예요. 시계에서 9시에 5시간을 더하면 2시가 되듯 9 + 5 ≡ 2 (mod 12)예요. 덧셈, 뺄셈, 곱셈은 중간에 아무 때나 mod를 해도 결과가 같아서 큰 수도 작게 유지하며 계산할 수 있어요. a · b ≡ 1이 되는 b를 a의 역원이라 하고, mod 7에서 3 × 5 = 15 ≡ 1이라 3⁻¹ = 5예요. 역원은 gcd(a, n) = 1일 때만 있어서 mod 8에서 2는 역원이 없어요. n이 소수 p면 0이 아닌 모든 수에 역원이 있어 사칙연산이 다 되는 유한체가 되고, 디피-헬먼과 타원곡선 암호는 이런 유한체 위에서 계산해요.<br><sub>a mod n is the remainder when a is divided by n. Just as 5 hours after 9 o’clock is 2 o’clock, 9 + 5 ≡ 2 (mod 12). Addition, subtraction and multiplication can be reduced at any point without changing the result, so huge numbers stay small. A number b with a · b ≡ 1 is the inverse of a; mod 7, 3 × 5 = 15 ≡ 1, so 3⁻¹ = 5. An inverse exists only when gcd(a, n) = 1, so 2 has none mod 8. When n is a prime p, every nonzero element has an inverse and the numbers form a finite field, the setting for Diffie–Hellman and elliptic curve cryptography.</sub> |
| **확장 유클리드 호제법**<br><sub>Extended Euclidean algorithm</sub> | 나눗셈을 되풀이해 최대공약수를 구하고, 거꾸로 대입해 모듈러 역원까지 찾아요. RSA의 개인 지수가 이렇게 나와요.<br><sub>Repeated division finds the gcd, and substituting back yields the modular inverse. RSA’s private exponent comes from it.</sub> | 유클리드 호제법은 gcd(a, b) = gcd(b, a mod b)를 이용해 나머지가 0이 될 때까지 나눠요. 3120 = 183 · 17 + 9, 17 = 1 · 9 + 8, 9 = 1 · 8 + 1이라 gcd(3120, 17) = 1이에요. 확장 버전은 각 나눗셈 식을 거꾸로 대입해 ax + by = gcd(a, b)를 만족하는 x, y를 함께 구해요. 여기서는 17 · (−367) + 3120 · 2 = 1이라 mod 3120에서 17의 역원은 −367 + 3120 = 2753이에요. RSA에서 e = 17, φ(n) = 3120일 때 개인 지수 d = 2753이 바로 이 값이고, 계산량은 자릿수에 비례해서 수천 비트 수도 순식간이에요.<br><sub>Euclid’s algorithm uses gcd(a, b) = gcd(b, a mod b), dividing until the remainder is zero: 3120 = 183 · 17 + 9, 17 = 1 · 9 + 8, 9 = 1 · 8 + 1, so gcd(3120, 17) = 1. The extended version substitutes back through the divisions to find x and y with ax + by = gcd(a, b). Here 17 · (−367) + 3120 · 2 = 1, so the inverse of 17 mod 3120 is −367 + 3120 = 2753. That is exactly the private exponent d for an RSA key with e = 17 and φ(n) = 3120, and the work grows only with the number of digits, so thousand-bit numbers take microseconds.</sub> |
| **페르마·오일러 정리**<br><sub>Fermat’s and Euler’s theorems</sub> | 소수 p에 대해 aᵖ⁻¹ ≡ 1, 일반적으로 aᵠ⁽ⁿ⁾ ≡ 1이에요. RSA가 복호화되는 이유이자 소수 판정의 출발점이에요.<br><sub>For a prime p, aᵖ⁻¹ ≡ 1; in general aᵠ⁽ⁿ⁾ ≡ 1. It is why RSA decrypts correctly and where primality tests start.</sub> | 페르마의 소정리는 p가 소수이고 a가 p의 배수가 아니면 aᵖ⁻¹ ≡ 1 (mod p)이라고 말해요. mod 7에서 3을 거듭 곱하면 3, 2, 6, 4, 5, 1로 6번째에 1로 돌아와요. 오일러는 이를 일반화해 gcd(a, n) = 1이면 aᵠ⁽ⁿ⁾ ≡ 1이라고 했고, φ(n)은 n 이하에서 n과 서로소인 수의 개수로 φ(15) = 8이에요. RSA는 ed ≡ 1 (mod φ(n))이 되게 키를 골라 mᵉᵈ = m · (mᵠ⁽ⁿ⁾)ᵏ ≡ m이 되도록 해요. 거꾸로 2ⁿ⁻¹ mod n ≠ 1이면 n이 합성수라는 페르마 테스트가 되지만, 561처럼 모든 밑을 속이는 카마이클 수가 있어서 실제로는 밀러-라빈 판정을 여러 번 돌려요.<br><sub>Fermat’s little theorem says that for a prime p and a not divisible by p, aᵖ⁻¹ ≡ 1 (mod p). Mod 7, powers of 3 run 3, 2, 6, 4, 5, 1 and return to 1 on the sixth step. Euler generalized it: if gcd(a, n) = 1 then aᵠ⁽ⁿ⁾ ≡ 1, where φ(n) counts the numbers up to n that are coprime to n, so φ(15) = 8. RSA chooses keys with ed ≡ 1 (mod φ(n)), so mᵉᵈ = m · (mᵠ⁽ⁿ⁾)ᵏ ≡ m and decryption undoes encryption. Run in reverse it becomes the Fermat primality test, but Carmichael numbers such as 561 fool every base, so real code uses repeated Miller–Rabin rounds.</sub> |
| **빠른 거듭제곱**<br><sub>Square-and-multiply</sub> | 지수를 2진수로 보고 제곱과 곱셈을 반복해 거듭제곱을 계산해요. 비트 수에 비례하는 시간이라 큰 지수도 순식간이에요.<br><sub>Read the exponent in binary and alternate squaring with multiplying. The work grows with the bit length, so huge exponents are fast.</sub> | bᵉ mod n을 그대로 계산하면 e − 1번 곱해야 해서 2048비트 지수라면 끝나지 않아요. 빠른 거듭제곱은 e를 2진수로 쓰고 b, b², b⁴, b⁸…을 제곱으로 만든 다음, 비트가 1인 자리의 값만 곱해요. 65¹⁷ mod 3233은 17 = 10001₂라서 제곱 4번과 곱셈 1번, 65¹⁶ · 65 ≡ 789 · 65 ≡ 2790으로 끝나요. 매 단계 mod를 해서 수가 n보다 커지지 않고, 곱셈 횟수는 비트 수의 1.5배 정도예요. 다만 비트가 1일 때만 곱셈을 하면 실행 시간이나 전력 소모로 비트가 새어 나가서, 실제 구현은 몽고메리 래더처럼 비트와 관계없이 같은 일을 하는 상수 시간 방식을 써요.<br><sub>Computing bᵉ mod n by repeated multiplication takes e − 1 steps, hopeless for a 2048-bit exponent. Square-and-multiply writes e in binary, builds b, b², b⁴, b⁸ … by squaring, and multiplies together only the powers whose bit is 1. For 65¹⁷ mod 3233, 17 = 10001₂, so four squarings and one multiplication give 65¹⁶ · 65 ≡ 789 · 65 ≡ 2790. Reducing mod n at every step keeps numbers small, and the multiplication count is about 1.5 times the bit length. Multiplying only on 1 bits leaks the key through timing or power use, so production code uses constant-time methods like the Montgomery ladder.</sub> |
| **이산 로그 문제**<br><sub>The discrete log problem</sub> | gˣ mod p는 쉽게 계산되지만 결과에서 x를 되찾기는 매우 어려워요. 디피-헬먼, DSA, 타원곡선 암호의 바탕이에요.<br><sub>gˣ mod p is easy to compute but x is very hard to recover from the result. Diffie–Hellman, DSA and elliptic curves rest on it.</sub> | 소수 p와 생성원 g가 있을 때 gˣ mod p는 빠른 거듭제곱으로 금방 계산돼요. p = 23, g = 5면 5⁶ mod 23 = 8이에요. 그런데 x를 1씩 늘려도 결과는 1부터 22까지 규칙 없이 흩어져서, 8이라는 결과만 보고 x = 6을 찾으려면 사실상 하나씩 해 봐야 해요. 아기걸음 거인걸음이나 폴라드 로 같은 방법도 √p 정도의 시간이 들고, 일반 유한체에는 더 빠른 수체 체 방법이 있어 2048비트 이상의 p를 써요. 타원곡선 위의 이산 로그(ECDLP)는 알려진 지름길이 없어서 256비트 키로 128비트 안전성을 줘요. 양자 컴퓨터의 쇼어 알고리즘은 두 문제를 모두 효율적으로 풀기 때문에 양자내성 암호로의 전환이 진행 중이에요.<br><sub>For a prime p and generator g, gˣ mod p is fast to compute with square-and-multiply: with p = 23 and g = 5, 5⁶ mod 23 = 8. Yet as x increases the results scatter across 1 to 22 with no visible order, so recovering x = 6 from 8 essentially means searching. Baby-step giant-step and Pollard’s rho still need about √p work, and the number field sieve is faster for ordinary finite fields, which is why p is 2048 bits or more. The elliptic curve discrete log has no known shortcut, so a 256-bit curve gives 128-bit security. Shor’s quantum algorithm solves both problems efficiently, driving the migration to post-quantum cryptography.</sub> |

| **페이스텔 구조**<br><sub>Feistel network</sub> | 블록을 반으로 나눠 한쪽만 섞고 교환하기를 반복해요. 라운드 함수가 역함수를 갖지 않아도 복호화할 수 있어요.<br><sub>Split the block in half, mix one side and swap, round after round. Decryption works even when the round function has no inverse.</sub> | 페이스텔 구조는 블록을 왼쪽 L과 오른쪽 R로 나누고, 매 라운드 L₁ = R₀, R₁ = L₀ ⊕ F(R₀, k₁)로 바꿔요. 복호화는 같은 연산을 라운드 키 순서만 거꾸로 해서 하는데, F의 출력을 한 번 더 XOR하면 지워지기 때문에 F 자체는 되돌릴 수 없어도 괜찮아요. 그래서 설계자는 F를 마음껏 복잡하게 만들 수 있고, 암호화와 복호화 회로도 하나로 공유돼요. 1977년 표준인 DES가 64비트 블록에 16라운드 페이스텔 구조였지만 56비트 키가 너무 짧아 1998년 EFF의 전용 장비가 56시간 만에 키를 찾았어요. 3DES로 버티다가 AES로 넘어갔고, 페이스텔 구조는 Blowfish, Camellia 등에 남아 있어요.<br><sub>A Feistel network splits the block into halves L and R and, each round, sets L₁ = R₀ and R₁ = L₀ ⊕ F(R₀, k₁). Triple DES bridged the gap until AES, and the Feistel design lives on in Blowfish and Camellia.</sub> |
| **AES 라운드**<br><sub>AES rounds</sub> | 16바이트 상태에 SubBytes, ShiftRows, MixColumns, AddRoundKey를 10~14라운드 반복해요. 오늘날 가장 많이 쓰는 블록 암호예요.<br><sub>A 16-byte state goes through SubBytes, ShiftRows, MixColumns and AddRoundKey for 10 to 14 rounds. It is the most widely used block cipher today.</sub> | AES는 2001년 표준이 된 128비트 블록 암호로, 16바이트를 4×4 상태에 놓고 라운드마다 네 단계를 거쳐요. SubBytes는 GF(2⁸)의 역원과 아핀 변환으로 만든 S-box로 바이트를 치환하는 유일한 비선형 단계예요. ShiftRows는 행 i를 왼쪽으로 i칸 돌려 바이트를 다른 열로 보내고, MixColumns는 열마다 고정 행렬을 곱해 한 바이트의 변화를 열 전체로 퍼뜨려요. 마지막으로 AddRoundKey가 키 확장으로 만든 라운드 키를 XOR해요. 두 라운드면 모든 출력 비트가 모든 입력 비트에 의존하게 되고, 키 길이 128, 192, 256비트에 따라 10, 12, 14라운드를 돌려요. 대부분의 CPU에는 AES-NI 같은 전용 명령이 있어 한 라운드가 명령 하나로 처리돼요.<br><sub>AES, standardized in 2001, is a 128-bit block cipher that arranges 16 bytes in a 4×4 state and applies four steps each round. SubBytes swaps each byte through an S-box built from inversion in GF(2⁸) plus an affine map, the only nonlinear step. ShiftRows rotates row i left by i so bytes move between columns, and MixColumns multiplies each column by a fixed matrix so a change in one byte spreads through the whole column. AddRoundKey then XORs in a round key from the key schedule. After two rounds every output bit depends on every input bit, and keys of 128, 192 and 256 bits use 10, 12 and 14 rounds. Most CPUs have instructions such as AES-NI that perform a whole round in one step.</sub> |
| **스트림 암호 ChaCha20**<br><sub>The ChaCha20 stream cipher</sub> | 키와 nonce, 카운터로 키스트림을 만들어 평문에 XOR해요. 더하기·회전·XOR만 써서 소프트웨어로도 빠르고 타이밍 공격에 강해요.<br><sub>Key, nonce and counter generate a keystream that is XORed with the plaintext. Using only add, rotate and XOR makes it fast in software and resistant to timing attacks.</sub> | ChaCha20은 상수 4워드, 256비트 키 8워드, 블록 카운터 1워드, 96비트 nonce 3워드로 4×4 상태를 채워요. 더하기, 비트 회전, XOR만 쓰는 쿼터 라운드를 열과 대각선에 번갈아 20라운드 적용하고, 원래 상태를 더해 64바이트 키스트림 블록을 얻어요. 평문과 XOR하면 암호문이 되고, 다음 블록은 카운터만 올리면 돼서 병렬 계산과 임의 위치 접근이 자유로워요. 표를 찾아보는 연산이 없어서 캐시 타이밍 공격에 강하고, AES 하드웨어 가속이 없는 휴대폰에서도 빨라요. Poly1305 MAC과 묶은 ChaCha20-Poly1305가 TLS 1.3, WireGuard, SSH에서 쓰여요.<br><sub>ChaCha20 fills a 4×4 state with four constant words, an eight-word 256-bit key, a one-word block counter and a three-word 96-bit nonce. It applies quarter rounds built from addition, rotation and XOR to columns and diagonals for 20 rounds, then adds the original state to get a 64-byte keystream block. XORing with the plaintext gives the ciphertext, and the next block just bumps the counter, allowing parallel computation and random access. With no table lookups it resists cache-timing attacks and runs fast even on phones without AES hardware. Paired with the Poly1305 MAC as ChaCha20-Poly1305, it is used in TLS 1.3, WireGuard and SSH.</sub> |
| **nonce 재사용**<br><sub>Nonce reuse</sub> | 같은 키와 nonce로 두 메시지를 암호화하면 키스트림이 같아져 평문끼리의 XOR이 드러나요. GCM에서는 위조까지 가능해져요.<br><sub>Encrypting two messages with the same key and nonce repeats the keystream and exposes the XOR of the plaintexts. With GCM it even enables forgeries.</sub> | CTR, GCM, ChaCha20 같은 스트림 계열 암호는 키와 nonce에서 키스트림을 만들기 때문에, 두 메시지에 같은 nonce를 쓰면 키스트림이 완전히 같아져요. 두 암호문을 XOR하면 키스트림이 지워져 c₁ ⊕ c₂ = m₁ ⊕ m₂가 되고, 한쪽 평문을 알거나 추측하면 다른 쪽도 그대로 풀려요. AES-GCM은 여기에 더해 인증용 해시 키 H가 계산되어 메시지를 위조할 수 있게 돼요. 무작위 96비트 nonce는 생일 문제 때문에 키 하나당 2³²개 메시지 정도까지만 안전하고, 그 이상은 카운터 nonce나 192비트 nonce를 쓰는 XChaCha20, 실수해도 덜 위험한 AES-GCM-SIV를 써요. 2017년 KRACK 공격은 WPA2 핸드셰이크를 재전송해 nonce를 강제로 재사용시켰어요.<br><sub>Stream-style ciphers such as CTR, GCM and ChaCha20 derive the keystream from key and nonce, so reusing a nonce makes two keystreams identical. XORing the ciphertexts cancels the keystream, leaving c₁ ⊕ c₂ = m₁ ⊕ m₂, and knowing or guessing one plaintext reveals the other. With AES-GCM the authentication hash key H can also be recovered, allowing forgeries. Random 96-bit nonces stay safe for only about 2³² messages per key because of the birthday bound; beyond that use counter nonces, XChaCha20 with 192-bit nonces, or misuse-resistant AES-GCM-SIV. The 2017 KRACK attack replayed WPA2 handshake messages to force nonce reuse.</sub> |
| **인증 암호 AEAD**<br><sub>Authenticated encryption (AEAD)</sub> | 암호화와 무결성 검사를 한 번에 해요. 헤더는 평문으로 두되 함께 인증하고, 한 비트라도 바뀌면 복호화를 거부해요.<br><sub>Encryption and integrity checking in one step. The header stays readable but is authenticated, and any changed bit makes decryption fail.</sub> | AEAD는 기밀성, 무결성, 부가 데이터 인증을 하나의 API로 제공해요. AES-GCM은 CTR 모드로 본문을 암호화하고, GF(2¹²⁸) 위의 다항식 해시 GHASH로 헤더(AAD)와 암호문 전체에 대한 16바이트 태그를 만들어요. 받는 쪽은 태그를 다시 계산해 상수 시간으로 비교하고, 일치할 때만 평문을 돌려줘요. 인증 없는 CTR이나 CBC 암호문은 비트를 뒤집어 금액 같은 내용을 조작할 수 있어서, 현대 프로토콜은 AEAD만 써요. 대표 구성은 AES-GCM, ChaCha20-Poly1305, nonce 실수에 강한 AES-GCM-SIV이고, TLS 1.3은 AEAD 암호 스위트만 허용해요.<br><sub>AEAD provides confidentiality, integrity and authentication of associated data through one API. AES-GCM encrypts the body in CTR mode and computes a 16-byte tag over the header (AAD) and the whole ciphertext with GHASH, a polynomial hash over GF(2¹²⁸). The receiver recomputes the tag, compares it in constant time, and releases plaintext only on a match. Unauthenticated CTR or CBC ciphertext can be edited by flipping bits, changing amounts and other content, so modern protocols use AEAD only. Common choices are AES-GCM, ChaCha20-Poly1305 and nonce-misuse-resistant AES-GCM-SIV, and TLS 1.3 permits only AEAD cipher suites.</sub> |
| **패딩 오라클 공격**<br><sub>The padding oracle attack</sub> | 서버가 패딩 오류를 따로 알려 주면 키 없이도 CBC 암호문을 한 바이트씩 풀 수 있어요. 작은 오류 메시지가 오라클이 돼요.<br><sub>If a server reveals padding errors, CBC ciphertext can be decrypted byte by byte without the key. A tiny error message becomes an oracle.</sub> | CBC 모드는 블록 크기를 맞추려고 PKCS#7 패딩을 붙여요. 3바이트가 남으면 03 03 03을 채우고, 복호화 후 이 형식이 맞는지 검사해요. 복호화는 P = Dₖ(C₁) ⊕ C₀라서 앞 블록 C₀의 바이트를 바꾸면 평문의 같은 자리가 그대로 바뀌어요. 서버가 “패딩 오류”와 다른 오류를 구분해서 알려 주면, 공격자는 C₀의 마지막 바이트를 0부터 255까지 바꿔 보다가 패딩이 맞는 순간 그 바이트가 01이 됐다는 걸 알고, 거기서 실제 평문 바이트를 계산해요. 이를 끝에서부터 반복하면 바이트당 최대 256번의 질의로 전체 평문이 풀려요. 2002년 보드네가 발표한 뒤 ASP.NET, SSL 3.0의 POODLE, TLS의 Lucky 13 같은 공격으로 이어졌고, 대책은 AEAD와 하나로 통일된 오류 응답이에요.<br><sub>CBC mode pads messages to the block size with PKCS#7, filling three spare bytes with 03 03 03, and checks that format after decrypting. Since decryption computes P = Dₖ(C₁) ⊕ C₀, changing a byte of the previous block C₀ changes the same plaintext byte. If the server reports padding errors differently from other errors, an attacker tries all 256 values in C₀’s last byte; the one that yields valid padding means that byte decrypted to 01, from which the real plaintext byte follows. Repeating from the end recovers the whole plaintext with at most 256 queries per byte. Since Vaudenay’s 2002 paper this has struck ASP.NET, SSL 3.0 (POODLE) and TLS (Lucky 13); the fix is AEAD plus a single, uniform error response.</sub> |

| **생일 공격**<br><sub>The birthday attack</sub> | 23명이면 생일이 같은 쌍이 있을 확률이 50%를 넘어요. n비트 해시는 약 2^(n/2)번이면 충돌이 나와요.<br><sub>With 23 people a shared birthday is more likely than not. An n-bit hash yields a collision after about 2^(n/2) tries.</sub> | 사람이 k명이면 쌍은 k(k − 1)/2개라 23명만 모여도 쌍이 253개고, 같은 생일이 있을 확률이 50.7%가 돼요. 해시도 마찬가지로 출력이 n비트면 약 2^(n/2)개의 입력만 해시해 봐도 두 입력의 해시가 같은 충돌이 나올 가능성이 커요. 그래서 128비트 MD5는 원리적으로 2⁶⁴, 256비트 SHA-256은 2¹²⁸의 충돌 저항성을 가져요. 충돌을 찾으면 무해한 문서와 악성 문서의 해시를 같게 만들어, 한쪽에 받은 서명을 다른 쪽에 쓸 수 있어요. MD5는 구조적 약점 때문에 지금은 몇 초 만에 충돌이 만들어지고, SHA-1도 2017년 SHAttered로 실제 충돌 PDF가 공개됐어요. 특정 해시값에 맞는 입력을 찾는 원상 공격은 여전히 2ⁿ이 들어요.<br><sub>With k people there are k(k − 1)/2 pairs, so 23 people already make 253 pairs and a 50.7% chance of a shared birthday. Likewise, an n-bit hash is likely to yield a collision, two inputs with the same hash, after only about 2^(n/2) inputs. That gives 128-bit MD5 a theoretical collision resistance of 2⁶⁴ and 256-bit SHA-256 one of 2¹²⁸. A collision lets an attacker make a harmless and a malicious document share a hash, so a signature on one validates the other. Structural weaknesses mean MD5 collisions now take seconds, and SHAttered published colliding SHA-1 PDFs in 2017. Finding an input for a given hash, a preimage, still costs 2ⁿ.</sub> |
| **머클-담고르와 길이 확장**<br><sub>Merkle–Damgård and length extension</sub> | MD5·SHA-1·SHA-2는 블록을 압축 함수로 이어 붙여요. 해시값이 곧 내부 상태라 H(secret ‖ m)은 MAC으로 쓸 수 없어요.<br><sub>MD5, SHA-1 and SHA-2 chain blocks through a compression function. Because the hash is the internal state, H(secret ‖ m) is unsafe as a MAC.</sub> | 머클-담고르 구조는 메시지를 패딩해 고정 크기 블록으로 나누고, 초기값 IV에서 시작해 hᵢ = f(hᵢ₋₁, mᵢ)로 압축 함수 f를 차례로 적용해요. 마지막 블록에는 1비트, 0들, 원래 길이를 붙여서 압축 함수가 충돌에 강하면 해시 전체도 충돌에 강하다는 성질을 보장해요. 문제는 출력이 마지막 체인 값 그대로라는 점이에요. H(secret ‖ m)을 MAC으로 쓰면 공격자는 비밀을 몰라도 그 값에서 압축을 이어 가, m ‖ 패딩 ‖ &admin=1 같은 확장된 메시지의 유효한 MAC을 계산할 수 있어요. 2009년 Flickr API가 이 공격에 당했어요. 그래서 MAC은 HMAC으로 만들고, SHA-3, SHA-512/256, BLAKE3처럼 내부 상태를 다 드러내지 않는 해시는 길이 확장이 안 돼요.<br><sub>The Merkle–Damgård construction pads the message into fixed-size blocks and, starting from an IV, applies a compression function as hᵢ = f(hᵢ₋₁, mᵢ). Padding the last block with a 1 bit, zeros and the original length ensures that a collision-resistant compression function yields a collision-resistant hash. The catch is that the output is simply the final chaining value. If H(secret ‖ m) is used as a MAC, an attacker can resume compression from it without the secret and compute a valid MAC for m ‖ padding ‖ &admin=1. Flickr’s API fell to this in 2009. MACs should be built with HMAC, and hashes that hide part of their state, such as SHA-3, SHA-512/256 and BLAKE3, resist length extension.</sub> |
| **스펀지 구조 (SHA-3)**<br><sub>The sponge construction (SHA-3)</sub> | 상태를 비율과 용량으로 나눠 입력을 흡수하고 출력을 짜내요. 용량이 드러나지 않아 길이 확장 공격이 통하지 않아요.<br><sub>Split the state into rate and capacity, absorb the input, then squeeze out the output. The capacity stays hidden, so length extension fails.</sub> | SHA-3(Keccak)는 1600비트 상태를 바깥과 닿는 비율 r과 숨겨진 용량 c로 나눠요. SHA3-256은 r = 1088, c = 512예요. 흡수 단계에서는 메시지 블록을 r 부분에 XOR하고 24라운드짜리 순열 Keccak-f로 상태 전체를 섞기를 반복해요. 다 흡수하면 짜내기 단계에서 r 부분의 앞쪽을 출력으로 읽고, 더 필요하면 다시 섞어 읽어요. 용량 c는 입출력에 직접 닿지 않아 해시값만으로 내부 상태를 복원할 수 없고, 안전성은 c/2 = 256비트가 되며 길이 확장 공격도 불가능해요. 출력 길이를 마음대로 정하는 SHAKE128/256(XOF)도 같은 구조이고, ML-KEM과 ML-DSA가 내부에서 써요.<br><sub>SHA-3 (Keccak) splits a 1600-bit state into an outer rate r and a hidden capacity c; SHA3-256 uses r = 1088 and c = 512. In the absorbing phase each message block is XORed into the rate and the whole state is stirred by Keccak-f, a 24-round permutation. In the squeezing phase output is read from the rate, mixing again whenever more is needed. Because the capacity never touches input or output directly, the internal state cannot be rebuilt from a hash, security is c/2 = 256 bits, and length extension is impossible. The extendable-output functions SHAKE128 and SHAKE256 use the same structure, and ML-KEM and ML-DSA use them internally.</sub> |
| **머클 트리**<br><sub>Merkle tree</sub> | 데이터 조각의 해시를 짝지어 해시하며 루트 하나로 모아요. 루트만 믿으면 전체 무결성과 개별 포함 여부를 짧게 증명할 수 있어요.<br><sub>Hash pairs of hashes up to a single root. Trusting the root proves integrity of everything and lets any item prove its membership compactly.</sub> | 머클 트리는 데이터 조각마다 해시를 구해 잎으로 놓고, 두 개씩 이어 붙여 다시 해시하기를 반복해 루트 해시 하나를 만들어요. 어느 잎이든 한 비트만 바뀌어도 루트까지 가는 경로의 해시가 모두 바뀌니, 루트 32바이트만 안전하게 받으면 전체 데이터의 무결성을 확인할 수 있어요. 특정 잎이 포함됐다는 건 형제 해시 log₂ n개로 증명돼서, 잎이 100만 개여도 해시 20개면 충분해요. 비트코인 블록 헤더, Git의 커밋과 트리, 인증서 투명성 로그, IPFS와 BitTorrent가 이 구조를 써요. 잎 해시와 내부 노드 해시에 서로 다른 접두어를 붙여 둘을 혼동시키는 공격을 막는 것도 중요해요.<br><sub>A Merkle tree hashes each data item into a leaf, then repeatedly hashes pairs together until one root hash remains. Changing a single bit in any leaf changes every hash on its path to the root, so obtaining just the 32-byte root securely is enough to verify all the data. Inclusion of a particular leaf is proven with log₂ n sibling hashes, so a million leaves need only 20. Bitcoin block headers, Git commits and trees, Certificate Transparency logs, IPFS and BitTorrent all use the structure. Prefixing leaf and internal-node hashes differently prevents attacks that confuse the two.</sub> |
| **키 유도 함수 (HKDF)**<br><sub>Key derivation (HKDF)</sub> | 하나의 비밀에서 용도별로 독립인 키를 뽑아요. 비밀번호처럼 엔트로피가 낮은 입력에는 일부러 느린 KDF를 써요.<br><sub>Derive independent per-purpose keys from one secret. Low-entropy inputs like passwords need a deliberately slow KDF instead.</sub> | 키 교환으로 얻은 공유 비밀은 길이와 분포가 제각각이라 그대로 키로 쓰기 어렵고, 한 비밀을 여러 용도에 그대로 쓰면 위험해요. HKDF(RFC 5869)는 먼저 추출 단계에서 HMAC(salt, 입력)으로 균일한 의사난수 키 PRK를 만들고, 확장 단계에서 Tᵢ = HMAC(PRK, Tᵢ₋₁ ‖ info ‖ i)를 이어 필요한 길이만큼 키 재료를 뽑아요. info를 “암호화”, “MAC”, “클라이언트→서버”처럼 바꾸면 서로 독립인 키가 나오고, TLS 1.3 키 스케줄이 이 방식으로 모든 키를 만들어요. 다만 HKDF는 빠르기 때문에 비밀번호처럼 추측할 수 있는 입력에는 맞지 않아요. 비밀번호에는 Argon2id, scrypt, bcrypt처럼 시간과 메모리를 일부러 많이 쓰는 KDF로 추측 공격의 비용을 높여요.<br><sub>Shared secrets from key exchange vary in length and distribution, and reusing one secret for several purposes is dangerous. HKDF (RFC 5869) first extracts a uniform pseudorandom key, PRK = HMAC(salt, input), then expands it with Tᵢ = HMAC(PRK, Tᵢ₋₁ ‖ info ‖ i) into as much key material as needed. Different info strings such as “encryption”, “MAC” or “client to server” yield independent keys, which is exactly how the TLS 1.3 key schedule derives every key. HKDF is fast, though, so it is wrong for guessable inputs like passwords. Passwords call for KDFs that deliberately spend time and memory, such as Argon2id, scrypt or bcrypt, to make guessing expensive.</sub> |

## 열쇠를 나누지 않고 비밀을 나누는 법 · Sharing secrets without sharing keys

RSA를 숫자로 직접 계산해 보고, 교과서 RSA의 함정과 OAEP, 타원곡선의 점 덧셈, ECDSA 서명과 nonce 재사용 사고, 순방향 비밀성, 그리고 실제 시스템이 쓰는 하이브리드 암호까지 따라가요.

| **RSA의 수학**<br><sub>The math of RSA</sub> | 두 소수의 곱 n을 공개하고, 소수를 알아야 계산되는 d를 비밀로 둬요. n을 소인수분해할 수 없다는 데 안전성이 달려 있어요.<br><sub>Publish the product n of two primes and keep d, computable only from those primes. Security depends on n being impossible to factor.</sub> | RSA는 큰 소수 p, q를 골라 n = pq를 만들고 φ(n) = (p − 1)(q − 1)을 계산해요. φ(n)과 서로소인 공개 지수 e를 정하고 확장 유클리드로 ed ≡ 1 (mod φ(n))인 d를 구하면, (n, e)가 공개 키, d가 개인 키예요. p = 61, q = 53이면 n = 3233, φ = 3120이고, e = 17에서 d = 2753이 나와요. 암호화 c = mᵉ mod n으로 65는 2790이 되고, 복호화 cᵈ mod n은 오일러 정리 덕분에 다시 65가 돼요. 같은 수학으로 s = mᵈ를 만들면 서명이 되고 sᵉ로 검증해요. n을 소인수분해하면 φ(n)과 d가 바로 나오므로 안전성은 소인수분해의 어려움에 달려 있고, 지금은 2048비트 이상을 권장해요. 실제로는 e = 65537과 패딩을 함께 써요.<br><sub>RSA picks large primes p and q, forms n = pq and computes φ(n) = (p − 1)(q − 1). Choosing a public exponent e coprime to φ(n) and using extended Euclid to find d with ed ≡ 1 (mod φ(n)) gives the public key (n, e) and private key d. With p = 61 and q = 53, n = 3233 and φ = 3120, and e = 17 gives d = 2753. Encryption c = mᵉ mod n turns 65 into 2790, and decryption cᵈ mod n returns 65 thanks to Euler’s theorem. The same math signs, s = mᵈ, verified with sᵉ. Factoring n reveals φ(n) and d at once, so security rests on the hardness of factoring, and 2048-bit or larger moduli are recommended. Real systems use e = 65537 together with padding.</sub> |
| **교과서 RSA의 함정과 OAEP**<br><sub>Textbook RSA pitfalls and OAEP</sub> | 패딩 없는 RSA는 결정적이고 곱셈으로 조작할 수 있어요. 암호화는 OAEP, 서명은 PSS로 무작위성을 섞어야 해요.<br><sub>Unpadded RSA is deterministic and malleable through multiplication. Mix in randomness with OAEP for encryption and PSS for signatures.</sub> | 패딩 없는 교과서 RSA는 Enc(a) · Enc(b) = Enc(ab)를 만족해서, 공격자가 암호문 2790에 2¹⁷ mod n = 1752를 곱한 3017을 보내면 복호화 결과가 65의 두 배인 130이 돼요. 또 같은 평문은 늘 같은 암호문이 되어, “yes”나 “no”처럼 후보가 적으면 직접 암호화해 비교하는 것만으로 내용을 알아낼 수 있어요. e = 3에 작은 m을 쓰면 mᵉ가 n보다 작아 그냥 세제곱근으로 풀리기도 해요. OAEP는 무작위 seed와 마스크 생성 함수(MGF)로 평문을 섞은 뒤 암호화해서 매번 다른 암호문을 만들고, 조작하면 구조가 깨져 거부되게 해요. 예전 PKCS#1 v1.5 암호화 패딩은 1998년 블라이헨바허의 패딩 오라클 공격에 당했고, 2017년 ROBOT으로 여러 제품에서 다시 발견됐어요.<br><sub>Unpadded textbook RSA satisfies Enc(a) · Enc(b) = Enc(ab), so multiplying the ciphertext 2790 by 2¹⁷ mod n = 1752 gives 3017, which decrypts to 130, twice the original 65. It is also deterministic: when candidates are few, like “yes” or “no”, encrypting them and comparing reveals the message. With e = 3 and a small m, mᵉ may not even exceed n, so a plain cube root recovers it. OAEP mixes the message with a random seed through mask generation functions before encrypting, giving a fresh ciphertext every time and rejecting tampered ones. The older PKCS#1 v1.5 encryption padding fell to Bleichenbacher’s padding oracle attack in 1998, rediscovered across many products as ROBOT in 2017.</sub> |
| **타원곡선**<br><sub>Elliptic curves</sub> | 곡선 위의 점끼리 더하는 규칙으로 군을 만들어요. kP에서 k를 찾기 어려워 짧은 키로도 높은 안전성을 줘요.<br><sub>Adding points on a curve forms a group. Recovering k from kP is hard, so short keys give strong security.</sub> | 타원곡선은 y² = x³ + ax + b를 만족하는 점들과 무한원점으로 이루어져요. 두 점 P, Q를 잇는 직선은 곡선과 한 점 R에서 더 만나고, R을 x축에 대해 뒤집은 점을 P + Q로 정의해요. y² = x³ − x + 1에서 P(−1, 1)과 Q(0, 1)을 더하면 직선 y = 1이 R(1, 1)을 지나 P + Q = (1, −1)이 돼요. 같은 점을 더할 때는 접선을 써서 2Q = (¼, −⅞)이고, 두 배와 덧셈을 반복하면 kP를 약 log k번에 계산해요. 암호에서는 소수 p로 나눈 나머지 위의 곡선을 쓰고, kP에서 k를 찾는 ECDLP는 알려진 지름길이 없어 256비트 곡선이 3072비트 RSA와 비슷한 안전성을 줘요. P-256, secp256k1, Curve25519가 대표 곡선이에요.<br><sub>An elliptic curve consists of the points satisfying y² = x³ + ax + b plus a point at infinity. The line through two points P and Q meets the curve at one more point R, and reflecting R across the x-axis defines P + Q. On y² = x³ − x + 1, adding P(−1, 1) and Q(0, 1) uses the line y = 1, which passes through R(1, 1), so P + Q = (1, −1). Adding a point to itself uses the tangent, giving 2Q = (¼, −⅞), and repeated doubling and adding computes kP in about log k steps. Cryptography uses curves over integers mod a prime p, where recovering k from kP, the ECDLP, has no known shortcut, so a 256-bit curve matches roughly 3072-bit RSA. P-256, secp256k1 and Curve25519 are common curves.</sub> |
| **ECDSA와 nonce**<br><sub>ECDSA and its nonce</sub> | 서명마다 비밀 난수 k를 써요. 같은 k로 두 번 서명하면 두 식을 풀어 개인 키가 바로 나와요.<br><sub>Every signature uses a secret random k. Sign twice with the same k and the private key falls out of two equations.</sub> | ECDSA 서명은 비밀 난수 k로 R = kG를 계산해 r = R의 x좌표 mod n으로 두고, s = k⁻¹(z + rd) mod n을 계산해요. 여기서 z는 메시지 해시, d는 개인 키예요. 검증자는 공개 키 Q = dG만으로 u₁ = z/s, u₂ = r/s를 구해 u₁G + u₂Q의 x좌표가 r과 같은지 확인해요. 그런데 같은 k로 두 메시지에 서명하면 r이 같아지고, 두 s 식을 빼면 k = (z₁ − z₂)/(s₁ − s₂), 이어서 d = (s₁k − z₁)/r이 나와요. 2010년 소니 PS3는 k를 고정값으로 써서 서명 키가 공개됐고, 2013년 안드로이드 난수 버그로 비트코인 지갑들이 털렸어요. k가 조금만 치우쳐도 격자 공격으로 키가 새기 때문에, RFC 6979처럼 개인 키와 메시지에서 k를 결정적으로 만들거나 처음부터 그렇게 설계된 Ed25519를 써요.<br><sub>An ECDSA signature uses a secret random k to compute R = kG, sets r to R’s x-coordinate mod n, and computes s = k⁻¹(z + rd) mod n, where z is the message hash and d the private key. A verifier with only the public key Q = dG computes u₁ = z/s and u₂ = r/s and checks that u₁G + u₂Q has x-coordinate r. Signing two messages with the same k repeats r, and subtracting the two s equations gives k = (z₁ − z₂)/(s₁ − s₂) and then d = (s₁k − z₁)/r. Sony’s PS3 used a fixed k and lost its signing key in 2010, and an Android random-number bug emptied Bitcoin wallets in 2013. Even slightly biased k values leak keys through lattice attacks, so k is derived deterministically from the key and message (RFC 6979), or Ed25519, designed that way, is used instead.</sub> |
| **순방향 비밀성**<br><sub>Forward secrecy</sub> | 세션마다 임시 키로 키를 합의하고 지워요. 나중에 장기 키가 새도 지난 대화는 풀리지 않아요.<br><sub>Agree on keys with ephemeral key pairs and erase them after each session. A later leak of the long-term key leaves past conversations sealed.</sub> | 도청자는 지금 풀 수 없는 암호문도 일단 저장해 둘 수 있어요. 예전 TLS의 RSA 키 전송 방식은 클라이언트가 세션 키를 서버의 공개 키로 암호화해 보냈기 때문에, 몇 년 뒤 서버 개인 키가 유출되면 녹화된 모든 세션이 한꺼번에 풀려요. ECDHE는 세션마다 새 임시 키 쌍으로 디피-헬먼을 해서 공유 비밀을 만들고, 끝나면 임시 키를 지워요. 서버의 장기 키는 이 교환에 서명하는 데만 쓰이므로, 나중에 새도 공격자는 앞으로의 위장만 할 수 있고 지난 세션은 그대로 안전해요. TLS 1.3은 RSA 키 전송을 없애고 (EC)DHE만 남겼고, 메신저의 더블 래칫은 이 원리를 메시지 단위로 적용해요.<br><sub>An eavesdropper can store ciphertext today and wait. With the old TLS RSA key transport, the client encrypted the session key under the server’s public key, so if that private key leaked years later every recorded session could be decrypted at once. ECDHE runs Diffie–Hellman with a fresh ephemeral key pair per session and erases it afterward. The server’s long-term key only signs the exchange, so a later leak lets an attacker impersonate the server in future but leaves past sessions safe. TLS 1.3 removed RSA key transport and kept only (EC)DHE, and messengers’ Double Ratchet applies the same idea to every message.</sub> |
| **하이브리드 암호**<br><sub>Hybrid encryption</sub> | 공개키 암호로는 대칭키만 나르고, 실제 데이터는 빠른 대칭키 암호로 암호화해요. 거의 모든 실제 시스템의 구조예요.<br><sub>Public-key crypto carries only a symmetric key, and fast symmetric encryption handles the data. Nearly every real system works this way.</sub> | 공개키 연산은 대칭키 암호보다 수천 배 느리고 한 번에 작은 값만 다룰 수 있어서, 큰 데이터를 직접 암호화하지 않아요. 대신 KEM(키 캡슐화 메커니즘)으로 받는 사람의 공개 키에 대해 무작위 공유 비밀 ss와 캡슐 enc를 만들고, ss를 HKDF로 대칭키로 바꿔 데이터를 AES-GCM 같은 AEAD로 암호화해요. 보내는 것은 32바이트 정도의 enc와 암호문뿐이고, 받는 사람은 개인 키로 enc를 열어 같은 키를 얻어요. 이 KEM-DEM 구조는 TLS, PGP, HPKE(RFC 9180), 클라우드 KMS의 봉투 암호화에 그대로 쓰이고, KEM 자리에 ML-KEM 같은 양자내성 알고리즘을 끼워 넣기도 쉬워요.<br><sub>Public-key operations are thousands of times slower than symmetric ciphers and handle only small values, so they never encrypt bulk data directly. Instead a KEM (key encapsulation mechanism) produces a random shared secret ss and a capsule enc for the recipient’s public key; HKDF turns ss into a symmetric key, and the data is encrypted with an AEAD such as AES-GCM. Only the roughly 32-byte enc and the ciphertext are sent, and the recipient opens enc with the private key to get the same key. This KEM-DEM structure underlies TLS, PGP, HPKE (RFC 9180) and cloud KMS envelope encryption, and swapping in a post-quantum KEM such as ML-KEM is straightforward.</sub> |

## 보여 주지 않고 증명하고 계산하기 · Proving and computing without revealing

비밀을 보여 주지 않고 아는 걸 증명하는 영지식 증명, 여러 명이 나눠 갖는 비밀 분산, 암호문 그대로 계산하는 동형 암호, 양자 컴퓨터 이후를 대비하는 양자내성 암호, 그리고 메신저의 종단간 암호화까지, 지금 실제로 쓰이는 암호예요.  
*Zero-knowledge proofs that show knowledge without revealing it, secret sharing across many parties, homomorphic encryption that computes on ciphertext, post-quantum cryptography for the era after quantum computers, and the end-to-end encryption inside messengers: cryptography in use today.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **영지식 증명**<br><sub>Zero-knowledge proofs</sub> | 비밀 x를 보여 주지 않고 x를 안다는 사실만 증명해요. 약속, 도전, 응답 세 단계의 슈노어 프로토콜로 원리를 봐요.<br><sub>Prove you know a secret x without revealing it. The three-move Schnorr protocol of commit, challenge and response shows how.</sub> | 슈노어 프로토콜에서 증명자는 y = gˣ의 x를 안다는 걸 보이려 해요. 먼저 무작위 r로 t = gʳ를 보내 약속하고, 검증자가 무작위 도전값 c를 보내면, s = r + cx로 응답해요. 검증자는 gˢ = t · yᶜ인지 확인하는데, p = 23, g = 5, x = 6, r = 3, c = 4라면 s = 27 ≡ 5이고 5⁵ = 20 = 10 · 8⁴ mod 23이 맞아요. x를 모르면 c를 미리 알지 못하는 한 맞는 s를 만들 수 없고(건전성), r이 무작위라 s는 x에 대해 아무것도 알려 주지 않아요(영지식). c를 H(t, m)으로 바꾸는 피아트-샤미르 변환을 하면 대화 없이 검증 가능한 슈노어 서명이 되고, Ed25519도 이 계열이에요. zk-SNARK는 임의의 계산이 올바르게 수행됐다는 사실을 수백 바이트로 증명해 블록체인 롤업과 신원 증명에 쓰여요.<br><sub>In the Schnorr protocol a prover shows it knows the x behind y = gˣ. It first commits to t = gʳ for a random r; the verifier replies with a random challenge c; the prover answers s = r + cx. The verifier checks gˢ = t · yᶜ: with p = 23, g = 5, x = 6, r = 3 and c = 4, s = 27 ≡ 5 and 5⁵ = 20 = 10 · 8⁴ mod 23. Without x no valid s can be produced unless c is known in advance (soundness), and because r is random, s reveals nothing about x (zero knowledge). Replacing c with H(t, m), the Fiat–Shamir transform, yields the non-interactive Schnorr signature, the family Ed25519 belongs to. zk-SNARKs prove that an arbitrary computation was done correctly in a few hundred bytes and power blockchain rollups and identity proofs.</sub> |
| **샤미르 비밀 분산**<br><sub>Shamir secret sharing</sub> | 비밀을 다항식의 상수항에 숨기고 조각을 나눠 줘요. 아무 k명이면 복원하고, k − 1명으로는 아무것도 알 수 없어요.<br><sub>Hide the secret in a polynomial’s constant term and hand out points. Any k shares recover it; k − 1 reveal nothing.</sub> | 샤미르 비밀 분산은 비밀 S를 상수항으로 하는 k − 1차 다항식을 무작위로 만들어요. S = 1234, k = 3이면 f(x) = 1234 + 166x + 94x²처럼 고르고, 참가자 n = 6명에게 f(1) = 1494부터 f(6) = 5614까지 한 조각씩 나눠 줘요. 2차식은 점 3개로 하나로 정해지므로 아무 3명이 모이면 라그랑주 보간으로 f(0) = 1234를 되찾아요. 2명뿐이면 두 점을 지나는 포물선이 무수히 많아 비밀이 어떤 값이든 될 수 있고, 이는 계산량과 무관한 정보 이론적 안전성이에요. 실제로는 정수 대신 소수 p에 대한 나머지 위에서 계산해야 이 성질이 정확히 성립해요. 키 백업과 복구, 여러 명이 함께 서명하는 임계 서명, DNSSEC 루트 키 관리, 암호화폐 지갑에 쓰여요.<br><sub>Shamir secret sharing builds a random polynomial of degree k − 1 whose constant term is the secret S. For S = 1234 and k = 3, pick f(x) = 1234 + 166x + 94x² and give each of n = 6 participants one share, f(1) = 1494 through f(6) = 5614. Three points determine a quadratic, so any three people recover f(0) = 1234 by Lagrange interpolation. Two shares fit infinitely many parabolas, so the secret could be anything: information-theoretic security, independent of computing power. Real implementations compute modulo a prime p so that this holds exactly. It is used for key backup and recovery, threshold signatures, management of the DNSSEC root key and cryptocurrency wallets.</sub> |
| **동형 암호**<br><sub>Homomorphic encryption</sub> | 암호문 상태 그대로 계산하고, 결과를 복호화하면 평문으로 계산한 값과 같아요. 데이터를 보여 주지 않고 계산을 맡길 수 있어요.<br><sub>Compute directly on ciphertexts, and decrypting the result matches computing on plaintexts. Computation can be outsourced without revealing the data.</sub> | 동형 암호는 Enc(a)와 Enc(b)로 Enc(a ∘ b)를 만들 수 있는 암호예요. 교과서 RSA는 곱셈에 대해 동형이라, n = 3233, e = 17로 Enc(5) = 3086, Enc(13) = 47을 서버에 보내면 서버는 3086 × 47 mod 3233 = 2790을 계산하고, 이를 복호화하면 65 = 5 × 13이 나와요. Paillier 암호는 덧셈에 대해 동형이라 전자 투표 집계 등에 쓰였어요. 덧셈과 곱셈을 모두 지원하는 완전 동형 암호(FHE)는 2009년 크레이그 젠트리가 처음 만들었고, 어떤 계산이든 암호문 위에서 할 수 있어요. 격자 기반이라 연산마다 잡음이 커지고, 부트스트래핑으로 잡음을 줄이는 데 비용이 커서 평문 계산보다 수천~수백만 배 느려요. BFV, CKKS, TFHE 같은 방식이 암호화된 의료 데이터 분석, 비공개 모델 추론 등에 시도되고 있어요.<br><sub>Homomorphic encryption lets you derive Enc(a ∘ b) from Enc(a) and Enc(b). Textbook RSA is multiplicatively homomorphic: with n = 3233 and e = 17, sending Enc(5) = 3086 and Enc(13) = 47 lets a server compute 3086 × 47 mod 3233 = 2790, which decrypts to 65 = 5 × 13. Paillier encryption is additively homomorphic and has been used for vote tallying. Fully homomorphic encryption, supporting both addition and multiplication, was first built by Craig Gentry in 2009 and can evaluate any computation on ciphertexts. Being lattice-based, its noise grows with each operation, and bootstrapping to reduce it is costly, so it runs thousands to millions of times slower than plaintext computation. Schemes such as BFV, CKKS and TFHE are being applied to encrypted medical analytics and private model inference.</sub> |
| **양자내성 암호**<br><sub>Post-quantum cryptography</sub> | 양자 컴퓨터는 RSA와 타원곡선을 깰 수 있어요. 오차가 섞인 연립방정식(LWE) 같은 격자 문제로 옮겨 가는 중이에요.<br><sub>Quantum computers could break RSA and elliptic curves, so cryptography is moving to lattice problems like Learning With Errors.</sub> | 충분히 큰 양자 컴퓨터가 생기면 쇼어 알고리즘이 소인수분해와 이산 로그를 효율적으로 풀어 RSA, 디피-헬먼, 타원곡선 암호가 모두 깨져요. 그로버 알고리즘은 대칭키 탐색을 제곱근으로 줄일 뿐이라 AES-256이나 SHA-384처럼 길이를 늘리면 돼요. 지금 녹화한 암호문을 나중에 풀 수 있으므로 오래 지켜야 할 데이터는 미리 옮겨야 해요. 대표 후보인 LWE 문제는 비밀 s에 공개 행렬 A를 곱하고 작은 오차 e를 더한 b = As + e를 공개해요. 오차가 없으면 소거법으로 바로 풀리지만, 수백 차원에서 작은 오차가 섞이면 격자에서 가까운 점을 찾는 문제가 되어 양자 컴퓨터로도 어렵다고 여겨져요. NIST는 2024년 8월 ML-KEM(FIPS 203), ML-DSA(FIPS 204), SLH-DSA(FIPS 205)를 표준으로 발표했고, 브라우저 TLS의 X25519MLKEM768, Signal의 PQXDH, 애플 iMessage PQ3처럼 기존 알고리즘과 함께 쓰는 하이브리드 방식으로 배포되고 있어요.<br><sub>A large enough quantum computer running Shor’s algorithm would solve factoring and discrete logarithms efficiently, breaking RSA, Diffie–Hellman and elliptic curves. Grover’s algorithm only square-roots symmetric key search, so longer sizes such as AES-256 and SHA-384 suffice. Because ciphertext recorded today could be decrypted later, long-lived data must migrate early. The leading candidate problem, Learning With Errors, publishes b = As + e for a secret s, a public matrix A and a small error e. Without the error, elimination solves it at once, but small errors in hundreds of dimensions turn it into finding a close point in a lattice, believed hard even for quantum computers. In August 2024 NIST published ML-KEM (FIPS 203), ML-DSA (FIPS 204) and SLH-DSA (FIPS 205), now rolling out as hybrids with classical algorithms, such as X25519MLKEM768 in browser TLS, Signal’s PQXDH and Apple’s iMessage PQ3.</sub> |
| **종단간 암호화 (Signal)**<br><sub>End-to-end encryption (Signal)</sub> | 서버도 내용을 볼 수 없게 두 사용자만 키를 가져요. X3DH로 시작하고 더블 래칫으로 메시지마다 키를 바꿔요.<br><sub>Only the two users hold keys, so not even the server can read messages. X3DH starts the session and the Double Ratchet changes keys with every message.</sub> | 종단간 암호화는 서버가 메시지를 전달만 하고 내용은 볼 수 없게 해요. Signal 프로토콜에서 밥은 신원 키와 여러 개의 일회용 prekey를 미리 서버에 올려 두고, 앨리스는 밥이 오프라인이어도 그 prekey로 X3DH 키 합의를 해 공유 비밀을 만들어요. 이후 더블 래칫이 돌아가요. 대칭 래칫은 메시지마다 체인 키를 KDF로 한 칸 돌려 메시지 키를 뽑고 쓴 키는 지워서, 지금 키가 털려도 지난 메시지를 보호해요(순방향 비밀성). DH 래칫은 답장마다 새 DH 키 쌍을 섞어 루트 키를 갱신해서, 키가 한 번 털려도 다음 왕복부터 다시 안전해져요(침해 후 회복). 사용자는 안전 번호를 비교해 서버가 키를 바꿔치기하지 않았는지 확인해요. WhatsApp, Google 메시지도 이 프로토콜을 쓰고, Signal은 2023년 PQXDH로 초기 합의에 ML-KEM을 더했어요.<br><sub>End-to-end encryption lets the server relay messages without being able to read them. In the Signal Protocol, Bob uploads an identity key and a batch of one-time prekeys in advance, and Alice uses them to run the X3DH key agreement even while Bob is offline. The Double Ratchet then takes over. The symmetric ratchet turns the chain key one step through a KDF for each message key and erases used keys, protecting past messages if a current key leaks (forward secrecy). The DH ratchet mixes a fresh DH key pair into the root key with every reply, so security recovers one round trip after a compromise (post-compromise security). Users compare safety numbers to confirm the server did not swap keys. WhatsApp and Google Messages also use the protocol, and Signal added ML-KEM to the initial agreement with PQXDH in 2023.</sub> |
