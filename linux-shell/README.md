## 파일과 권한 · Files and permissions

리눅스 파일 트리를 돌아다니고 접근을 다루는 법이에요.  
*Getting around the Linux file tree and controlling access.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **파일 시스템 구조**<br><sub>Filesystem layout</sub> | 리눅스의 모든 파일은 / 하나에서 시작하는 트리에 있어요. 디렉터리마다 쓰임새가 정해져 있어요(FHS).<br><sub>Every Linux file hangs off a single root, /. Each top-level directory has a set purpose (the FHS).</sub> | /etc 설정, /home 사용자, /var 로그·DB처럼 변하는 데이터, /tmp 임시, /usr 프로그램과 라이브러리, /usr/local 직접 설치한 것, /proc·/sys 커널이 보여주는 가상 파일, /dev 장치. 디스크는 드라이브 문자 대신 /mnt, /data 같은 디렉터리에 마운트해서 붙여요.<br><sub>/etc holds config, /home users, /var changing data such as logs and databases, /tmp scratch space, /usr programs and libraries, /usr/local your own installs, /proc and /sys virtual files from the kernel, /dev devices. Disks are mounted onto directories such as /mnt or /data instead of getting drive letters.</sub> |
| **경로와 이동**<br><sub>Paths and navigation</sub> | 절대 경로는 /부터, 상대 경로는 지금 위치(현재 디렉터리)부터 찾아가요. ., .., ~ 로 짧게 써요.<br><sub>Absolute paths start at /; relative paths start from the current directory. ., .. and ~ are shortcuts.</sub> | pwd 현재 위치, cd 이동, cd - 직전 위치, cd ~ 또는 cd 홈. 상대 경로는 짧지만 실행 위치에 따라 결과가 달라지므로 크론·스크립트에서는 절대 경로나 "$(dirname "$0")" 기준이 안전해요. 탭 완성으로 오타를 줄여요.<br><sub>pwd prints where you are, cd moves, cd - jumps back, cd ~ (or plain cd) goes home. Relative paths are short but depend on where you run them, so cron jobs and scripts are safer with absolute paths or paths based on "$(dirname "$0")". Tab completion saves typos.</sub> |
| **파일 권한 (chmod)**<br><sub>File permissions (chmod)</sub> | 파일마다 소유자·그룹·그 외 사람에 대해 읽기(r)·쓰기(w)·실행(x) 권한이 있어요. 세 비트씩 묶어 754 같은 숫자로 써요.<br><sub>Each file grants read (r), write (w) and execute (x) separately to its owner, its group and everyone else. Three bits per group make an octal number such as 754.</sub> | r = 4, w = 2, x = 1. 644(rw-r--r--)는 일반 파일, 755(rwxr-xr-x)는 실행 파일·디렉터리, 600은 SSH 개인 키. 디렉터리에서 x는 들어가기, r은 목록, w는 파일 생성·삭제. chown으로 소유자 변경, umask가 새 파일의 기본값을 정해요. 777은 거의 항상 잘못된 해결책이에요.<br><sub>r = 4, w = 2, x = 1. 644 (rw-r--r--) suits ordinary files, 755 (rwxr-xr-x) executables and directories, 600 SSH private keys. On a directory, x means enter, r list, w create or delete entries. chown changes the owner and umask sets defaults for new files. 777 is almost always the wrong fix.</sub> |
| **하드 링크와 심볼릭 링크**<br><sub>Hard and symbolic links</sub> | 하드 링크는 같은 데이터(inode)에 이름을 하나 더 붙이고, 심볼릭 링크는 다른 경로를 적어 둔 바로가기예요.<br><sub>A hard link gives the same data (inode) a second name; a symbolic link is a shortcut that stores another path.</sub> | ln a b는 하드 링크(링크 수 증가, 원본을 지워도 유지, 같은 디스크·파일만), ln -s a b는 심볼릭 링크(디렉터리·다른 디스크도 가능, 원본이 사라지면 끊김). 버전 전환(current → releases/v2.3), /usr/bin/python → python3 같은 곳에 심링크를 써요. ls -li로 inode 번호 확인.<br><sub>ln a b makes a hard link (link count goes up, survives deleting the original, same filesystem and files only); ln -s a b makes a symlink (works for directories and across disks, breaks if the target disappears). Symlinks power version switching (current → releases/v2.3) and aliases such as /usr/bin/python → python3. ls -li shows inode numbers.</sub> |
| **글로브 패턴과 find**<br><sub>Glob patterns and find</sub> | \*.log 같은 패턴은 셸이 명령 실행 전에 맞는 파일 이름 목록으로 바꿔요. 하위 폴더까지 조건으로 찾을 땐 find를 써요.<br><sub>Patterns such as \*.log are turned into matching file names by the shell before the command runs. For subfolders and conditions, use find.</sub> | \* 아무 글자, ? 한 글자, [ab] 문자 하나, {a,b} 나열(파일 존재 여부와 무관). 따옴표 안에서는 펼쳐지지 않아요. find . -name "\*.log" -mtime -1 -size +10M -exec gzip {} +. 맞는 파일이 없으면 bash는 패턴을 그대로 넘기니 rm 같은 명령에 주의.<br><sub>\* matches anything, ? one character, [ab] one of a set, {a,b} lists alternatives whether or not files exist. Quotes stop expansion. find . -name "\*.log" -mtime -1 -size +10M -exec gzip {} + searches with conditions. With no match bash passes the pattern through unchanged, so be careful with rm.</sub> |

## 텍스트 처리 · Text processing

작은 도구를 파이프로 이어 데이터를 다뤄요.  
*Chaining small tools with pipes to work on data.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **파이프라인 조합**<br><sub>Composing pipelines</sub> | 한 가지 일만 하는 작은 명령을 파이프(\|)로 이어 복잡한 질문에 답해요. 앞 명령의 출력이 다음 명령의 입력이 돼요.<br><sub>Chain single-purpose commands with \| to answer complex questions; each command’s output becomes the next one’s input.</sub> | 예: grep ' 500 ' access.log \| awk '{print $1}' \| sort \| uniq -c \| sort -rn \| head → 500 오류를 가장 많이 낸 IP. uniq는 붙어 있는 중복만 세므로 앞에 sort가 필요해요. 단계마다 head를 붙여 중간 결과를 확인하며 만들어요.<br><sub>grep ' 500 ' access.log \| awk '{print $1}' \| sort \| uniq -c \| sort -rn \| head lists the IPs causing the most 500 errors. uniq counts only adjacent duplicates, hence the sort before it. Build pipelines step by step, checking intermediate output with head.</sub> |
| **grep과 정규식**<br><sub>grep and regular expressions</sub> | grep은 패턴과 맞는 줄만 골라 보여줘요. 정규식으로 글자 그대로가 아니라 형태로 찾을 수 있어요.<br><sub>grep keeps only lines matching a pattern; regular expressions match by shape rather than exact text.</sub> | -i 대소문자 무시, -v 반대, -c 개수, -n 줄 번호, -r 폴더 전체, -A/-B/-C 앞뒤 줄, -o 맞은 부분만, -E 확장 정규식. ^ 줄 시작, $ 줄 끝, . 아무 글자, [0-9]+ 숫자 하나 이상, \b 단어 경계. ripgrep(rg)은 .gitignore를 존중하고 훨씬 빨라요.<br><sub>-i ignores case, -v inverts, -c counts, -n numbers lines, -r recurses, -A/-B/-C add context, -o prints only the match, -E enables extended regex. ^ start, $ end, . any character, [0-9]+ one or more digits, \b word boundary. ripgrep (rg) respects .gitignore and is much faster.</sub> |
| **sed와 awk**<br><sub>sed and awk</sub> | sed는 줄 단위로 찾아 바꾸고 지우는 스트림 편집기, awk는 줄을 열로 나눠 거르고 계산하는 작은 언어예요.<br><sub>sed is a stream editor for line-by-line find, replace and delete; awk is a tiny language that splits lines into fields to filter and compute.</sub> | sed 's/old/new/g' 바꾸기, sed -i 파일 직접 수정, sed '/^#/d' 주석 삭제. awk -F, '{s+=$3} END {print s}' 합계, awk '$2=="web" {print $1}' 조건 출력. 따옴표 안 쉼표가 있는 CSV, JSON처럼 구조가 복잡해지면 csvkit·jq·파이썬으로 넘어가요.<br><sub>sed 's/old/new/g' replaces, sed -i edits files in place, sed '/^#/d' drops comment lines. awk -F, '{s+=$3} END {print s}' sums a column; awk '$2=="web" {print $1}' prints by condition. For CSV with quoted commas or for JSON, move to csvkit, jq or Python.</sub> |
| **리다이렉션**<br><sub>Redirection</sub> | 프로그램을 고치지 않고 입력과 출력의 방향을 바꿔요. >는 출력, 2>는 에러, <는 입력을 파일로 연결해요.<br><sub>Rewire a program’s input and output without changing it: > for output, 2> for errors, < for input from a file.</sub> | > 덮어쓰기, >> 이어 쓰기, 2>&1 에러를 출력과 같은 곳으로, &> 둘 다(bash), < 파일 입력, << 히어독, /dev/null 버리기, tee 화면과 파일 동시. 순서가 중요해요: cmd > f 2>&1은 둘 다 파일로, cmd 2>&1 > f는 에러만 화면에 남아요.<br><sub>> overwrites, >> appends, 2>&1 sends errors wherever output goes, &> does both (bash), < reads a file, << is a here-doc, /dev/null discards, tee writes to screen and file at once. Order matters: cmd > f 2>&1 sends both to the file, cmd 2>&1 > f leaves errors on screen.</sub> |
| **xargs와 명령 치환**<br><sub>xargs and command substitution</sub> | 앞 명령의 출력을 다른 명령의 인자로 넘겨요. xargs는 입력 줄을 인자로 모아 실행하고, $( )는 출력을 그 자리에 끼워 넣어요.<br><sub>Feed one command’s output into another as arguments: xargs gathers input lines into arguments, and $( ) pastes output in place.</sub> | 공백이 든 파일 이름은 쪼개지므로 find -print0 \| xargs -0을 써요. 인자가 너무 많으면 "Argument list too long" → xargs가 나눠 실행해요. -P 8 병렬, -I{} 자리 표시자, -n 1 하나씩. find -exec {} +도 비슷한 일을 해요.<br><sub>Names with spaces split apart, so use find -print0 \| xargs -0. Too many arguments trigger “Argument list too long”, and xargs batches them for you. -P 8 runs in parallel, -I{} is a placeholder, -n 1 passes one at a time. find -exec {} + does a similar job.</sub> |

## 셸 스크립트 · Shell scripting

셸이 명령줄을 해석하는 규칙과 자동화의 기본이에요.  
*How the shell reads a command line, and the basics of automation.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **셸 확장과 따옴표**<br><sub>Expansion and quoting</sub> | 셸은 명령을 실행하기 전에 변수·명령 치환·글로브를 펼치고 공백에서 단어를 나눠요. 따옴표가 이 과정을 조절해요.<br><sub>Before running a command the shell expands variables, command substitutions and globs and splits words at spaces. Quotes control that process.</sub> | 순서: 중괄호 {a,b} → ~ → $변수·$( )·$(( )) → 단어 분리 → 글로브. 따옴표 없는 $f에 공백이 있으면 인자가 여러 개로 쪼개져요. "$var"는 변수만 펼치고 한 덩어리, '…'은 아무것도 안 펼쳐요. 변수는 거의 항상 큰따옴표로 감싸고 shellcheck로 확인해요.<br><sub>Order: braces {a,b} → ~ → $vars, $( ) and $(( )) → word splitting → globs. An unquoted $f containing a space becomes several arguments. "$var" expands but stays one word; '…' expands nothing. Quote variables almost always, and let shellcheck catch the misses.</sub> |
| **종료 코드와 &&, \|\|**<br><sub>Exit codes, && and \|\|</sub> | 모든 명령은 종료 코드를 남겨요. 0은 성공, 그 외는 실패이고 &&와 \|\|로 결과에 따라 다음 명령을 고를 수 있어요.<br><sub>Every command leaves an exit status: 0 for success, anything else for failure. && and \|\| choose the next command based on it.</sub> | $?로 직전 종료 코드 확인. make && ./app \|\| echo failed. 파이프라인은 마지막 명령의 코드만 남아 앞의 실패를 놓치므로 set -o pipefail. 스크립트 맨 위에 set -euo pipefail: 실패하면 멈추고, 정의 안 된 변수는 에러로. CI 파이프라인도 종료 코드로 성공·실패를 판단해요.<br><sub>$? holds the last status. make && ./app \|\| echo failed. A pipeline reports only its last command, hiding earlier failures, so set -o pipefail. Start scripts with set -euo pipefail: stop on errors and treat unset variables as errors. CI pipelines judge success by exit codes too.</sub> |
| **환경 변수와 PATH**<br><sub>Environment variables and PATH</sub> | 명령 이름만 입력하면 셸이 PATH의 디렉터리를 앞에서부터 찾아 처음 나온 것을 실행해요. 환경 변수는 자식 프로세스에 복사돼요.<br><sub>Type a bare command and the shell walks the directories in PATH, running the first match. Environment variables are copied into child processes.</sub> | which·type으로 실제 실행될 파일 확인. export PATH="$HOME/bin:$PATH"처럼 앞에 넣은 것이 우선. export한 변수만 자식에게 전달되고 부모로는 돌아가지 않아요. VAR=1 cmd는 그 명령에만. 설정은 ~/.bashrc·~/.profile·~/.zshrc에. 비밀 값은 환경 변수로 넘기되 로그에 남지 않게.<br><sub>which and type show what will actually run. Entries placed first win, as in export PATH="$HOME/bin:$PATH". Only exported variables reach children, and nothing flows back to the parent. VAR=1 cmd sets it for one command. Settings live in ~/.bashrc, ~/.profile or ~/.zshrc. Pass secrets through the environment, but keep them out of logs.</sub> |
| **셸 스크립트 기본**<br><sub>Shell script basics</sub> | #!로 인터프리터를 정하고 실행 권한을 주면 명령처럼 실행돼요. 인자, 조건, 반복으로 반복 작업을 자동화해요.<br><sub>Pick an interpreter with #!, set the execute bit, and the script runs like any command. Arguments, conditions and loops automate repetitive work.</sub> | $1 $2 위치 인자, $# 개수, "$@" 전체, ${2:-기본값}. [ -d dir ], [ -f file ], [ -z "$s" ], 숫자 비교 -eq -lt. for f in "$dir"/\*.conf; do … done. 에러는 >&2로 내고 exit 1. 함수, trap으로 정리 작업. 길어지거나 자료구조가 필요하면 파이썬이 나아요.<br><sub>$1 $2 are positional arguments, $# their count, "$@" all of them, ${2:-default} a fallback. Tests: [ -d dir ], [ -f file ], [ -z "$s" ], numeric -eq and -lt. for f in "$dir"/\*.conf; do … done. Report errors with >&2 and exit 1; clean up with trap. Once it grows or needs real data structures, Python is the better tool.</sub> |
| **작업 제어와 세션**<br><sub>Job control and sessions</sub> | &로 백그라운드 실행, Ctrl+Z로 멈춤, bg·fg로 이어서 실행해요. 터미널을 닫아도 계속 돌리려면 tmux나 nohup이 필요해요.<br><sub>Start work in the background with &, pause it with Ctrl+Z, resume with bg or fg. To survive closing the terminal you need tmux or nohup.</sub> | jobs로 목록, fg %2로 2번 작업을 앞으로. 터미널을 닫으면 SIGHUP으로 작업이 종료돼요 → nohup cmd &, disown, 또는 tmux·screen 세션에서 실행하면 SSH가 끊겨도 유지. 계속 돌아야 하는 서비스는 systemd 유닛으로 만들어요.<br><sub>jobs lists them and fg %2 brings job 2 forward. Closing the terminal sends SIGHUP and kills jobs, so use nohup cmd &, disown, or a tmux or screen session that survives a dropped SSH connection. Services that must keep running belong in a systemd unit.</sub> |

## 시스템 관리 · System administration

서버 상태를 보고 서비스·디스크·패키지·일정을 다뤄요.  
*Watching a server and managing services, disks, packages and schedules.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **top으로 상태 보기**<br><sub>Reading top</sub> | top은 CPU·메모리·부하와 자원을 많이 쓰는 프로세스를 실시간으로 보여줘요. 서버가 느릴 때 가장 먼저 보는 화면이에요.<br><sub>top shows CPU, memory, load and the hungriest processes live: the first screen to open when a server is slow.</sub> | load average는 실행 중이거나 기다리는 작업 수의 1·5·15분 평균으로 코어 수와 비교해요. us/sy/id/wa 중 wa가 높으면 디스크 병목. free가 작아도 buff/cache는 필요하면 돌려주니 available을 봐요. %CPU 200은 코어 2개. htop, ps aux --sort=-%cpu, vmstat 1, iostat -x 1.<br><sub>Load average is runnable plus waiting tasks over 1, 5 and 15 minutes; compare it with the core count. Of us/sy/id/wa, a high wa means the disk is the bottleneck. A small free is fine because buff/cache is returned on demand, so watch available. %CPU 200 means two cores. Also htop, ps aux --sort=-%cpu, vmstat 1, iostat -x 1.</sub> |
| **systemd 서비스**<br><sub>systemd services</sub> | 서비스를 유닛 파일로 정의하고 systemctl로 시작·중지·자동 시작을 관리해요. 죽으면 다시 살리고 로그도 모아 줘요.<br><sub>Describe a service in a unit file and let systemctl start, stop and enable it. systemd restarts it when it dies and collects its logs.</sub> | systemctl enable --now api(지금 + 부팅 시), status, restart, stop. Restart=on-failure로 자동 재시작, User=로 권한 낮추기, After=로 순서. journalctl -u api -f로 로그, systemctl daemon-reload로 유닛 변경 반영. 타이머(크론 대체)와 cgroup 자원 제한(MemoryMax)도 제공해요.<br><sub>systemctl enable --now api (start now and at boot), status, restart, stop. Restart=on-failure restarts automatically, User= drops privileges, After= orders startup. journalctl -u api -f follows logs; systemctl daemon-reload picks up unit edits. It also offers timers (a cron replacement) and cgroup limits such as MemoryMax.</sub> |
| **디스크와 마운트**<br><sub>Disks and mounts</sub> | df로 파일 시스템별 사용량을, du로 폴더별 크기를 봐요. 새 디스크는 디렉터리에 마운트해서 트리에 붙여요.<br><sub>df shows usage per filesystem and du per folder. A new disk joins the tree by mounting it on a directory.</sub> | df -h, du -sh /var/\* \| sort -h, ncdu. mount /dev/sdb1 /data, 부팅 때 자동은 /etc/fstab(UUID로). df에 여유가 있는데 "No space left on device"면 inode 고갈(df -i)이나 지웠지만 열려 있는 파일(lsof +L1). 로그는 logrotate, journald는 --vacuum-size로 줄여요.<br><sub>df -h, du -sh /var/\* \| sort -h, ncdu. mount /dev/sdb1 /data; for boot-time mounts use /etc/fstab (by UUID). “No space left on device” with room in df means exhausted inodes (df -i) or deleted files still held open (lsof +L1). Tame logs with logrotate and journald with --vacuum-size.</sub> |
| **패키지 관리자**<br><sub>Package managers</sub> | 패키지 관리자는 저장소에서 소프트웨어를 받아 의존성까지 맞춰 설치·업데이트·삭제해요. 서명을 확인해 변조를 막아요.<br><sub>A package manager downloads software from repositories, resolves dependencies and installs, updates or removes it, checking signatures against tampering.</sub> | apt update(목록 갱신) → apt install/upgrade. 데비안·우분투 apt(.deb), 레드햇·페도라 dnf(.rpm), 알파인 apk, macOS brew. dpkg -L로 설치된 파일 목록. 시스템 파이썬에 pip install은 피하고 venv를, 버전 고정은 apt-mark hold. 컨테이너 이미지에서는 설치 후 캐시를 지워 크기를 줄여요.<br><sub>apt update refreshes the index, then apt install or upgrade. Debian and Ubuntu use apt (.deb), Red Hat and Fedora dnf (.rpm), Alpine apk, macOS brew. dpkg -L lists a package’s files. Avoid pip-installing into the system Python (use a venv); pin versions with apt-mark hold. In container images, clear the cache after installing to keep them small.</sub> |
| **크론 예약 작업**<br><sub>Scheduled jobs with cron</sub> | 크론은 분·시·일·월·요일 다섯 칸으로 정한 시각에 명령을 실행해요. 백업·정리·보고서 같은 반복 작업에 써요.<br><sub>cron runs commands at times set by five fields: minute, hour, day of month, month and weekday. Backups, cleanups and reports run this way.</sub> | \*/15 9-18 \* \* 1-5 = 평일 9~18시 15분마다. crontab -e로 편집. 함정: 최소한의 환경(PATH가 짧음), 출력은 리다이렉션하지 않으면 메일로 가거나 사라짐, 서버 시간대 기준, 이전 실행과 겹침(flock -n). systemd 타이머, 쿠버네티스 CronJob, 클라우드 스케줄러가 대안이에요.<br><sub>\*/15 9-18 \* \* 1-5 means every 15 minutes, 9 to 18, Monday to Friday. Edit with crontab -e. Gotchas: a minimal environment (short PATH), output that is mailed or lost unless redirected, the server’s time zone, and overlapping runs (wrap with flock -n). Alternatives: systemd timers, Kubernetes CronJobs, cloud schedulers.</sub> |
| **로그 보기와 관리**<br><sub>Reading and managing logs</sub> | tail -f로 로그를 실시간으로 따라가고, grep으로 거르고, journalctl로 서비스 로그를 봐요. logrotate가 로그가 디스크를 채우지 않게 관리해요.<br><sub>Follow logs live with tail -f, filter them with grep, and read service logs with journalctl. logrotate keeps logs from filling the disk.</sub> | tail -f app.log \| grep --line-buffered ERROR, less +F, journalctl -u api --since "1 hour ago" -p err. logrotate: 매일 돌리고 7개 보관·압축. 서버가 여러 대면 ELK(Elasticsearch·Kibana), Loki·Grafana, 클라우드 로깅으로 한곳에 모아요. JSON 구조화 로그는 필드로 거르기 쉬워요.<br><sub>tail -f app.log \| grep --line-buffered ERROR, less +F, journalctl -u api --since "1 hour ago" -p err. logrotate rotates daily, keeping seven compressed copies. With many servers, centralize in ELK (Elasticsearch, Kibana), Loki and Grafana, or cloud logging. Structured JSON logs filter cleanly by field.</sub> |

## 원격 접속과 네트워크 · Remote access and networking

서버에 안전하게 들어가고 연결 문제를 찾는 법이에요.  
*Getting into servers safely and tracking down connection problems.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **SSH 키 인증**<br><sub>SSH key authentication</sub> | 공개 키를 서버에 등록해 두면, 접속할 때 개인 키로 서명해서 신원을 증명해요. 비밀번호가 네트워크로 오가지 않아요.<br><sub>Register your public key on the server and prove your identity by signing with the private key at login; no password ever crosses the network.</sub> | ssh-keygen -t ed25519로 키 쌍 생성, ssh-copy-id로 공개 키를 ~/.ssh/authorized\_keys에 등록. 처음 접속 때 서버 호스트 키 지문을 확인해 known\_hosts에 저장하고, 바뀌면 경고(재설치 또는 중간자 공격). 비밀번호 로그인 끄기, ~/.ssh/config 별칭, ssh-agent, 개인 키 권한 600.<br><sub>ssh-keygen -t ed25519 makes the pair; ssh-copy-id adds the public key to ~/.ssh/authorized\_keys. On first connect you confirm the server’s host-key fingerprint, stored in known\_hosts; a changed key raises a warning (a rebuild, or a man-in-the-middle). Disable password logins, use ~/.ssh/config aliases and ssh-agent, and keep the private key at mode 600.</sub> |
| **네트워크 진단**<br><sub>Network troubleshooting</sub> | “접속이 안 돼요”는 DNS → IP 도달 → 포트 → 애플리케이션 순으로 아래 계층부터 하나씩 확인해요.<br><sub>Break “it won’t connect” into layers and check from the bottom: DNS, then reachability, then the port, then the application.</sub> | dig·nslookup(이름 해석), ping(도달·지연), nc -zv host 443(포트 열림), curl -v(HTTP·TLS 상세). 서버에서는 ss -tlnp로 듣고 있는 포트와 프로세스, 방화벽(ufw, iptables, 보안 그룹) 확인. 경로는 traceroute·mtr, 패킷은 tcpdump·Wireshark.<br><sub>dig or nslookup for name resolution, ping for reachability and latency, nc -zv host 443 for an open port, curl -v for HTTP and TLS details. On the server, ss -tlnp shows which process listens where; check firewalls (ufw, iptables, security groups). traceroute or mtr for the path, tcpdump or Wireshark for packets.</sub> |
| **SSH 포트 포워딩**<br><sub>SSH port forwarding</sub> | SSH 연결을 통로로 삼아 내 컴퓨터의 포트를 원격 네트워크 안의 서버로 이어요. 사설망의 DB에 안전하게 접속할 때 써요.<br><sub>Use an SSH connection as a pipe linking a port on your machine to a server inside a remote network, such as a database on a private subnet.</sub> | ssh -L 5433:db.internal:5432 bastion → localhost:5433이 db:5432로 연결. -R은 반대(원격 포트 → 내 컴퓨터), -D는 SOCKS 프록시, -J는 점프 호스트 경유, -N은 명령 없이 터널만. 트래픽이 SSH로 암호화돼요. 상시로 쓰면 VPN이나 클라우드의 세션 관리 기능이 더 적합해요.<br><sub>ssh -L 5433:db.internal:5432 bastion makes localhost:5433 reach db:5432. -R forwards the other way (remote port → your machine), -D runs a SOCKS proxy, -J hops through a jump host, -N opens only the tunnel. Traffic rides encrypted inside SSH. For permanent access, a VPN or the cloud’s session manager fits better.</sub> |
| **rsync 동기화**<br><sub>Syncing with rsync</sub> | rsync는 양쪽 파일을 비교해 바뀐 부분만 보내는 동기화 도구예요. 백업과 배포에 많이 써요.<br><sub>rsync compares both sides and transfers only what changed: a staple of backups and deployments.</sub> | 크기·수정 시각으로 비교하고, 바뀐 파일은 롤링 체크섬으로 다른 블록만 전송. -a 권한·시각 유지, -z 압축, -P 진행률·이어받기, --delete 원본에 없는 파일 삭제. 끝 슬래시 주의: src/는 내용물, src는 폴더째. 실행 전 -n(--dry-run)으로 확인해요.<br><sub>It compares size and modification time, then sends only the differing blocks of changed files using a rolling checksum. -a preserves permissions and times, -z compresses, -P shows progress and resumes, --delete removes files missing from the source. Mind the trailing slash: src/ copies the contents, src the folder itself. Dry-run first with -n.</sub> |
