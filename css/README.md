## 선택자와 캐스케이드 · Selectors and the cascade

어떤 요소를 고르고, 여러 규칙이 겹칠 때 어떤 값이 이기는지예요.  
*Which elements a rule picks, and which value wins when rules collide.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **캐스케이드**<br><sub>The cascade</sub> | 같은 요소에 여러 규칙이 겹칠 때 하나의 값을 고르는 규칙이에요. 출처와 중요도, 레이어, 명시도, 등장 순서 순으로 비교해요.<br><sub>The rule that picks one value when several rules target the same element, comparing origin and importance, layers, specificity, then source order.</sub> | 브라우저 기본값은 a를 파랗게, 작성자 CSS는 회색으로 칠하면 작성자 CSS가 이겨요. 출처가 같으면 명시도로 겨뤄서 #home(ID)이 .nav a와 a를 이기고, 나중에 쓴 a { color: red }도 명시도가 낮아 져요. 등장 순서는 명시도가 똑같을 때만 승부를 가려요. !important는 이 순서를 뒤집지만, 남발하면 이기기 위해 !important를 더 쓰는 악순환이 생겨요. DevTools의 Styles 패널은 진 선언에 취소선을 그어 보여줘요.<br><sub>If the browser default colors a link blue and author CSS colors it gray, the author wins. With equal origin, specificity decides: #home (an ID) beats .nav a and a, and even a later a { color: red } loses on specificity. Source order breaks ties only between equal specificities. !important overturns all this, but overuse starts an arms race of more !important. The DevTools Styles panel strikes through losing declarations.</sub> |
| **명시도**<br><sub>Specificity</sub> | 선택자의 (ID, 클래스, 태그) 개수로 정하는 우선순위예요. 왼쪽 칸부터 비교해서, 클래스가 아무리 많아도 ID 하나를 못 이겨요.<br><sub>A priority computed from a selector’s counts of IDs, classes and tags, compared column by column from the left, so no number of classes beats one ID.</sub> | p는 0,0,1, .note p는 0,1,1, .card .note p는 0,2,1, #main p는 1,0,1이라 #main p가 가장 강해요. :hover 같은 가상 클래스와 [type] 같은 속성 선택자는 클래스로 세고, ::before 같은 가상 요소는 태그로 세요. :where()는 항상 0이고 :is()는 인자 중 가장 센 값을 써요. 인라인 style 속성은 모든 선택자보다 강해요. 스타일에 ID와 인라인 스타일을 피하고 클래스 하나로 쓰면 명시도가 평평해져 덮어쓰기가 쉬워요.<br><sub>p is 0,0,1, .note p is 0,1,1, .card .note p is 0,2,1 and #main p is 1,0,1, so #main p is strongest. Pseudo-classes such as :hover and attribute selectors such as [type] count as classes, and pseudo-elements such as ::before as tags. :where() always counts as 0, while :is() takes its strongest argument. An inline style attribute beats every selector. Avoiding IDs and inline styles and using single classes keeps specificity flat and overrides easy.</sub> |
| **상속**<br><sub>Inheritance</sub> | 글자 관련 속성은 부모에서 자식으로 상속되고, 상자 관련 속성은 상속되지 않아요. inherit·initial·unset으로 이 동작을 직접 정할 수 있어요.<br><sub>Text properties inherit from parent to child while box properties do not; inherit, initial and unset control this explicitly.</sub> | body에 color와 font-size를 한 번만 정하면 그 안의 p와 a가 물려받아요. 반면 .box의 border, padding, margin, background는 자식에게 내려가지 않아요. 링크는 브라우저가 따로 파랑을 주기 때문에 a { color: inherit }로 부모 색을 따르게 하고, button·input은 글꼴을 상속하지 않아 font: inherit을 자주 써요. initial은 명세의 기본값, unset은 상속 속성이면 inherit 아니면 initial이에요. all: unset은 모든 속성을 한 번에 초기화해요.<br><sub>Setting color and font-size once on body lets every p and a inside inherit them, while .box’s border, padding, margin and background stay with .box. Browsers give links their own blue, so a { color: inherit } follows the parent instead, and buttons and inputs do not inherit fonts, hence font: inherit. initial means the specification default, and unset means inherit for inherited properties and initial otherwise. all: unset resets every property at once.</sub> |
| **선택자 조합**<br><sub>Combining selectors</sub> | 결합자(공백, >, +, ~)로 요소 사이의 관계를, [속성]으로 속성 값을, :nth-child로 위치를 조건으로 요소를 골라요.<br><sub>Combinators (space, >, +, ~) express relationships, [attribute] selectors match attribute values, and :nth-child matches positions.</sub> | nav a는 nav 안 어디에 있든 모든 링크를, nav > a는 바로 아래 자식 링크만 골라요. h2 + p는 h2 바로 다음 형제 하나, h2 ~ p는 그 뒤의 모든 p예요. a[href^="https"]는 https로 시작하는 링크, input[type="email"]은 이메일 입력창이에요(^= 시작, $= 끝, \*= 포함). li:nth-child(2n)은 짝수 번째, :first-child·:last-child는 처음과 끝이에요. 브라우저는 선택자를 오른쪽 끝부터 맞춰 보므로, 깊은 체인보다 짧은 클래스 선택자가 읽기도 빠르기도 좋아요.<br><sub>nav a matches every link anywhere inside nav, while nav > a matches only direct children. h2 + p is the single sibling right after an h2, and h2 ~ p every later p. a[href^="https"] matches links starting with https and input[type="email"] email inputs (^= starts, $= ends, \*= contains). li:nth-child(2n) picks even items, and :first-child and :last-child the ends. Browsers match selectors from the rightmost part, so short class selectors beat deep chains for both readability and speed.</sub> |
| **가상 클래스와 가상 요소**<br><sub>Pseudo-classes and pseudo-elements</sub> | 가상 클래스(:)는 :hover처럼 요소의 상태를, 가상 요소(::)는 ::after처럼 요소의 일부나 덧붙인 내용을 골라요.<br><sub>Pseudo-classes (:) select states such as :hover, and pseudo-elements (::) select parts or generated content such as ::after.</sub> | a:hover는 마우스가 올라갔을 때, input:focus-visible은 키보드로 초점을 옮겼을 때, input:invalid는 입력이 형식에 맞지 않을 때, button:disabled는 비활성일 때 적용돼요. .req::after { content: " \*" }는 필수 항목 옆에 별표를 덧붙이고, ::first-line은 첫 줄, ::selection은 드래그한 영역, ::marker는 목록 글머리표를 꾸며요. ::before·::after는 content가 있어야 나타나고 장식용이라 중요한 정보는 넣지 않아요. :hover만으로 기능을 숨기면 터치 기기에서 쓸 수 없어요.<br><sub>a:hover applies under the pointer, input:focus-visible on keyboard focus, input:invalid when input fails validation and button:disabled when inactive. .req::after { content: " \*" } adds an asterisk to required fields, ::first-line styles the first line, ::selection highlighted text and ::marker list bullets. ::before and ::after need content to appear and are decorative, so keep essential information out of them. Hiding features behind :hover alone breaks them on touch devices.</sub> |
| **:has()와 :is()·:where()**<br><sub>:has(), :is() and :where()</sub> | :has()는 “이런 자식을 가진 부모”를 고르는 선택자이고, :is()와 :where()는 여러 선택자를 하나로 묶어요. :where()는 명시도가 0이에요.<br><sub>:has() selects a parent that contains a match, while :is() and :where() group selectors; :where() has zero specificity.</sub> | .card:has(img)는 이미지가 들어 있는 카드만 골라 여백을 없애요. 오랫동안 불가능했던 부모 선택자라, form:has(:invalid) .submit처럼 상태를 조합하면 JS 없이도 폼 전체 스타일을 바꿀 수 있어요. :is(h1, h2, h3) a는 h1 a, h2 a, h3 a를 짧게 쓴 것이고 명시도는 인자 중 가장 센 값이에요. :where(ul, ol) li는 같은 뜻이지만 명시도가 0이라 리셋이나 라이브러리 기본 스타일을 .list li 하나로 쉽게 덮을 수 있어요. :has()는 계산 비용이 있어 body:has()처럼 넓은 범위에는 신중하게 써요.<br><sub>.card:has(img) picks only cards containing an image and removes their padding. As the long-missing parent selector, combined states such as form:has(:invalid) .submit restyle a whole form without JavaScript. :is(h1, h2, h3) a is shorthand for h1 a, h2 a, h3 a, with the specificity of its strongest argument. :where(ul, ol) li means the same with zero specificity, so resets and library defaults are easy to override with a plain .list li. :has() has a cost, so use it carefully on broad scopes such as body:has().</sub> |
| **캐스케이드 레이어**<br><sub>Cascade layers</sub> | @layer로 CSS를 우선순위 층으로 나눠요. 레이어 순서가 명시도보다 먼저 비교되어 명시도 싸움을 구조로 해결해요.<br><sub>@layer splits CSS into priority tiers whose order is compared before specificity, resolving specificity wars by structure.</sub> | @layer reset, base, components, utilities;처럼 첫 줄에 적은 순서대로 뒤의 레이어가 강해요. 그래서 components 안의 #app .btn(명시도 1,1,0)도 utilities의 .text-red(0,1,0)에 져요. 레이어에 속하지 않은 일반 CSS는 모든 레이어보다 강하고, !important 선언은 레이어 순서가 거꾸로 적용돼요. @import url(lib.css) layer(vendor)로 외부 라이브러리를 가장 낮은 층에 넣으면 내 스타일로 쉽게 덮을 수 있어요. Tailwind v4도 내부적으로 @layer를 사용해요.<br><sub>With @layer reset, base, components, utilities; later layers win in the order of that first statement. So #app .btn in components (specificity 1,1,0) loses to .text-red in utilities (0,1,0). Unlayered CSS beats every layer, and for !important declarations the layer order reverses. Importing a library with @import url(lib.css) layer(vendor) puts it in the lowest tier, easy to override. Tailwind v4 uses @layer internally too.</sub> |

## 박스와 흐름 · Boxes and flow

모든 요소가 상자라는 데서 시작해, 상자가 흐름 속에서 어떻게 놓이고 겹치고 넘치는지예요.  
*Starting from the fact that every element is a box: how boxes sit in the flow, overlap and overflow.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **박스 모델**<br><sub>The box model</sub> | 모든 요소는 content, padding, border, margin 네 겹의 상자예요. box-sizing이 width가 어디까지를 가리키는지 정해요.<br><sub>Every element is a box of four layers: content, padding, border and margin; box-sizing decides what width measures.</sub> | width: 200px, padding: 20px, border: 5px를 주면 기본값 content-box에서는 width가 내용만 가리켜 실제 폭이 200 + 40 + 10 = 250px이 돼요. box-sizing: border-box면 width가 테두리까지 포함해 지정한 200px 그대로이고 내용 영역이 150px로 줄어요. 계산이 직관적이라 대부분의 프로젝트가 \*, \*::before, \*::after에 border-box를 전역으로 걸어요. margin은 상자 바깥의 간격이라 어느 방식이든 폭에 들어가지 않고, padding까지는 배경색이 칠해져요.<br><sub>With width: 200px, padding: 20px and border: 5px, the default content-box applies width to the content alone, so the box is really 200 + 40 + 10 = 250px wide. With box-sizing: border-box, width includes padding and border, staying at 200px while the content shrinks to 150px. Because this is intuitive, most projects set border-box globally on \*, \*::before, \*::after. Margin is space outside the box and never counts toward width, while the background paints through the padding.</sub> |
| **마진 상쇄**<br><sub>Margin collapsing</sub> | 블록 흐름에서 세로로 맞닿은 마진은 더해지지 않고 겹쳐 큰 값 하나만 남아요. 부모 밖으로 새어 나가기도 해요.<br><sub>In block flow, adjoining vertical margins overlap instead of adding, leaving only the larger, and can even leak out of the parent.</sub> | h2의 margin-bottom 30px과 p의 margin-top 20px 사이 간격은 50px이 아니라 30px이에요. 부모에 패딩·테두리가 없으면 첫 자식의 margin-top 40px이 부모 밖으로 새어 나가 부모 전체가 내려가요. 부모에 display: flow-root를 주면 새 블록 서식 맥락이 생겨 마진이 안에 머물러요. 가로 마진, flex·grid 아이템, absolute 요소에서는 상쇄가 일어나지 않아요. 그래서 요즘은 자식의 margin 대신 부모의 gap으로 간격을 관리하는 경우가 많아요.<br><sub>The gap between an h2 with margin-bottom: 30px and a p with margin-top: 20px is 30px, not 50px. With no padding or border on the parent, a first child’s margin-top: 40px leaks out and pushes the whole parent down. display: flow-root on the parent creates a new block formatting context that keeps the margin inside. Horizontal margins, flex and grid items and absolutely positioned elements never collapse. That is why spacing is now often managed with the parent’s gap instead of child margins.</sub> |
| **display**<br><sub>display</sub> | display는 요소가 주변과 어떻게 흐를지(block·inline)와 자식을 어떻게 배치할지(flex·grid)를 정해요. none이면 자리까지 사라져요.<br><sub>display sets how an element flows among its neighbors (block, inline) and how its children are laid out (flex, grid); none removes it entirely.</sub> | div 같은 block 요소는 한 줄을 통째로 차지하며 아래로 쌓이고, span 같은 inline 요소는 글자처럼 옆으로 흐르다 줄바꿈하며 width·height와 위아래 margin이 듣지 않아요. inline-block은 줄 안에 놓이면서도 폭과 높이를 가질 수 있어 태그나 배지에 써요. display: flex·grid는 자식들의 배치 방식을 바꿔요. display: none은 자리까지 없애고 스크린 리더에서도 사라지지만, visibility: hidden은 보이지만 않을 뿐 자리를 남겨요.<br><sub>Block elements such as div take a whole line and stack downward, while inline elements such as span flow sideways like text, wrapping, and ignore width, height and vertical margins. inline-block sits in a line yet takes a width and height, handy for tags and badges. display: flex and grid change how the children are arranged. display: none removes the element and its space, even for screen readers, whereas visibility: hidden only hides it and keeps the space.</sub> |
| **position**<br><sub>position</sub> | position은 요소를 흐름 속 어디에 놓을지 정해요. relative, absolute, fixed, sticky가 각각 다른 기준으로 위치를 잡아요.<br><sub>position chooses how an element is placed relative to the flow: relative, absolute, fixed and sticky each use a different reference.</sub> | .a { position: relative; top: 10px }는 원래 자리를 기준으로 살짝 옮기되 원래 자리는 비워 둬요. absolute는 흐름에서 빠져, position이 지정된 가장 가까운 조상(.card) 기준으로 놓여서 카드 모서리의 배지에 써요. sticky는 평소엔 흐름대로 있다가 스크롤해서 top: 0에 닿으면 그 자리에 붙어요(헤더, 표 머리글). fixed는 뷰포트 기준이라 스크롤해도 같은 자리에 있어요(플로팅 버튼). 조상에 transform이 있으면 fixed도 그 조상 기준이 되니 주의해요.<br><sub>.a { position: relative; top: 10px } nudges an element from its normal spot while keeping that spot reserved. absolute leaves the flow and is placed against the nearest positioned ancestor, such as .card, which suits corner badges. sticky stays in the flow until scrolling reaches top: 0, then sticks there, as for headers and table heads. fixed is placed against the viewport and stays put while scrolling, as for floating buttons. Beware: an ancestor with transform becomes the reference even for fixed elements.</sub> |
| **z-index와 쌓임 맥락**<br><sub>z-index and stacking contexts</sub> | z-index는 같은 쌓임 맥락 안에서만 비교돼요. 부모가 맥락을 만들면 자식은 z-index 9999여도 부모의 순서를 넘을 수 없어요.<br><sub>z-index is compared only within one stacking context; once a parent creates a context, its children cannot escape its order even at z-index 9999.</sub> | .a(z 1)와 .b(z 2)는 .b가 위예요. 그런데 .a에 opacity: .99를 주면 .a가 쌓임 맥락이 되어, 안쪽 .menu의 z-index 9999는 .a 상자 안에서만 비교되고 결국 .b 아래에 깔려요. opacity 1 미만, transform, filter, position과 z-index 조합, isolation: isolate 등이 맥락을 만들어요. “z-index가 안 먹는다”의 원인은 거의 항상 조상의 쌓임 맥락이에요. <dialog>와 popover는 문서 전체 위의 최상위 레이어에 그려져 이 싸움에서 벗어나요.<br><sub>.a (z 1) and .b (z 2) put .b on top. Give .a opacity: .99 and it becomes a stacking context, so its .menu with z-index 9999 competes only inside .a and still ends up under .b. Opacity below 1, transform, filter, positioned z-index and isolation: isolate all create contexts. “z-index does nothing” is almost always an ancestor’s stacking context. <dialog> and popovers render in the top layer above the whole document, escaping the contest.</sub> |
| **overflow와 말줄임**<br><sub>Overflow and ellipsis</sub> | overflow는 상자보다 큰 내용을 어떻게 처리할지 정해요. visible(넘침), hidden(자름), auto(필요할 때 스크롤)가 대표 값이에요.<br><sub>overflow decides what happens to content larger than its box: visible spills, hidden clips and auto scrolls when needed.</sub> | 높이 120px 상자에 글이 많으면 기본값 visible이라 상자 밖으로 흘러넘쳐 다른 요소를 덮어요. overflow: hidden은 넘친 부분을 잘라 버리니 내용이 사라질 수 있어 신중하게 써요. overflow: auto는 넘칠 때만 스크롤 막대를 만들어요. 한 줄 말줄임은 white-space: nowrap, overflow: hidden, text-overflow: ellipsis 세 가지를 함께 줘야 하고, 여러 줄은 line-clamp를 써요. flex 자식 안에서 말줄임이 안 되면 min-width: 0을 더해요.<br><sub>With lots of text in a 120px-tall box, the default visible lets it spill out over neighboring elements. overflow: hidden clips the excess, which can hide content, so use it carefully. overflow: auto adds a scrollbar only when needed. A one-line ellipsis needs white-space: nowrap, overflow: hidden and text-overflow: ellipsis together, and multiple lines use line-clamp. If the ellipsis fails inside a flex child, add min-width: 0.</sub> |
| **CSS 단위**<br><sub>CSS units</sub> | px는 고정 크기이고, rem·em·%·vw·vh·dvh·ch는 무엇인가를 기준으로 한 상대 크기예요. clamp()로 범위 안에서 유동적으로 바꿀 수 있어요.<br><sub>px is a fixed size, while rem, em, %, vw, vh, dvh and ch are relative to something; clamp() makes values fluid within bounds.</sub> | rem은 루트(html) 글자 크기 기준이라 중첩돼도 2rem은 늘 32px이에요. em은 자기 글자 크기 기준이라 font-size에 em을 쓰면 중첩될수록 누적돼 커져요. %는 부모 기준, vw·vh는 화면의 1%이고, 모바일에선 주소창이 나타나고 사라지는 것을 반영하는 dvh가 정확해요. ch는 글자 “0”의 폭이라 본문 줄 길이를 65ch 정도로 제한할 때 좋아요. clamp(24px, 5vw, 48px)는 화면에 따라 커지되 24~48px 사이에 머물러요. 글자 크기를 rem으로 두면 사용자의 브라우저 글꼴 설정을 존중해요.<br><sub>rem is based on the root font size, so 2rem is always 32px however deep the nesting. em is based on the element’s own font size, so em font sizes compound as they nest. % is relative to the parent and vw and vh to 1% of the viewport; on mobile, dvh accounts for toolbars appearing and disappearing. ch is the width of “0”, ideal for capping body text at about 65ch. clamp(24px, 5vw, 48px) grows with the screen yet stays between 24 and 48px. rem font sizes also respect the user’s browser font setting.</sub> |

## Flexbox와 Grid, 반응형 레이아웃 · Flexbox, Grid and responsive layout

한 방향 배치의 Flexbox, 두 방향 배치의 Grid, 그리고 화면과 컨테이너 크기에 반응하는 방법이에요.  
*Flexbox for one direction, Grid for two, and responding to screen and container sizes.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **Flexbox의 두 축**<br><sub>The two axes of Flexbox</sub> | display: flex는 자식을 주축 한 방향으로 늘어놓아요. justify-content는 주축, align-items는 교차축 방향의 정렬이에요.<br><sub>display: flex lines children up along one main axis; justify-content aligns along the main axis and align-items along the cross axis.</sub> | display: flex를 주면 블록처럼 쌓이던 자식들이 가로(주축)로 나란히 놓여요. justify-content: space-between은 양 끝에 붙이고 사이를 균등하게, center는 가운데로 모아요. align-items: center는 높이가 서로 달라도 세로(교차축) 가운데에 맞춰요. flex-direction: column이면 주축이 세로로 바뀌어 justify와 align의 방향도 함께 바뀌어요. gap으로 아이템 사이 간격을, flex-wrap: wrap으로 넘치는 아이템의 줄바꿈을 정해요. 내비게이션, 버튼 묶음, 카드 안 배치처럼 한 방향 정렬에 가장 많이 써요.<br><sub>display: flex turns children that stacked like blocks into a horizontal row along the main axis. justify-content: space-between pins items to both ends with even spacing, and center gathers them in the middle. align-items: center centers items of different heights on the vertical cross axis. flex-direction: column makes the main axis vertical, swapping the directions of justify and align. gap sets the space between items, and flex-wrap: wrap lets overflowing items wrap. It is the go-to tool for one-directional alignment such as navigation bars, button groups and card internals.</sub> |
| **flex-grow·shrink·basis**<br><sub>flex-grow, shrink and basis</sub> | flex: grow shrink basis는 아이템의 기본 크기(basis)와, 공간이 남을 때 늘어나는 비율(grow), 모자랄 때 줄어드는 비율(shrink)이에요.<br><sub>flex: grow shrink basis sets an item’s base size, its share of extra space (grow) and how it gives way when space runs short (shrink).</sub> | .side { flex: 0 0 200px }는 늘지도 줄지도 않는 200px, .main { flex: 1 }은 남는 공간을 모두 차지해서 창을 넓히면 main만 커져요. flex-grow가 1과 2면 남는 공간을 1 : 2로 나눠 가져요. 공간이 모자라면 flex-shrink 비율로 줄어드는데, 로고처럼 찌그러지면 안 되는 요소는 flex-shrink: 0을 줘요. flex 아이템은 기본 min-width가 내용 크기라 긴 글이 줄어들지 않으니, 말줄임이 필요하면 min-width: 0을 줘요. flex: 1은 flex: 1 1 0%의 줄임말이에요.<br><sub>.side { flex: 0 0 200px } stays at 200px, while .main { flex: 1 } takes all leftover space, so only main grows as the window widens. flex-grow values of 1 and 2 split the leftover space 1 : 2. When space runs short, items shrink by their flex-shrink ratio, so things that must not squash, such as logos, get flex-shrink: 0. Flex items default to a content-sized min-width, so long text will not shrink until you add min-width: 0 for an ellipsis. flex: 1 is shorthand for flex: 1 1 0%.</sub> |
| **Grid 기초**<br><sub>Grid basics</sub> | display: grid는 행과 열을 먼저 정의하고 아이템을 칸에 배치하는 2차원 레이아웃이에요. fr 단위는 남은 공간의 비율이에요.<br><sub>display: grid is a two-dimensional layout: define rows and columns first, then place items into cells; fr is a share of the remaining space.</sub> | grid-template-columns: 200px 1fr 1fr은 고정 열 하나와 남은 공간을 반씩 나누는 열 두 개를 만들고, grid-template-rows: auto 1fr은 내용 높이의 행과 나머지를 채우는 행을 만들어요. gap은 칸 사이 간격이에요. 칸 사이의 선에는 1부터 번호가 붙어 grid-column: 1 / -1은 처음부터 끝까지 한 줄 전체를 차지하고, grid-row: span 2는 두 행을 차지해요. 한 방향 정렬은 Flexbox, 행과 열이 함께 맞아야 하는 페이지 골격이나 카드 목록은 Grid가 알맞아요.<br><sub>grid-template-columns: 200px 1fr 1fr creates one fixed column and two that split the remaining space, and grid-template-rows: auto 1fr a content-height row plus one that fills the rest. gap sets the space between tracks. Grid lines are numbered from 1, so grid-column: 1 / -1 spans the whole row and grid-row: span 2 takes two rows. Use Flexbox for one direction and Grid when rows and columns must line up, as in page skeletons and card lists.</sub> |
| **grid-template-areas**<br><sub>grid-template-areas</sub> | 문자열로 그린 지도에 영역 이름을 적어 페이지 골격을 정의하는 방법이에요. 미디어 쿼리에서 지도만 바꾸면 배치가 바뀌어요.<br><sub>A string map of named areas defines the page skeleton; changing only the map in a media query rearranges the layout.</sub> | "head head" "side main" "foot foot"처럼 적으면 같은 이름이 이어진 칸이 하나의 영역이 돼요. header { grid-area: head }처럼 이름을 주면 각 요소가 지도에서 자기 자리를 찾아가요. 좁은 화면의 미디어 쿼리에서 지도를 "head" "main" "side" "foot"로 바꾸면 같은 HTML이 세로로 재배치돼요. HTML 순서와 화면 배치를 분리할 수 있지만, 읽는 순서와 너무 다르면 키보드·스크린 리더 사용자가 헷갈려요. 빈칸은 점(.)으로 표시하고, 영역은 반드시 직사각형이어야 해요.<br><sub>Writing "head head" "side main" "foot foot" turns consecutive cells with the same name into one area. Naming elements, as in header { grid-area: head }, sends each to its place on the map. Changing the map in a narrow-screen media query to "head" "main" "side" "foot" restacks the same HTML vertically. Source order and visual order become independent, but straying far from reading order confuses keyboard and screen reader users. Empty cells are written as a dot (.), and areas must be rectangles.</sub> |
| **반응형 그리드 auto-fill·auto-fit**<br><sub>Responsive grids with auto-fill and auto-fit</sub> | repeat(auto-fill, minmax(200px, 1fr))은 미디어 쿼리 없이도 화면 폭에 맞춰 열 수가 저절로 바뀌는 그리드예요.<br><sub>repeat(auto-fill, minmax(200px, 1fr)) creates a grid whose column count follows the available width with no media queries.</sub> | minmax(200px, 1fr)은 “최소 200px, 남으면 같은 비율로 늘어남”이라는 뜻이고, auto-fill은 이 조건으로 들어갈 수 있는 만큼 열을 만들어요. 그래서 넓은 화면에선 4열, 좁아지면 2열, 휴대폰에선 1열로 저절로 줄어요. 아이템이 적을 때 auto-fill은 빈 칸을 남겨 두고, auto-fit은 빈 칸을 접어 남은 아이템을 넓게 늘려요. 카드 목록, 갤러리, 상품 그리드의 단골 패턴이에요. 최솟값이 컨테이너보다 크면 넘칠 수 있으니 minmax(min(200px, 100%), 1fr)로 감싸요.<br><sub>minmax(200px, 1fr) means at least 200px and stretching evenly when there is room, and auto-fill creates as many such columns as fit. A wide screen gets four columns, a narrower one two, and a phone one, all automatically. With few items, auto-fill keeps the empty tracks while auto-fit collapses them and stretches the remaining items. It is a staple for card lists, galleries and product grids. If the minimum can exceed the container, wrap it as minmax(min(200px, 100%), 1fr).</sub> |
| **가운데 정렬**<br><sub>Centering</sub> | 무엇을(글자·블록·아이템) 어느 방향으로 가운데에 놓을지에 따라 도구가 달라요. 요즘은 flex나 grid 한 줄로 대부분 해결돼요.<br><sub>The right tool depends on what is centered (text, block or item) and in which direction; flex or grid handle most cases in a line or two.</sub> | 글자 같은 인라인 내용은 text-align: center, 폭이 정해진 블록은 margin-inline: auto로 가로 가운데에 놓아요. 가로·세로 모두 가운데는 flex 컨테이너에 justify-content: center와 align-items: center를 주거나, grid에 place-items: center 한 줄이면 돼요. 크기가 정해진 모달처럼 겹쳐 놓을 요소는 position: absolute; inset: 0; margin: auto로 가운데에 놓을 수 있어요. vertical-align은 인라인 요소와 표 셀에만 듣고 블록에는 듣지 않아요.<br><sub>Inline content such as text centers with text-align: center, and a block with a set width with margin-inline: auto. For both directions, a flex container with justify-content: center and align-items: center, or a grid with place-items: center, does the job. An overlay of known size such as a modal can center with position: absolute; inset: 0; margin: auto. vertical-align works only on inline elements and table cells, not on blocks.</sub> |
| **미디어 쿼리와 모바일 우선**<br><sub>Media queries and mobile first</sub> | 미디어 쿼리는 화면 폭이나 사용자 환경에 따라 다른 스타일을 적용하는 조건문이에요. 좁은 화면을 기본으로 쓰고 넓은 화면을 덧붙이는 게 모바일 우선이에요.<br><sub>Media queries apply styles conditionally by viewport width or user environment; mobile first writes the narrow layout as the base and adds rules for wider screens.</sub> | 기본 스타일을 1열로 쓰고 @media (min-width: 768px)에서 2열, (min-width: 1200px)에서 3열을 덧붙이면 조건이 겹칠 때 뒤의 규칙이 이겨요. 모바일 기기는 대개 단순한 레이아웃을 쓰므로 이렇게 쌓아 가는 편이 덮어쓸 코드가 적어요. 폭뿐 아니라 (hover: hover)로 마우스가 있는 기기에만 hover 효과를, prefers-reduced-motion과 prefers-color-scheme으로 사용자 설정을 반영해요. HTML에 <meta name="viewport" content="width=device-width">가 없으면 모바일에서 동작하지 않아요.<br><sub>Writing one column as the base and adding two columns at @media (min-width: 768px) and three at (min-width: 1200px) works because later rules win where conditions overlap. Mobile layouts are usually simpler, so building upward leaves less to override. Beyond width, (hover: hover) limits hover effects to devices with a mouse, and prefers-reduced-motion and prefers-color-scheme reflect user settings. Without <meta name="viewport" content="width=device-width"> in the HTML, mobile browsers ignore all this.</sub> |
| **컨테이너 쿼리**<br><sub>Container queries</sub> | 화면이 아니라 부모 컨테이너의 크기에 반응하는 스타일이에요. 같은 컴포넌트가 놓인 자리에 맞춰 스스로 모양을 바꿔요.<br><sub>Styles that respond to the size of a parent container instead of the viewport, so a component adapts to wherever it is placed.</sub> | .slot에 container-type: inline-size를 주면 그 안의 요소가 @container (min-width: 400px)로 부모 칸의 폭을 물어볼 수 있어요. 같은 카드라도 좁은 사이드바 안에서는 이미지와 글이 세로로 쌓이고, 넓은 main 안에서는 가로로 놓여요. 화면 크기는 같아도 컴포넌트마다 다른 배치가 되는 거예요. cqi 단위는 컨테이너 폭의 1%라 clamp(1rem, 6cqi, 1.5rem)처럼 제목 크기도 칸에 맞춰요. 페이지 골격은 미디어 쿼리, 컴포넌트 안쪽은 컨테이너 쿼리로 나눠 쓰면 재사용성이 높아져요.<br><sub>Giving .slot container-type: inline-size lets descendants ask about that slot’s width with @container (min-width: 400px). The same card stacks image and text vertically in a narrow sidebar and lays them side by side in a wide main area, on the very same screen. The cqi unit is 1% of the container’s width, so clamp(1rem, 6cqi, 1.5rem) sizes headings to the slot. Using media queries for the page skeleton and container queries inside components makes components truly reusable.</sub> |

## 색, 글꼴, 움직임 · Color, type and motion

색을 표현하는 방법, 변수와 테마, 글꼴과 타이포그래피, 그리고 전환·애니메이션·변형이에요.  
*Ways to express color, variables and themes, fonts and typography, and transitions, animation and transforms.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **색 표현**<br><sub>Expressing color</sub> | hex·rgb는 빨강·초록·파랑의 양으로, hsl은 색상·채도·명도로, oklch는 사람 눈에 균일한 밝기로 색을 적어요.<br><sub>hex and rgb describe amounts of red, green and blue, hsl uses hue, saturation and lightness, and oklch uses perceptually uniform lightness.</sub> | #3366ff와 rgb(51 102 255)는 같은 색이고, rgb(51 102 255 / 80%)처럼 / 뒤에 투명도를 적어요. hsl(225 100% 60%)은 명도만 바꿔 같은 색의 밝고 어두운 단계를 만들기 쉬워요. 하지만 hsl에서 명도 50%인 노랑은 파랑보다 훨씬 밝아 보이는데, oklch는 같은 명도면 눈에도 같은 밝기라 디자인 시스템의 색 단계를 만들기 좋고 P3 같은 넓은 색역도 표현해요. color-mix(in oklch, red, blue)는 두 색을 섞고, currentColor는 현재 글자색을 테두리나 아이콘에 그대로 써요.<br><sub>#3366ff and rgb(51 102 255) are the same color, and alpha follows a slash, as in rgb(51 102 255 / 80%). hsl(225 100% 60%) makes tints and shades easy by changing only lightness. Yet at 50% lightness in hsl, yellow looks far brighter than blue, while in oklch equal lightness looks equally bright, which suits design-system color scales and wide gamuts such as P3. color-mix(in oklch, red, blue) blends two colors, and currentColor reuses the text color for borders and icons.</sub> |
| **CSS 변수**<br><sub>CSS variables</sub> | --brand처럼 --로 시작하는 커스텀 속성에 값을 두고 var()로 꺼내 써요. 상속되고, 범위 안에서 덮어쓸 수 있고, 실행 중에도 바뀌어요.<br><sub>Custom properties beginning with --, such as --brand, store values that var() reads; they inherit, can be overridden in scope and change at run time.</sub> | :root { --brand: #36f }에 정한 색을 .btn { background: var(--brand) }로 쓰면 한 곳만 고쳐도 모든 버튼이 바뀌어요. 커스텀 속성도 상속되는 일반 속성이라 .danger { --brand: #e33 }처럼 범위 안에서 다시 정하면 그 안의 버튼만 빨개져요. 테마마다 변수 값만 바꾸면 다크 모드 같은 전체 전환이 쉬워요. var(--accent, #36f)처럼 기본값을 둘 수 있고, JS의 el.style.setProperty("--x", "40px")로 실행 중에 값을 바꿀 수도 있어요. Sass 변수는 빌드 때 사라지지만 CSS 변수는 브라우저에 남아 있어요.<br><sub>A color set as :root { --brand: #36f } and used as .btn { background: var(--brand) } updates every button from one place. Custom properties inherit like any property, so redefining .danger { --brand: #e33 } turns only the buttons inside it red. Swapping variable values per theme makes switches such as dark mode easy. var(--accent, #36f) supplies a fallback, and el.style.setProperty("--x", "40px") in JavaScript updates values at run time. Sass variables vanish at build time, but CSS variables live in the browser.</sub> |
| **글꼴과 타이포그래피**<br><sub>Fonts and typography</sub> | 웹 글꼴 로딩, 대체 글꼴, 글자 크기, 줄 간격, 줄 길이가 함께 읽기 경험을 만들어요.<br><sub>Web font loading, fallbacks, size, line height and line length together shape the reading experience.</sub> | @font-face로 Pretendard 같은 웹 글꼴을 등록하고 font-display: swap을 주면, 글꼴을 받는 동안 대체 글꼴로 먼저 보여줘서 글자가 안 보이는 시간이 없어요. font-family는 쉼표로 대체 글꼴을 이어 적고, line-height는 단위 없이 1.6처럼 적어 글자 크기에 비례하게 해요. clamp(1.75rem, 4vw, 3rem)은 화면 폭에 따라 제목이 커지되 범위 안에 머물러요. 본문은 max-width: 65ch 정도로 줄 길이를 제한하고, text-wrap: balance는 제목 줄 길이를 고르게, pretty는 마지막 줄에 단어 하나만 남는 것을 막아요. 한글 글꼴은 용량이 커서 서브셋과 woff2를 써요.<br><sub>@font-face registers a web font such as Pretendard, and font-display: swap shows a fallback font while it downloads so text is never invisible. font-family lists fallbacks separated by commas, and a unitless line-height such as 1.6 scales with the font size. clamp(1.75rem, 4vw, 3rem) grows headings with the viewport within bounds. Cap body text at about max-width: 65ch; text-wrap: balance evens heading lines and pretty avoids a lone word on the last line. Korean fonts are large, so use subsets and woff2.</sub> |
| **transition**<br><sub>transition</sub> | transition은 속성 값이 바뀔 때 그 사이를 정한 시간 동안 부드럽게 채워요. 시작과 끝, 두 상태 사이의 보간이에요.<br><sub>transition fills in the values between two states over a set duration whenever a property changes.</sub> | :hover로 배경이 바뀌면 기본적으로는 순간 이동하지만, transition: background 200ms ease를 주면 200ms 동안 중간 색들이 채워져요. 이징은 시간에 따른 속도 변화로, ease-out은 빠르게 시작해 천천히 멈춰 화면에 들어오는 움직임에, ease-in은 나가는 움직임에 잘 맞아요. transform과 opacity는 합성 단계만 다시 해서 부드럽고, width·height·top은 매 프레임 레이아웃을 다시 해서 버벅일 수 있어요. height: auto는 전환되지 않아서 grid-template-rows: 0fr → 1fr 같은 우회법을 써요. UI 전환은 150~300ms가 적당해요.<br><sub>A background changed on :hover normally jumps instantly, but transition: background 200ms ease fills in the intermediate colors over 200ms. Easing shapes speed over time: ease-out starts fast and settles slowly, suiting entrances, while ease-in suits exits. transform and opacity only re-composite and stay smooth, whereas width, height and top redo layout every frame and can stutter. height: auto cannot transition, so workarounds such as grid-template-rows from 0fr to 1fr are used. 150–300ms suits most UI transitions.</sub> |
| **@keyframes 애니메이션**<br><sub>@keyframes animation</sub> | @keyframes로 시간 지점마다 상태를 적고 animation으로 재생해요. 상태 변화 없이도, 여러 단계로, 반복해서 움직일 수 있어요.<br><sub>@keyframes lists states at points in time and animation plays them, so elements can move without a state change, in many steps and on repeat.</sub> | @keyframes pop에 0%(작고 투명), 60%(살짝 크게), 100%(제자리)를 적고 .toast { animation: pop 300ms ease-out both }로 재생하면 알림이 톡 튀어나와요. animation 한 줄에 이름, 시간, 이징, 반복 횟수, 채우기 모드를 적고, both는 시작 전과 끝난 뒤의 상태를 유지해요. infinite는 로딩 스피너처럼 끝없이 반복해요. transition이 A→B 두 상태라면 animation은 여러 단계와 반복이 가능해요. 사용자가 “동작 줄이기”를 켰다면 prefers-reduced-motion으로 큰 움직임을 끄고 페이드 정도만 남겨요.<br><sub>@keyframes pop with 0% (small and transparent), 60% (slightly enlarged) and 100% (settled), played with .toast { animation: pop 300ms ease-out both }, makes a notification pop in. The animation shorthand sets name, duration, easing, iteration count and fill mode, and both keeps the first and last states. infinite repeats forever, as for loading spinners. Where a transition goes from A to B, an animation can have many steps and loops. When users enable reduced motion, prefers-reduced-motion turns off large motion and keeps only subtle fades.</sub> |
| **transform**<br><sub>transform</sub> | transform은 레이아웃에 영향을 주지 않고 요소를 옮기고, 돌리고, 키워요. GPU로 합성되어 애니메이션에 가장 적합해요.<br><sub>transform moves, rotates and scales elements without affecting layout, and is composited on the GPU, making it ideal for animation.</sub> | translate(40px, 0)으로 옮겨도 이웃 요소는 그 자리에 그대로 있어요. rotate(15deg) scale(1.2)처럼 함수를 공백으로 이어 한 번에 적용하고, transform-origin으로 회전·확대의 기준점을 정해요(기본값은 가운데). 함수는 오른쪽부터 적용되기 때문에 translate() rotate()와 rotate() translate()의 결과 위치가 서로 달라요. 요즘은 translate, rotate, scale을 개별 속성으로도 쓸 수 있어 따로 애니메이션하기 편해요. transform이 있는 요소는 쌓임 맥락이 되고 fixed 자식의 기준도 돼요.<br><sub>Moving an element with translate(40px, 0) leaves its neighbors exactly where they were. Functions chain with spaces, as in rotate(15deg) scale(1.2), and transform-origin sets the pivot for rotation and scaling (the center by default). Functions apply from right to left, so translate() rotate() and rotate() translate() end up in different places. translate, rotate and scale now also exist as individual properties, which are easier to animate separately. A transformed element becomes a stacking context and the reference for fixed children.</sub> |
| **다크 모드**<br><sub>Dark mode</sub> | 색을 변수로 두고, 시스템 설정(prefers-color-scheme)이나 사용자 선택에 따라 변수 값만 바꿔 테마를 전환해요.<br><sub>Keep colors in variables and swap their values by system setting (prefers-color-scheme) or user choice to switch themes.</sub> | :root { color-scheme: light dark }를 선언하면 스크롤바와 입력창 같은 브라우저 기본 UI도 테마를 따라가요. --bg, --text 같은 변수를 두고 @media (prefers-color-scheme: dark)에서 값만 바꾸면 페이지 전체가 OS 설정을 따라 어두워져요. light-dark(#111, #eee) 함수로 한 줄에 두 값을 적을 수도 있어요. 사용자가 직접 고르는 토글은 html에 data-theme 속성을 달아 덮어쓰고 선택을 localStorage에 저장하며, 페이지가 그려지기 전에 스크립트로 적용해 깜빡임을 막아요. 순수한 검정 대신 짙은 회색이 눈에 편해요.<br><sub>Declaring :root { color-scheme: light dark } makes browser UI such as scrollbars and inputs follow the theme. With variables such as --bg and --text, changing only their values under @media (prefers-color-scheme: dark) darkens the page with the OS setting. light-dark(#111, #eee) writes both values in one line. A user-facing toggle overrides with a data-theme attribute on html, stores the choice in localStorage and applies it with a script before first paint to avoid a flash. Dark gray is easier on the eyes than pure black.</sub> |

## 아키텍처, 성능, 접근성 · Architecture, performance and accessibility

브라우저가 화면을 그리는 과정, CSS를 충돌 없이 조직하는 방법, 그리고 모두가 쓸 수 있는 스타일이에요.  
*How browsers draw a frame, organizing CSS without collisions, and styles that work for everyone.*

| 개념 | 설명 | 실무 팁 |
| --- | --- | --- |
| **렌더링 파이프라인**<br><sub>The rendering pipeline</sub> | 브라우저는 스타일 계산 → 레이아웃 → 페인트 → 합성 순서로 화면을 그려요. 어떤 속성을 바꾸느냐에 따라 다시 하는 단계가 달라져요.<br><sub>Browsers draw a frame by computing styles, then layout, paint and composite; which property changes decides which stages rerun.</sub> | width, margin, top처럼 크기·위치가 바뀌면 레이아웃부터 모든 단계를 다시 해서 가장 비싸요. color, background처럼 모양만 바뀌면 레이아웃을 건너뛰고 페인트부터 다시 해요. transform과 opacity는 합성 단계만 다시 해서 GPU가 빠르게 처리하므로 애니메이션은 이 둘로 만들어요. JS에서 스타일을 쓰고 곧바로 offsetHeight 같은 크기를 읽으면 브라우저가 강제로 레이아웃을 계산하고, 반복문 안에서 쓰기·읽기를 섞으면 레이아웃 스래싱이 생겨요. 60fps를 지키려면 한 프레임을 16.7ms 안에 그려야 해요.<br><sub>Changing size or position, such as width, margin or top, reruns everything from layout and is the most expensive. Appearance-only changes such as color or background skip layout and repaint. transform and opacity only re-composite on the GPU, which is why animations should use them. Writing a style in JavaScript and immediately reading a size such as offsetHeight forces a synchronous layout, and mixing writes and reads in a loop causes layout thrashing. Keeping 60fps means drawing each frame within 16.7ms.</sub> |
| **이름 규칙과 스코프**<br><sub>Naming and scoping</sub> | CSS는 기본적으로 전역이라 이름이 겹치면 서로를 덮어써요. BEM 같은 이름 규칙, CSS Modules 같은 빌드 도구, 표준 @scope로 범위를 관리해요.<br><sub>CSS is global by default, so clashing names overwrite each other; naming rules such as BEM, build tools such as CSS Modules and the standard @scope manage boundaries.</sub> | card.css와 modal.css가 둘 다 .title을 쓰면 나중에 불러온 쪽이 다른 컴포넌트의 제목까지 바꿔요. BEM은 .card\_\_title(블록\_\_요소), .card--featured(블록--변형)처럼 규칙으로 이름을 겹치지 않게 하고, 클래스 하나라 명시도도 평평해요. CSS Modules는 빌드 도구가 .title을 .Card\_title\_\_x7f2a처럼 파일마다 고유한 이름으로 바꿔 줘요. 표준 @scope (.card) to (.content)는 .card 안에서, .content를 만나기 전까지만 규칙을 적용해요. Tailwind 같은 유틸리티 클래스는 이름 짓기 자체를 줄이는 또 다른 접근이에요.<br><sub>If card.css and modal.css both use .title, whichever loads later restyles the other component’s title too. BEM avoids clashes by convention, with names such as .card\_\_title (block\_\_element) and .card--featured (block--modifier), and keeps specificity flat with single classes. CSS Modules have the build tool rename .title to something unique per file, such as .Card\_title\_\_x7f2a. The standard @scope (.card) to (.content) applies rules inside .card but stops where .content begins. Utility classes such as Tailwind take another route by avoiding most naming altogether.</sub> |
| **CSS 중첩**<br><sub>CSS nesting</sub> | 관련 규칙을 부모 규칙 안에 중첩해 쓰는 표준 문법이에요. &는 바깥 선택자를 가리키고, 이제 전처리기 없이 브라우저가 직접 지원해요.<br><sub>Standard syntax for nesting related rules inside their parent; & refers to the outer selector, and browsers now support it without a preprocessor.</sub> | .card 안에 & .title { … }을 쓰면 .card .title, &:hover는 .card:hover, &.is-active는 .card.is-active로 펼쳐져요. @media (width > 600px) { padding: 24px }처럼 미디어 쿼리도 규칙 안에 넣어 관련 스타일을 한곳에 모아요. .theme-dark &처럼 &를 뒤에 두면 “조상이 .theme-dark일 때”라는 뜻이 돼요. 중첩 선택자는 :is()처럼 계산되어 명시도가 예상보다 높아질 수 있고, 깊게 중첩할수록 덮어쓰기 어려워지니 3단 이내로 유지해요. Sass의 &\_\_title 같은 이름 이어 붙이기는 지원하지 않아요.<br><sub>Inside .card, & .title { … } expands to .card .title, &:hover to .card:hover and &.is-active to .card.is-active. Media queries such as @media (width > 600px) { padding: 24px } can sit inside the rule, keeping related styles together. Placing & at the end, as in .theme-dark &, means “when an ancestor is .theme-dark”. Nested selectors are computed like :is(), so specificity can run higher than expected, and deep nesting makes overrides hard, so stay within three levels. Sass-style name concatenation such as &\_\_title is not supported.</sub> |
| **접근성을 지키는 CSS**<br><sub>Accessible CSS</sub> | 초점 표시를 지우지 않고, 동작 줄이기 설정을 존중하며, 화면에 숨긴 텍스트와 충분한 크기·대비로 모두가 쓸 수 있게 해요.<br><sub>Keep focus visible, respect reduced-motion settings, and provide visually hidden labels, adequate size and contrast so everyone can use the page.</sub> | :focus-visible은 키보드로 이동할 때만 초점 테두리를 보여주므로, 디자인 때문에 outline: none으로 지우지 말고 이 선택자로 보기 좋게 다듬어요. 초점이 안 보이면 키보드 사용자는 지금 어디에 있는지 알 수 없어요. prefers-reduced-motion: reduce일 때는 큰 움직임과 전환을 끄거나 줄여요. .sr-only 패턴은 아이콘 버튼의 “검색” 같은 텍스트를 화면에선 숨기고 스크린 리더엔 읽히게 해요(display: none은 리더에서도 사라져요). 터치 대상은 44px 이상, 글자와 배경의 대비는 4.5:1 이상을 지켜요.<br><sub>:focus-visible shows the focus ring only for keyboard navigation, so refine it with this selector instead of removing it with outline: none. Without a visible focus, keyboard users cannot tell where they are. Under prefers-reduced-motion: reduce, turn off or tone down large motion and transitions. The .sr-only pattern hides text such as an icon button’s “Search” visually while keeping it for screen readers, unlike display: none. Keep touch targets at least 44px and text contrast at least 4.5:1.</sub> |
| **논리 속성**<br><sub>Logical properties</sub> | 위·아래·왼쪽·오른쪽 대신 글의 흐름(inline·block, start·end)을 기준으로 쓰는 속성이에요. 오른쪽에서 왼쪽으로 쓰는 언어와 세로쓰기에서도 그대로 맞아요.<br><sub>Properties based on the flow of text (inline and block, start and end) instead of top, bottom, left and right, so they stay correct in right-to-left and vertical writing.</sub> | .icon { margin-right: 8px }은 언제나 오른쪽이라, 아랍어처럼 dir="rtl"인 화면에서는 아이콘과 글자 사이가 아니라 바깥쪽에 간격이 생겨요. margin-inline-end는 “글이 끝나는 쪽”이라 방향에 따라 자동으로 뒤집혀요. inline은 글이 흐르는 방향, block은 줄이 쌓이는 방향이라 width는 inline-size, height는 block-size, padding-top·bottom은 padding-block이에요. writing-mode: vertical-rl로 세로쓰기를 해도 두 축이 함께 돌아가서 논리 속성은 그대로 맞아요. 다국어 서비스라면 처음부터 논리 속성으로 쓰는 게 좋아요.<br><sub>.icon { margin-right: 8px } is always on the right, so under dir="rtl", as in Arabic, the gap lands outside instead of between the icon and the text. margin-inline-end means the side where text ends and flips automatically with direction. inline is the direction text flows and block the direction lines stack, so width becomes inline-size, height block-size and top and bottom padding padding-block. Even with writing-mode: vertical-rl, both axes rotate together and logical properties still fit. Multilingual products benefit from using them from the start.</sub> |
